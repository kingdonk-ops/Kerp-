## Goal
Cut backend CI wall-clock time without weakening any test. Today the `backend` job runs the full
suite on SQLite (28–54 min) and then on PostgreSQL (14–25 min) in series; every other CI job
finishes in ~2 min. Cause (audit 2026-11-21): ~1,150 tests build their database through
`tests/audit_support.py:migrated_database`, which runs all migrations up and back down per test
(~1.3 s each). This task fixes the SQLite side and the CI layout; the PostgreSQL side is T-0082.

## Acceptance criteria
- [x] On SQLite, `migrated_database` migrates + seeds **one template file per test process** and each test gets a byte copy of it; nothing is downgraded on SQLite (the file is discarded with `tmp_path`); behaviour on PostgreSQL is unchanged (upgrade head → yield → downgrade base)
- [x] Every other per-test fixture that runs `command.upgrade(cfg, "head")` on a fresh SQLite file for plain "migrated database" purposes uses the same helper; tests that exercise migrations themselves (`test_migrations.py`, revision-targeted upgrades/downgrades) are left unchanged
- [x] `pytest-xdist` added to the backend `dev` extra; the SQLite suite passes with `pytest -n auto` (coverage floor 90 % still enforced, combined across workers) and with plain `pytest`
- [x] `ci.yml`: SQLite and PostgreSQL backend tests run as **two jobs in parallel** (`backend` = lint + mypy + SQLite `pytest -n auto`; `backend-pg` = PostgreSQL + RLS); `backend-publish` and `e2e` need both; `scripts/ci_gate.py` and its tests know `backend-pg`
- [x] Both backend pytest runs pass `--durations=25`
- [x] `scripts/ci_changes.py`: a PR whose changes are all under `tracker/`, `docs/` or `.claude/` skips the app jobs (planner PRs); the conformance-fixture TODO exception stays; tests cover it
- [x] CLAUDE.md §4 backend gate uses `pytest -n auto`; `docs/WORKFLOW.md` and `backend/README.md` updated
- [x] No test skipped, xfailed, removed or weakened; no coverage or lint change
- [x] All quality gates green (see CLAUDE.md §Quality gates)

## Notes
- The SQLite suite stays in CI on purpose: agents in cloud sessions have no PostgreSQL, so plain `pytest` on SQLite is their local gate (ADR 0001 keeps the types dialect-portable for this); CI must keep that path green.
- The coverage floor stays on the SQLite run until T-0082 makes the PostgreSQL run fast enough to carry it.
- PR #138 (T-0033) also edits `.github/workflows/ci.yml`; whichever lands second rebases.
- Implementation: `tests/audit_support.py` keeps one migrated SQLite template per process and variant (`seeded`); `test_onboarding.py` (needs an empty tenant directory) uses the unseeded variant. The other fixtures that call `command.upgrade(cfg, "head")` directly were reviewed and left alone: they test migrations themselves (`test_migrations.py`, `test_tenants.py` downgrades, `test_membership_persona_migration.py`, `test_validation_unlock_migration.py`, `test_team_grants.py` at `0024`, `test_audit_ledger_device.py`, `test_saved_view_teams.py`) or are PostgreSQL-only (`test_rls_bypass.py`).
- `scripts/ci_changes.py` renamed its predicate to `is_docs_or_tracker_only` (output `docs_or_tracker_only=`); `docs/**` was code before (PR #133 kept it conservative). A new test proves no backend/frontend/e2e/contract file opens `docs/` or `.claude/` by relative path (FastAPI's `/docs` URL route is not a path).
- `tests/test_dev_infra.py` now reads the PostgreSQL service/steps from the `backend-pg` job (moved, not changed).
- Local results (4 vCPU): SQLite suite `pytest -n auto` 2,797 passed / 78 skipped in 2 min 18 s, coverage 97.40 % (was 28–54 min serial in CI). The PostgreSQL job is unchanged apart from moving into its own job; CI's `backend-pg` run is the check for it.
