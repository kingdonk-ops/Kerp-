- 2026-11-10: TD-112 planner pass: the projects table created here gets the membership-based RLS policy in T-0014 (TD-053); create it with the standard policy and let T-0014 replace it.
- 2026-11-13 (implementer): `oe_projects_project` (migration `0008`, tenant-level row, standard RLS) with `code`/`name`/`status`, `site_timezone` (IANA via `zoneinfo`), `spatial_bounds` (PostGIS `geometry(Polygon,4326)` on PostgreSQL through the new portable `app.core.geo.GeoJSONGeometry`, GeoJSON text on SQLite), `currency_code` (ISO 4217) and `locale` (BCP 47). CRUD at `/api/v1/projects`; changes audited on chain `project:<id>`.
- Authorisation reads the caller's memberships for the project in the path, because the request binds no project yet (TD-122): read = member (else 404), edit/delete = `admin` capability (else 403), create = `admin` on any project (interim, TD-184). `require_capability` is not used because it needs a bound project.
- Status values and currency/locale defaults are not in the spec: TD-185. GiST index, `ST_IsValid`, code reuse after soft delete: TD-186.
- `app.core.geo` registers `geometry` with PostgreSQL's reflection type names, so `alembic check` compares the geometry kind/SRID instead of warning.
- 2026-11-13 (review round 1): `site_timezone` is validated against the `tzdata` package's zone list (now a direct dependency) instead of the host's `TZPATH`, so `localtime`/`posixrules` are rejected; `Factory` is excluded explicitly. Coordinates are strict JSON numbers (booleans and numeric strings rejected). Size raised to M.
