## Goal
Project-level inspections (user, 2026-11-21; ADR 0003 amendment 2026-11-21; quality-and-inspection.md §Project-level inspections): `qa_itp` records keep the ADR 0003 anchor; records of every other area have no anchor and belong to the project, with an optional informational location and 0..many informational links to an asset (node/Item), a material or an equipment register entry.

## Acceptance criteria
- [ ] Anchor rule from the area of the pinned revision: `qa_itp` → exactly one of `node_id` / `item_id` as T-0111 (unchanged); any other area → both NULL (giving one → 422 `PROJECT_LEVEL_AREA`); additive migration, the T-0111 anchor check stays in one place (tests per area)
- [ ] Nullable `location_node_id` (any live node of the project, checked through the `asset_management` service; retired or other project → 422/404)
- [ ] `oe_inspections_link` (`BaseRecordMixin` + project-scoped RLS): `inspection_id`, `target_kind` (`node | item | material | equipment`), `target_id`, unique per (inspection, kind, target); each target checked through the owning module's `service.py` (no FK, no cross-module table access); unknown or other project → 404; at most one `equipment` link per record (422); `material` → 422 `LINK_KIND_UNAVAILABLE` until the materials module registers a link target (E-03-03)
- [ ] A link-target provider interface (`resolve_link_target(kind, id, project)`, display label, detail route) implemented by `asset_management` (node, Item) and `equipment`; the inspections module calls providers, never their tables
- [ ] Location and links are informational: the node inspection roll-up (T-0111 `GET /assets/nodes/{id}/inspections`), progress, `work_anchor.complete` and the T-0160 tiles never count a record through its location or links (tests)
- [ ] Search: `GET /api/v1/inspections?location={node}&linked={kind}:{id}` (location matches the node and its descendants, planner default); `inspections.service.linked_records(kind, id)` for "Linked inspections" on the linked record's detail
- [ ] Offline: project-level inspections assigned to or started by the user are in the pull scope (T-0147); links and location are part of the queued mutations
- [ ] The inspection PDF (T-0158) header shows "Project", the location and the links for a project-level record
- [ ] Links and location changes are ledgered (T-0006); a cross-project read → 404 (test)
- [ ] Module `README.md` and docs updated
- [ ] All quality gates green (see CLAUDE.md §Quality gates)
