## Goal
The RFI slot state machine after issue (quality-and-inspection.md §`inspection_requests` 4, 5, 12–14): confirmation, the reschedule back-transition that keeps history (TD-045), witness attendance and outcomes, and the witness check that stops an ITR being submitted before its external hold/witness point is satisfied.

## Acceptance criteria
- [ ] Confirm `requested → confirmed` by the named witness or a PER-15 of the client party whose subtree holds every slot anchor; PER-06/PER-07 may record it on behalf only with `confirmation_ref` (`confirmed_via = recorded_on_behalf`); others 403 (tests)
- [ ] Reschedule `requested | confirmed | no_show | failed → requested` with a future time, non-blank reason and cause party (PER-15 → always `client`): event keeps old and new `scheduled_start`; `reschedule_count` + 1; confirmation, attendance and `reminder_sent_at` cleared; notice recomputed from now; a closed request reopens; linked records stay `INSPECTION_REQUESTED` with `planned_start` moved; from `witnessed | waived | cancelled` → 409 (tests)
- [ ] Attendance per external H/W party: the named witness may record their own `attended`; PER-06/PER-07 record `attended | absent`; **waive a party** sets one party's `attendance = waived` and stores `waiver_ref` on that party row (PER-15 of that party for any point; PER-06 for that party's `W` point only, with `waiver_ref`; PER-06 on an `H` point → 403) and moves the slot to `waived` when every external H/W party is waived (tests, incl. client waives `W` + principal attends `H` → `witnessed`)
- [ ] Outcomes per §4: `witnessed` needs no external H/W party `pending`, every one attended or waived and ≥ 1 attended; `no_show` needs no party `pending`, ≥ 1 `absent` and `outcome_occurred_at` ≥ start + `no_show_grace_minutes` (default 30); a `pending` party → 422 `ATTENDANCE_PENDING`; `failed` needs a reason code (tests for each)
- [ ] `witness_status(inspection_id)` per §5 uses the most recently issued slot linking the record **or, for an ITR, its ITP line when the slot's anchors cover the ITR's anchor** (test: a line-only slot whose anchors do not cover the ITR's anchor does not count), and reports per external party: test "slot links only the ITP line, witnessed, then the ITR submits" passes `inspection.submit`; `no_show` with only `W` parties absent after valid notice → satisfied; `H` absent, short notice or `failed` → not satisfied (tests)
- [ ] `construction_control` adds the locked system-default rules `WITNESS_REQUIREMENT_HOLD` (param `overridable: false`) and `WITNESS_REQUIREMENT_WITNESS` to `inspection.submit` using `witness_status` and the ITP line's external H/W points; HOLD fails only for unmet `H` parties and WITNESS only for unmet `W` parties (test: client `W` absent after valid notice + principal `H` pending gives only a HOLD finding; client `W` pending + principal `H` attended gives only an overridable WITNESS finding); findings `RFI_REQUIRED`, `WITNESS_PENDING`, `WITNESS_NOT_SATISFIED`; a record without external H/W points is never blocked (test)
- [ ] `validation.service` override-request path (T-0035) refuses a request naming a finding of a rule with `overridable: false` with 422 `OVERRIDE_NOT_ALLOWED` (additive; `oe_validation_override` shape unchanged): test through the override-request endpoint for a `WITNESS_REQUIREMENT_HOLD` finding (422) and a `WITNESS_REQUIREMENT_WITNESS` finding (accepted) — default of decision TD-486
- [ ] Comments from both sides (`party` from the author's persona), append-only, ≤ 2,000 characters; PER-15 only on slots they can see (tests)
- [ ] Every transition is a conditional update on `version` + `status`: the second of two concurrent actions gets 409 (test); each writes an event (with `on_behalf_of_user_id` / `delegation_id` columns, filled by T-0293) and a ledger entry; each runs `run_checks(context, "inspection_request.<action>")`
- [ ] Offline outcome: attendance + `witnessed | no_show | failed` accepted as a queued mutation with client op id and diff §6.4.1 time evidence; at sync the §4 rules run on the reconstructed `occurred_at`; a slot no longer `requested`/`confirmed` fails the mutation with `SLOT_STATE_CHANGED`, nothing applied, inspector notified (tests)
- [ ] History and detail read by an `is_internal = false` reader (PER-15) omit `cause_changed` events and carry no `cause_party`, delay id or delay hours in any payload (§13 redaction, T-0295 field class); internal readers see them (tests)
- [ ] Module `README.md` and docs updated
- [ ] All quality gates green (see CLAUDE.md §Quality gates)
