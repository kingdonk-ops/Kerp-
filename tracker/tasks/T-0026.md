## Goal
Admin UI for the access model of diff §4.1 and the 15-persona model + site scoping (edge §5), under
the Admin nav group (diff §6.1). Tenants never appear in the UI.

## Acceptance criteria
- [ ] **System** screen (only for `system_admin`): list users with their admin grants; appoint / remove Project Admins (`create_projects`) and System admins; the last System admin cannot be removed (T-0039)
- [ ] **Users** screen: a System admin creates and deactivates accounts; a PER-09 invites a user by e-mail to one of its projects
- [ ] **Projects**: a Project Admin creates a project (lands in it as PER-09); a PER-09 edits its project's settings and toggles *visible in lobby* (T-0040)
- [ ] **Members** of a project (PER-09 or System admin): assign / remove persona(s) + Asset-Site scope; a user can be assigned to several of the admin's projects in one action
- [ ] Assigning PER-09 with a hold-authority persona (PER-02, PER-06, PER-07, PER-11) shows the `sod_warning` and needs an explicit confirmation before saving (TD-151)
- [ ] The UI never offers hold release or sign-off rights through an admin role; such rights appear only via qualified personas (diff §4.1)
- [ ] All strings through `t()`; component tests + one e2e journey (System admin appoints a Project Admin → they create a project → assign a user), synthetic data only
- [ ] Module `README.md` and docs updated
- [ ] All quality gates green (see CLAUDE.md §Quality gates)
