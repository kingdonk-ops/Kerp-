## Goal
TD-120 3a and TD-184 1a: System admins appoint Project Admins (the tenant-level `create_projects` grant); only Project Admins create projects, and the creator is PER-09 on the new project.

## Acceptance criteria
- [ ] `GET/POST/DELETE /api/v1/admin/grants` lists, grants and revokes `system_admin` and `create_projects` for a user; only a `system_admin` may call it (else 403); the last `system_admin` cannot be revoked (409) (diff §4.1)
- [ ] `POST /api/v1/projects` needs `create_projects` (else 403), replacing the interim 'admin on any project' rule of T-0012 (TD-184)
- [ ] Creating a project grants the creator a PER-09 membership on it in the same transaction; a test creates a project and immediately reads and edits it as the creator
- [ ] Revoking `create_projects` keeps the user's existing PER-09 memberships
- [ ] `load_grants` and the allowed project list ignore memberships on soft-deleted projects; a test shows a PER-09 whose only project was deleted has no admin capability (TD-184)
- [ ] Neither grant confers hold release, sign-off, `A` or `S`: a test shows a `system_admin` + `create_projects` user without a qualified persona is refused an `A`-capability check on a project (diff §4.1, edge §5 Admins)
- [ ] Grant and revoke are written to the audit ledger
- [ ] Module `README.md` and docs updated
- [ ] All quality gates green (see CLAUDE.md §Quality gates)
