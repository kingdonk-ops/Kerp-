## Goal
System admins see the SAQ queues and can retry or abort failed work (diff §4.7 Queue monitor).

## Acceptance criteria
- [ ] Every endpoint is `system_admin` only: any other caller, PER-09 included, gets 403 (test per endpoint, including a PER-09 of every project)
- [ ] `GET /api/v1/admin/system/queues`: per queue (`interactive`, `batch`) queued, active, scheduled and failed counts and the oldest queued age
- [ ] Cron jobs (on the batch worker; no separate cron queue) listed with last run, next run and last outcome
- [ ] `GET /api/v1/admin/system/queues/failed`: kind, queue, project code, attempts, error class and a message truncated to 500 characters; **never job kwargs, payloads or Redis mail payloads** (test with a job carrying a synthetic secret)
- [ ] `POST .../failed/{job_id}/retry` and `POST .../{job_id}/abort` (queued or active), each audited with actor and job kind; unknown id 404
- [ ] SAQ's own web UI is not mounted (it has no KERP auth)
- [ ] Module `README.md` and docs updated
- [ ] All quality gates green (see CLAUDE.md §Quality gates)
