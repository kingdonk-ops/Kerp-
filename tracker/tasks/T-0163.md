## Goal
TD-213 (record): the client's signature is a ledger entry carrying the signer's identity, accepted online or from an offline queue only when the signer was entitled to sign.

## Acceptance criteria
- [ ] A client co-sign writes its own sign-off ledger entry: signer user id and name, persona PER-15, the five time-evidence values of diff §6.4.1 (from T-0148), geolocation, the inspector's `device_id`, verification mode `online|offline`, drawn signature image (stored via T-0016) and inspection id
- [ ] Online it requires a valid unused co-sign token (T-0162); offline it arrives through `push-mutations` and the server re-checks that the signer was an active PER-15 member with the anchor in their granted subtree at `occurred_at`; otherwise that mutation fails and the inspector is notified
- [ ] A template with `requires_client_signature` makes `inspection.submit` fail with `CLIENT_SIGNATURE_MISSING` until a client co-signature exists for the current review round
- [ ] The inspection report (T-0158) prints the client signature next to the inspector's and reviewer's
- [ ] `signing` `README.md` and docs updated
- [ ] All quality gates green (see CLAUDE.md §Quality gates)
