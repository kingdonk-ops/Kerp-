## Goal
TD-163 (server side): Items carry scan identifiers and a scanned value resolves to its Item (asset-and-tagging.md §Scan identifiers).

## Acceptance criteria
- [ ] `oe_asset_item_identifier` (`item_id`, `kind` barcode|qr|nfc, `value`, `is_active`) with `BaseRecordMixin` + project RLS; an active `(project_id, kind, value)` is unique (409 on duplicate)
- [ ] Values are trimmed; NFC values are normalised to upper-case hex without separators; tests for each kind
- [ ] `GET /api/v1/assets/items/lookup?value=&kind=` returns Item id, tag, item type, node display path, work anchor and `inspectable`; no match or another project's Item → 404
- [ ] PER-06 and PER-09 may add and deactivate identifiers; deactivated identifiers stay for history; others → 403 (planner default)
- [ ] Identifiers of Items in a device's picks are exposed through the `asset_management` service for the pull scope (T-0147)
- [ ] No identifier is attached to a node (Items only, planner default)
- [ ] `asset_management` `README.md` and docs updated
- [ ] All quality gates green (see CLAUDE.md §Quality gates)
