## Goal
Issue templates designed like inspection templates, only simpler (issues.md §2): a one-engine form template of kind `issue` with frozen revisions whose metadata carries the issue type, category, flag defaults and the workflow step of each section; a pack/project-editable category list; the project's default template per category × type; and the three copied layers (system defaults → tenant library / client pack → project copy). Creates the `issues` module.

## Acceptance criteria
- [ ] Module `backend/app/modules/issues/` with `manifest.py`, `models.py`, `router.py`, `service.py`, `schemas.py`, `README.md`
- [ ] The forms template store (T-0110) accepts kind `issue`; revision metadata `name` (localised), `issue_type` (`punch | ncr`), `category` (an active category key), `default_origin`, `default_visibility` (`internal | client`), `default_mdr_effect` (`blocks | register_only | excluded`), `completion_effect` (`blocks | none`), `default_severity` is validated on save (422 with the path)
- [ ] Each section carries a `step` valid for the type (punch `raise | rectify | verify`; NCR `raise | containment | disposition | root_cause | corrective_action | effectiveness`); a missing step means `raise`; an NCR step on a punch template or vice versa → 422
- [ ] Metadata and step assignment are part of the frozen revision and its canonical hash; editing a published revision → 409; any field, step or flag-default change is a new revision (test)
- [ ] `oe_issues_category` (`key`, localised `label`, `is_active`, `sort_order`) on the system, tenant and project layers, seeded `painting, blasting, insulation, cladding, civil, mechanical, piping, welding, scaffolding, electrical, audit, general`; a used key cannot be deleted or re-keyed (409), only deactivated
- [ ] `oe_issues_default_template` unique `(project_id, category, issue_type)`; the mapped template must have that type and category (422)
- [ ] System-default templates ship in the module seed and in client packs (T-0108): at least a `general` punch template and a `general` NCR template with an optional 5-whys section in `root_cause`; a project copy keeps `derived_from`; a new library revision is offered to the project and never changes the project copy until adopted (test)
- [ ] Tenant library templates and categories are edited by PER-13; project templates, categories and defaults by the project's QA authority (`qa_reviewer_persona`) or PER-09; others 403
- [ ] The seed format supports tenant-default templates authored by us; the Pilot-0 starting set (painting, blasting, civil, mechanical, welding × punch/NCR, internal audit) is seeded by T-0322
- [ ] `GET /api/v1/issues/templates?issue_type=&category=` lists the project's published templates with type, category and flag defaults (filter tests)
- [ ] Tables use `BaseRecordMixin` and have RLS policies (project tables project-scoped; system/tenant layers with `project_id` NULL)
- [ ] Module `README.md` and docs updated
- [ ] All quality gates green (see CLAUDE.md §Quality gates)
