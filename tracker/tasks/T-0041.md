## Goal
The user side of the lobby and the access-request lifecycle (diff §4.1; product owner, 2026-11-14). The admin inbox is T-0051.

## Acceptance criteria
- [x] Lobby route: internal users see the lobby-visible projects (code, name) with 'Request access' and an optional message (T-0040); external users see no list (no request is made for it, `is_internal` from `/auth/me`) and a short hint that projects are joined by code or invite
- [x] A project-code field (all users) finds one project by exact code and offers 'Request access', which sends the lookup ticket returned by that lookup with the request (T-0040, T-0050; a code never grants access, TD-202); unknown code shows a neutral 'not found' message; a project the user already belongs to offers 'Open' instead
- [x] **Active requests** panel from `GET /access-requests/mine` (T-0050): each request with project code/name and a status chip (`pending`, `approved`, `rejected`, `withdrawn`); pending → 'Withdraw'; approved → 'Open project'; rejected → the decider's reason when given and a **'Request again'** action that is disabled with "available from <local time>" until `request_again_at`, then files a new request **without a ticket** (an earlier rejected or withdrawn request makes one unnecessary, T-0050; cooldown 409 handled with the same message)
- [x] The panel refreshes on lobby open and on window focus, so a requester learns the outcome without a project notification (they are not a member)
- [x] Users with no project land here (T-0042); users with projects reach it from the picker entry **"Browse / join another project"** (product owner, 2026-11-14; T-0042)
- [x] Approving a request makes the project appear in the requester's picker on their next load
- [ ] All strings through `t()`; component tests (incl. the cooldown countdown with a fake clock) and one e2e journey for an **external user and a project found by code** (code lookup → request with ticket → reject with reason → chip and reason shown, Request again disabled → after the cooldown (short cooldown configured for the test) Request again without a ticket → approve via T-0051 → project appears in the picker), synthetic data only
- [x] Module `README.md` and docs updated
- [x] All quality gates green (see CLAUDE.md §Quality gates)

  - **Request again on withdrawn requests too.** The criterion names the action for `rejected`; the spec says a withdrawn request has no cooldown and needs no ticket for a new request (diff §4.1, T-0050), so a withdrawn card offers Request again at once (`request_again_at` is null).
  - **Picker refresh.** "Open project" / "Open" reload `/me/projects` before picking the project; when the panel shows an approval the picker does not list yet, `/me/projects` is reloaded once per request, so the project appears without a new sign-in (beyond "on their next load").
  - **Window focus** uses a `focus` listener on `window` (TanStack Query v5 only listens to `visibilitychange`); the app-wide `refetchOnWindowFocus: false` is unchanged.
  - Message ≤ 1000 characters (`AccessRequestCreate`). Other 409s ("already pending", "already a member") and a 404 on filing (expired ticket → enter the code again) have their own messages.
