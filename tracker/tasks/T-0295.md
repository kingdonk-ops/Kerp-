## Goal
External accounts (clients, subcontractors, labs; `is_internal = false`) never read internal commercial data, whatever persona a PER-09 gives them (diff §4.9 *External parties*). A guard for the modules that will carry such data (Phases 4–6).

## Acceptance criteria
- [ ] Route classification `data_class` (`project` default, `internal_commercial`) declared on routers; an `is_internal = false` caller of an `internal_commercial` route gets 404 (not 403: no existence oracle)
- [ ] Schema helper marks response fields `internal_commercial`; they are omitted for external callers (unit test on a sample schema)
- [ ] Contract test over every mounted route: each route has a data class; any route in a module manifest flagged commercial (`commercial`, `progress_claims`, `variations`, `costmodel`, estimating, CBS burn) without a class fails CI
- [ ] Client-facing claim verification for PER-15 stays a `project` class route by explicit declaration (documented in the README; TD-435 confirms)
- [ ] `is_internal` is read from the verified session user only (never request input), as in diff §4.1
- [ ] Module `README.md` and docs updated
- [ ] All quality gates green (see CLAUDE.md §Quality gates)
