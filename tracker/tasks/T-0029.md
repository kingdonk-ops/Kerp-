## Goal
A review approval must cover tracker content: changing a task's goal or acceptance criteria after approval needs a new review. Covers TD-013 (user decision 2026-11-09: fix now).

Also (absorbed from T-0066): `scripts/tracker.py set --note` always prefixes today's date, so notes that already start with a date end up as `- date: date: ...` (seen in E-05-07, T-0110; raised in PR #14 and #34).

## Acceptance criteria
- [x] The review-gate patch-id includes `tracker/` content
- [x] Bookkeeping-only changes do not invalidate approval: front-matter `status`, `pr`, `owner`, `updated` and dated note lines (`- YYYY-MM-DD: ...`) are normalised away
- [x] Generated boards (`docs/TASKS.md`, `docs/TODO.md`) stay excluded
- [x] Tests in `scripts/tests` cover: content change → new patch-id; bookkeeping-only change → same patch-id
- [x] `.github/workflows/review-gate.yml` and the reviewer/coordinator docs use the same computation
- [x] TD-013 resolved in the same PR
- [x] `set --note` skips its own date prefix when the note already starts with an ISO date (`YYYY-MM-DD`); tested in `scripts/tests` — from T-0066 (PR #14, #34 review)
- [x] Existing doubled prefixes in `tracker/` cleaned — from T-0066 (PR #14, #34 review)
- [x] All quality gates green (see CLAUDE.md §Quality gates)
