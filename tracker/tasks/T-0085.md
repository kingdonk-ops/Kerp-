## Goal
A System admin must not be able to deactivate their own account. T-0331 hides Deactivate on the caller's own row, but the client never asserts authority: `admin.service.update_user` refuses only the last active System admin (TD-274). Enforce the rule on the server and show a clear message if the screen ever sends it (stale list, second tab).

## Acceptance criteria
- [ ] `PATCH /api/v1/admin/users/{id}` with `{"is_active": false}` where `id` is the caller answers 409 `{"code": "CANNOT_DEACTIVATE_SELF", "detail": ...}` and writes nothing, also when other active System admins exist (test); the last-admin 409 is unchanged (existing test kept green)
- [ ] Deactivating another user, renaming oneself and reactivating are unchanged (tests)
- [ ] The refusal is audited: one ledger entry on the `admin-user:{id}` stream with `{"action": "update_refused", "reason": "self_deactivation"}` that survives the refused request's rollback (test reads the ledger after the 409)
- [ ] The check lives in `admin.service.update_user` (one place; the router only maps the error), so any future caller of the service gets it
- [ ] Admin -> Users maps 409 `CANNOT_DEACTIVATE_SELF` to an i18n message (`admin.users.*`, via `t()`) and re-reads the list; vitest covers the mapping; the own-row button stays hidden (existing test green)
- [ ] OpenAPI documents the 409 code; `npm run gen:api` re-run and committed if the schema changed
- [ ] TD-463 resolved by this task
- [ ] Module/README.md and docs updated (`backend/app/modules/admin/README.md`, `frontend/src/admin/README.md`)
