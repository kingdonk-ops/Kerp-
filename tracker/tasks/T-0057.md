## Goal
Product-owner decision 2026-11-14 (TD-136; diff §4.2 *Magic links for Field Workers only*): only users with a PER-14 Field Worker grant on at least one project (or a valid pending invite naming PER-14) can sign in by magic link; everyone else uses password or Entra ID SSO, without the API revealing which accounts or personas exist.

## Acceptance criteria
- [ ] Eligibility = an active account with at least one effective PER-14 grant (direct or team-derived, T-0073) on a project that is not soft-deleted, read through the projects/admin module's `service.py` (no cross-module table access), behind one eligibility function in the identity service that T-0052 extends with the invite branch (a valid pending invite naming PER-14 for the account's e-mail)
- [ ] `POST /api/v1/auth/magic-link` for an ineligible user returns the **same 202 body, status and headers** as for an unknown e-mail and an eligible user; no magic-link record is stored and no mail is sent (fake mail transport asserts nothing queued); the existing request lockout / mailbox-flood cap (T-0068, TD-224) applies unchanged
- [ ] The refusal is logged and audited with reason `magic_link_not_field_worker` (no token, no e-mail in plain logs beyond what the audit ledger already records)
- [ ] Redeem re-checks eligibility: a link issued while the user held PER-14 is refused with the neutral invalid-link error once the last PER-14 grant was removed (or the project soft-deleted) before redeem
- [ ] No timing oracle: the ineligible path does the same hashing/lookup work as the eligible path, so an eligible vs ineligible vs unknown e-mail is not distinguishable by a measurable response-time difference (test asserts the same code path up to the send step, e.g. via a spy, not wall-clock)
- [ ] Tests: PER-14 direct grant → link issued; PER-14 only via a team link → issued; PER-14 only on a soft-deleted project → neutral 202, nothing issued; other persona only (e.g. PER-06) → neutral 202, nothing issued; no membership at all → neutral 202; PER-14 removed between request and redeem → redeem refused
- [ ] Module `README.md` (identity) documents the rule and the neutral response; docs updated
- [ ] All quality gates green (see CLAUDE.md §Quality gates)
