## Goal
Raise issues from inspections and audits (issues.md §8; quality-and-inspection.md §Post-submit automation): a failed painting inspection raises the painting punch or NCR, and the lifecycle's `INSPECTED_FAILED → (Cat A punch | NCR)` goes through this action.

## Acceptance criteria
- [ ] `action_type` `create_issue` with `action_config` `{template_key | "default", issue_type, punch_category?, severity?, answer_mapping}` validated on save (published template of that type, mapping keys exist in both templates; 422 with the path); part of the frozen inspection template revision
- [ ] `create_issue` rules run on the transition to `INSPECTED_PASSED` / `INSPECTED_FAILED` (after review, T-0150), not at `SUBMITTED`; a returned inspection raises nothing (test)
- [ ] The issue is created through `issues.service` (no cross-module table access): anchor = the inspection's anchor, `source_inspection_id`, mapped answers and photos (same attachment ids), `raised_by` = the approving reviewer, ledger `source = "automation"`, an action-log row (test with a synthetic painting pack)
- [ ] Approving as failed when no rule raised an issue requires an inline issue in the same request (422 `ISSUE_REQUIRED` otherwise); `RE_INSPECT` requires at least one linked issue
- [ ] On a path with no work-anchor node the action is logged `skipped` with `NO_WORK_ANCHOR`, the reviewer and the QA authority are notified, and the result is not rolled back (TD-443 default; test)
- [ ] Inspection template revisions accept an optional `issue_category` (a category key, part of the revision hash); `GET /api/v1/issues/templates?for_inspection={id}` pre-filters by type + that category and pre-selects the project default
- [ ] A standalone audit template (T-0179) raises an internal audit issue (`origin = internal_audit`, `internal`, `excluded`) through an audit issue template (test)
- [ ] Module `README.md` and docs updated
- [ ] All quality gates green (see CLAUDE.md §Quality gates)
