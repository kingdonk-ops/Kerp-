## Goal
Raise issues from inspections and audits (issues.md §8; quality-and-inspection.md §Post-submit automation): a failed painting inspection raises the painting punch or NCR, and the lifecycle's `INSPECTED_FAILED → (Cat A punch | NCR)` goes through this action.

## Acceptance criteria
- [ ] `action_type` `create_issue` with `action_config` `{template_key, punch_category?, severity?, answer_mapping}` validated on save: `template_key` must be one of the template's linked issue types (T-0327; a template without linked issue types cannot use `create_issue`), the type comes from that template, mapping keys exist in both templates; 422 with the path; part of the frozen inspection template revision
- [ ] `create_issue` rules run on the transition to `INSPECTED_PASSED` / `INSPECTED_FAILED` (after review, T-0150; at the final submit of an informal record, T-0324), not at `SUBMITTED`; a returned inspection raises nothing (test)
- [ ] The issue is created through `issues.service` (no cross-module table access): anchor = the inspection's anchor, or a project-level issue with the inspection's location and links for a project-level inspection (T-0326), `source_inspection_id`, mapped answers and photos (same attachment ids), `raised_by` = the approving reviewer (the submitter for an informal record), ledger `source = "automation"`, an action-log row (test with a synthetic painting pack)
- [ ] Approving as failed when no rule raised an issue requires an inline issue in the same request, its template among the T-0327 resolution options (422 `ISSUE_REQUIRED` otherwise); `RE_INSPECT` requires at least one linked issue; informal records force nothing
- [ ] A `qa_itp` inspection on a path with no work-anchor node: the action is logged `skipped` with `NO_WORK_ANCHOR`, the reviewer and the QA authority are notified, and the result is not rolled back (TD-443 resolved: remaining case; test); a project-level inspection raises a project-level issue instead (test)
- [ ] Manual raise from an inspection (`POST /api/v1/inspections/{id}/issues`) uses the T-0327 resolution (single / pick / fallback by discipline × type) and sets `source_inspection_id`
- [ ] An internal audit template (T-0324 audit tick, any area) raises an issue with `origin = internal_audit`, `internal`, `excluded`; an external audit template `origin = external_audit`, `client`, `blocks` (tests through the seeded `audit` templates)
- [ ] Module `README.md` and docs updated
- [ ] All quality gates green (see CLAUDE.md §Quality gates)
