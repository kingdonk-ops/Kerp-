## Goal
UI half of T-0059 and T-0077 (diff §4.1, §4.2): an external invitee creates their password from the invite e-mail and lands in the project; everyone with a password can reset it by e-mail.

## Acceptance criteria
- [ ] `/invite#<invite_token>.<setup_token>` (T-0053 route): when `setup-preview` says a first password can be set, show "Create your password" (e-mail shown read-only, password + confirm, live length hint from the server policy, show/hide toggle, paste allowed) as the primary action; submit `accept-with-password`; on success open `joined_project_id`; policy errors shown translated; no Microsoft button on this screen
- [ ] Copied link (no `setup_token`) for an account without credentials → "Send me an e-mail to set my password" (T-0077 request), keeping the `invite_token` for the carry-through after sign-in
- [ ] Sign-in screen: "Forgot password?" link → e-mail form → the same neutral confirmation for every address; `/reset-password#<token>` reads the token from the fragment, removes it from the address bar (no referrer), sets a new password, then routes to sign-in with a translated success message
- [ ] Same screens in the Capacitor Android build (App Link `https://<deployment>/invite` and `/reset-password`, verified via `assetlinks.json`; T-0143)
- [ ] All strings through `t()`; component tests with a mocked server; e2e journeys against the fake mail transport: (1) PER-09 invites a brand-new external user → invite e-mail → create password → lands in the project; (2) forgot password → e-mail → reset → old session refused → sign in with the new password
- [ ] Module `README.md` and docs updated
- [ ] All quality gates green (see CLAUDE.md §Quality gates)
