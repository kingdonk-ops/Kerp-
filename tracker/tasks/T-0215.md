## Goal
Close TD-212 and the stuck-`verifying` part of TD-209 (review finding 3). Abandoned uploads never expire and their staging objects pile up; a verify job that fails with an internal error leaves its file `verifying` forever.

## Acceptance criteria
- [ ] The scheduler of T-0214 enqueues `uploads.sweep_orphans` for every live project every hour
- [ ] `sweep_orphans` rejects (reason `verify_failed`) a `verifying` file whose job has `failed` (read through the jobs service by `UploadedFile.job_id`, never the jobs table), or that has been `verifying` for more than 6 hours, and deletes its staging/quarantine objects
- [ ] A healthy `verifying` file (job queued/running, younger than the limit) is left alone
- [ ] The new reason code is in the API schema (and the generated client, if it changes) and i18n
- [ ] All quality gates green
