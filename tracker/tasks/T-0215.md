## Goal
Close TD-212 and the stuck-`verifying` part of TD-209 (review finding 3). Abandoned uploads never expire and their staging objects pile up; a verify job that fails with an internal error leaves its file `verifying` forever.

## Acceptance criteria
- [x] The scheduler of T-0214 enqueues `uploads.sweep_orphans` for every live project every hour
- [x] `sweep_orphans` rejects (reason `verify_failed`) a `verifying` file whose job has `failed` (read through the jobs service by `UploadedFile.job_id`, never the jobs table), or that has been `verifying` for more than 6 hours, and deletes its staging/quarantine objects
- [x] A healthy `verifying` file (job queued/running, younger than the limit) is left alone
- [x] The new reason code is in the API schema (and the generated client, if it changes) and i18n
- [x] All quality gates green

## Context
Repo review 2026-11-15, owner-accepted (finding 3). Supersedes TD-212; TD-209 keeps file deletion and content-object GC.

## Notes
- 2026-11-16: Generic hook: `registry.schedule_hourly_per_project(kind)`; `scheduler.hourly_project_jobs` (cron `17 * * * *`, batch worker) queues each such kind (`source="system"`) in every live project. The uploads module registers `uploads.sweep_orphans`. `sweep_orphans` now returns a `rejected` count. `verify_failed` is a stored `rejection_reason` string (the API field is `str`, so the OpenAPI schema and the generated client do not change); the frontend has no reason translations yet (no upload UI), so there is no i18n key to add.
- 2026-11-16: Review round 1 (PR #102, approved; robustness follow-ups applied): the sweep's `verifying` read and `verify_upload`'s final read lock the row (`FOR UPDATE`, PostgreSQL), so a sweep and a late verify job cannot leave a mixed row; `hourly_project_jobs` logs and continues when one project fails and skips (logs) a scheduled kind without a handler; the cron has the explicit `CRON_TIMEOUT_S`. New tests: a failing project does not skip the others, unknown kind skipped, no tenant / nothing scheduled, `job_status` is `None` out of scope. Rebased on the round-2 T-0214 branch. TD-212 is closed and TD-209 annotated when this merges (coordinator).
