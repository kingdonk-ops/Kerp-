## Goal
Admin side of access requests (diff §4.1, §6.1): PER-09 holders see and decide pending requests for their projects.

## Acceptance criteria
- [ ] Admin → Access requests (diff §6.1) lists pending requests (requester name and e-mail, project, message, age) for the projects where the user holds PER-09 (all projects for a `system_admin`), from T-0050
- [ ] Approve opens persona(s) + site-scope selection; when the API returns the PER-09 + hold-authority `sod_warning` the dialog shows it and re-submits with `confirm_sod: true` only after the user confirms (T-0014)
- [ ] Reject asks for an optional reason (≤ 500 characters, with a counter) and states that the requester will see it
- [ ] Decided requests leave the list; a 409 (already decided or withdrawn) shows a neutral message and refreshes the list
- [ ] The nav item is shown only to users who hold PER-09 on some project or `system_admin`
- [ ] All strings through `t()`; component tests with synthetic data
