## Goal
Close two races in the validation module and a display-code bug in asset management (audit items 9 and 10): a concurrent approve and reject of a rule unlock must not leave the rule unlocked but marked "rejected"; two concurrent rule-set edits must not both become the same version; clearing the last display-code template must recompute the codes.

## Acceptance criteria
- [ ] `approve_unlock` / `reject_unlock` (`validation/service.py`) change the request with a guarded `UPDATE … WHERE id = :id AND status = 'pending'` and check the row count; the loser gets 409 and writes no audit entry (as `overrides.py` already does). PostgreSQL test: approve and reject run concurrently (two sessions, barrier), exactly one succeeds, the final status matches the unlock state, one audit entry
- [ ] A rule-set version bump locks the rule-set row first (`SELECT … FOR UPDATE`, as `projects._locked` does); PostgreSQL test: two concurrent edits end as two consecutive versions, never the same number twice
- [ ] `asset_management/service.py` `_refresh_display_codes` no longer returns early when no level has a template; the early return applies only to the move-node path; clearing the last template recomputes every `display_code` to the default (test: `101 / 101.1 []` becomes `101.1` after the template is cleared)
- [ ] Module/README.md and docs updated
- [ ] All quality gates green (see CLAUDE.md §Quality gates)
