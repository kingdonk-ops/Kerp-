## Goal
The `review-gate` required check must not be satisfiable by the PR it checks, and every
workflow that holds a write token must pin its actions by commit SHA (repo review 2026-11-13,
findings 2 and 7).

## Acceptance criteria
- [x] `review-gate.yml` checks out the PR base into `base/` and runs `base/scripts/review_gate.py`; the PR head checkout is used only for the patch-id
- [x] `scripts/review_gate.py` counts `KERP-REVIEW` markers from PR reviews only (issue comments never re-trigger the gate, so they no longer count)
- [x] `actions/checkout` in `review-gate.yml` and `promote.yml` is SHA-pinned like `ci.yml`
- [x] `scripts/tests` asserts: gate script runs from the base checkout; every `uses:` in `.github/workflows/` is pinned to a 40-hex SHA; issue-comment markers are ignored
- [x] `docs/WORKFLOW.md` says where the gate script runs from and that markers are PR reviews
- [x] All quality gates green

## Notes
- `review-gate.yml` checks out base (sparse: `scripts`) into `base/` and the head into `pr/`; runs `python ../base/scripts/review_gate.py` in `pr/`. Both checkouts `persist-credentials: false`.
- Limitation: `pull_request` and `pull_request_review` both run the PR's copy of the workflow file, so a PR can still change the workflow (or add one with a `review-gate` job). Not fixable in-repo; recorded on TD-223.
- This PR's own gate already runs its *new* workflow (GitHub uses the PR's copy), i.e. `dev`'s `review_gate.py` from `base/`; that copy still reads issue comments until this merges.
- Recovery note: a broken gate script on `dev` cannot be fixed by a PR alone (the fix is judged by the broken base copy); it needs a one-off admin merge.
