## Goal
Template-level post-submit rules that run after an inspection is submitted (quality-and-inspection.md §Post-submit automation). Part 1 of the pasted T-0180: rule store, engine, action log and the `update_target_fields` action. `notify_users` is T-0256, `create_action_task` and the tagout gate T-0257.

## Acceptance criteria
- [ ] `oe_inspections_post_action` (`BaseRecordMixin` + RLS; scope follows its template revision): `template_revision_id`, `sort_order`, `name`, `enabled`, `trigger_cel` (default `true`), `action_type` (`update_target_fields | notify_users | create_action_task`), `action_config` JSONB; part of the frozen template revision (a change makes a new revision) and copied with client packs (T-0108)
- [ ] Editable by the project's PER-06 and PER-09 only while the revision is a draft; others 403
- [ ] `trigger_cel` compiles on save through the T-0017 runtime against the documented context (`answers`, `result`, `category`, `inspection`, `equipment`, `node`, `item`); an invalid expression or unknown variable → 422; evaluation is sandboxed and fails closed (only exactly `true` fires)
- [ ] `action_config` is validated per action type on save (422 with the path)
- [ ] After the transition to `SUBMITTED` (T-0150), for authenticated and (later) public submissions, enabled rules run in `sort_order`; database actions run in the submit transaction; a failing database action rolls back the submit with a user-readable reason
- [ ] `update_target_fields` writes only fields the owning module whitelists in its `service.py` (equipment: `last_inspected_at`, `last_inspection_id`, status `out_of_service | quarantined`; node/Item: `last_inspected_at`, `last_inspection_id`; anything else 422 on save). Automations only restrict, never release: no transition to `active` or any less restrictive status (test)
- [ ] Status changes go through the owning module's transition (which runs its own `run_checks`); no cross-module table access (test with a fake service)
- [ ] `oe_inspections_action_log` (`BaseRecordMixin` + RLS): inspection, rule, action type, outcome (`applied | skipped | failed`), changed fields `{field: [old, new]}`; every applied action is also a T-0006 ledger entry with `source = "automation"` (adds `automation` to `RECORD_SOURCES` with a short implementer ADR; TD-417)
- [ ] A template with no rules submits with zero side effects and no log rows (test)
- [ ] A passing pre-start sets `last_inspected_at` and leaves the equipment status unchanged (test with a fake equipment service until T-0249/T-0250)
- [ ] Module `README.md` and docs updated
- [ ] All quality gates green (see CLAUDE.md §Quality gates)
