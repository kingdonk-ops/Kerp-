## Goal
TD-165 (planning part): inspections are assigned and dated, so the inspector sees their work and the dashboard can count overdue ones (quality-and-inspection.md §Planning fields).

## Acceptance criteria
- [ ] Fields `assignee_user_id` (nullable), `planned_start` (date, nullable), `planned_duration_days` (integer ≥ 1, default 1) and stored `due_date` = start + duration − 1, recomputed on change
- [ ] The assignee must be a project member allowed to perform inspections (else 422); PER-06 and PER-07 on the project may set the fields, others get 403 (planner default)
- [ ] `overdue` is computed in the project timezone: `due_date` before today and status `PENDING`, `INSPECTION_REQUESTED` or `RETURNED`; tests at a timezone boundary with a fake clock
- [ ] Assigning notifies the assignee (T-0019; push via T-0144 when present)
- [ ] The inspection list endpoint filters by assignee, overdue and due-date range
- [ ] Additive migration; `inspections` `README.md` and docs updated
- [ ] An inspection whose submit `occurred_at` is on or before `due_date` counts as on time even when it syncs later (test)
- [ ] All quality gates green (see CLAUDE.md §Quality gates)
