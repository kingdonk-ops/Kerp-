## Goal
Saved views with `visibility = team` are shared with **one or more teams**, all linked to the
view's project, and are visible only in that project (register-views §3 team visibility, user
2026-11-13, TD-230/TD-244). Wire saved views to the teams service contract (T-0013) in place of
the fail-closed stub left by T-0020 (absorbs TD-242).

## Acceptance criteria
- [ ] Additive migration: link table `oe_saved_view_team` (`saved_view_id`, `team_id`; `BaseRecordMixin`, project RLS like `oe_saved_view`; unique among non-deleted rows). Every existing `oe_saved_view.team_id` is copied into it. The `team_matches_visibility` CHECK is relaxed so new rows keep `team_id` NULL. The column stays, nullable and unused, documented as deprecated. Dropping it later is destructive and needs an ADR (raise a `later` TODO)
- [ ] API: create/update takes `team_ids: list[UUID]`. It is required and non-empty when `visibility = team`, and must be empty otherwise (422). Every id must be in `teams.service.project_team_ids(project_id)` of the bound project, else 422 with the same body for unknown, other-project and other-tenant ids. Responses return `team_ids` (only teams still linked to the project)
- [ ] Visibility: the router passes `teams.service.user_team_ids(session, user_id)` into the viewer. A team view is visible to its owner, the project's PER-09 and any member of a named team that is still linked to the project. A team that is deleted or unlinked stops seeing it. With no named team left, the view is visible to owner and PER-09 only (no error)
- [ ] Who may share: any user who may create a view in the project may share it to any team linked to the project; they need not be a team member (planner default; the spec only restricts edit of shared views to owner or PER-09, which stays as T-0020 built it)
- [ ] The saved_views module manifest depends on `teams`, and the `team` visibility returns 422 when the teams module is unavailable
- [ ] No saved_views code reads teams tables (service contract only, CLAUDE.md §6)
- [ ] Tests: shared to teams X and Y; a member of Y sees it, a project member in neither does not. Unlinking X from the project hides it from X-only members. A team id linked only to another project is rejected with 422. Migrated legacy `team_id` rows behave the same as link rows. Owner/PER-09 fallback when all teams are gone
- [ ] Module/README.md and docs updated; `npm run gen:api` re-run and committed if the OpenAPI schema changed
- [ ] All quality gates green (see CLAUDE.md §Quality gates)
