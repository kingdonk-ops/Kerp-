## Goal
TD-166 (data part): a photo answer records when and where it was taken and the inspector's annotation, without changing the original image (quality-and-inspection.md §Photo answers and annotation).

## Acceptance criteria
- [ ] The `photo` field value schema in `core/fields` is a list of `{attachment_id, sha256, captured_at, geo, annotation}`; `geo` is `{lat, lon, accuracy_m}` or null; the server receipt time is stored as well
- [ ] Annotation schema v1: shapes `arrow`, `ellipse`, `rect`, `freehand`, `text` (≤ 200 characters), four-colour palette, `thin|thick` stroke, coordinates normalised 0–1, at most 50 shapes; an invalid annotation → 422 for that path (and a failed mutation result through sync)
- [ ] The schema is shared with the client (TS types generated or mirrored and covered by the same fixtures)
- [ ] The original attachment is never modified; annotations are read-only once the inspection is `SUBMITTED` (T-0150)
- [ ] `forms` `README.md` and docs updated
- [ ] All quality gates green (see CLAUDE.md §Quality gates)
