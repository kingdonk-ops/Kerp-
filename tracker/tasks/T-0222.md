## Goal
System admins browse the audit ledger and prove chain integrity on demand (diff §4.7 Audit explorer).

## Acceptance criteria
- [ ] Every endpoint is `system_admin` only: any other caller, PER-09 included, gets 403 (test per endpoint, including a PER-09 of every project)
- [ ] `GET /api/v1/admin/system/audit`: filters actor, device id, chain-key prefix, payload `event` key or boolean flag (e.g. `sod_warning`), date range; keyset paging; read under normal RLS: tenant-level chains plus the project chains of every project of the tenant (ADR 0016, T-0274; test: a `system_admin` without memberships reads project chains; a non-admin gets 403)
- [ ] Reads through `app/core/audit` service functions (core gains read helpers; no module imports in core); no endpoint updates or deletes a ledger row
- [ ] `POST /api/v1/admin/system/audit/verify` with a chain key: synchronous `verify_chain` report (contiguous seq, prev_hash links, recomputed content_hash)
- [ ] `POST /api/v1/admin/system/audit/verify-all`: a `batch` SAQ job verifying every chain the caller can read, result stored on the job (counts, first broken chain/seq), audited
- [ ] Tests: a tampered synthetic chain (fixture with a bypassed trigger in the test DB) reports the exact broken seq; filter and paging tests
- [ ] Module `README.md` and docs updated
- [ ] All quality gates green (see CLAUDE.md §Quality gates)
