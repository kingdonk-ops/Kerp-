## Goal
15 personas (PER-01…PER-15) incl. Field Worker + Client Portal User; capability tiers (V/C/E/A/S); Asset-Site scoping filter for Site Inspectors (diff §4; edge spec §5 enumerates the matrix and SoD rules). Cross-project reads use an **explicit multi-project scope** bound from memberships (TD-053, edge spec §6 amendments).

## Acceptance criteria
- [x] Site Inspector sees only their site's records (edge spec §5.2 PER-07)
- [x] SoD: project admin cannot release quality holds (edge spec §5.2 PER-09)
- [x] The session binds `app.allowed_project_ids` derived from the user's project memberships (from the verified JWT/membership store, never from request parameters); writes stay limited to the single bound `app.current_project_id` (edge spec §6 amendments, TD-053)
- [x] RLS read policy covers the allowed list: a portfolio persona (PER-01/10/11/12/13) with memberships in A and B reads rows of A and B in one session; a write to B while bound to A is refused (PostgreSQL test as `kerp_app`)
- [x] A user whose allowed list is [A] cannot read any row of project B (PostgreSQL test); an unbound session still sees nothing (T-0007 behaviour unchanged)
- [x] `app/core/tenancy/README.md` updated for the multi-project scope
- [x] All quality gates green (see CLAUDE.md §Quality gates)
