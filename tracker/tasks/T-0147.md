## Goal
TD-162 (server side): a field device pulls only what it picked for offline work plus the project reference data it needs, in pages, and learns when a record leaves its scope (diff §6.4).

## Acceptance criteria
- [ ] A download pick is an ADR 0005 checkout with scope `inspection` or `node` (anchor subtree) for one device, user and project; removing a pick releases it; more than 500 inspections per device and project → 422 (diff §6.4, planner default)
- [ ] `GET /api/v1/sync/download-candidates?project_id=` lists assigned-to-me inspections first, then unassigned ones, with status, anchor display path (via the `asset_management` service), due date, `downloaded` for this device and an estimated size = record JSON bytes + stored attachment sizes (T-0016); test with synthetic attachments of known size
- [ ] `pull-deltas` takes `project_id`, `since_version`, `limit` (default 500, max 1,000; above → 422) and returns `{deltas, new_version, has_more}` ordered by commit sequence; a test pulls 2,500 changes in pages and gets each exactly once
- [ ] Only in-scope records are returned: the device's picks (records, answers, answer comments, attachment metadata, linked open defects) and project reference data (level defs, terminology, item types and field defs, pinned/allowed template revisions, equipment with calibration state, rule sets, member display names); a test proves a record of another device's pick, another project or another tenant is never sent (cross-tenant → 404)
- [ ] A newly added pick is back-filled in full on the next pull regardless of `since_version`
- [ ] A `remove` delta is emitted when a pick is removed, a picked record is soft-deleted, or a picked inspection becomes `INSPECTED_PASSED`, `INSPECTED_FAILED` or `LOCKED_FOR_TURNOVER` (the server drops it from every device's picks)
- [ ] Endpoints are client-agnostic (no Android-only path) and refuse a revoked device with `DEVICE_REVOKED` (diff §4.3, §6.2)
- [ ] Reads go through the owning modules' services; no cross-module table access
- [ ] Tables use `BaseRecordMixin` and have a project-scoped RLS policy
- [ ] `sync` `README.md` and docs updated
- [ ] All quality gates green (see CLAUDE.md §Quality gates)
