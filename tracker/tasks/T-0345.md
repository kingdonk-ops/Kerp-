## Goal
Close three auth gaps from the audit: a PIN change can clear a `PIN_EXHAUSTED` lockout from any live session (item 6, against the TD-301 ruling); a lost or failed refresh response ends the whole session (item 7); magic-link requests and SSO start have no per-client limit (item 12).

## Acceptance criteria
- [ ] `PUT /api/v1/devices/{id}/pin` (`core/auth/device_api.py`): when the device is at the PIN-failure limit (`PIN_EXHAUSTED`), the change needs a session created by password or magic-link sign-in (or SSO) within the last 5 minutes and not renewed by PIN unlock; otherwise 401 with a distinct code (e.g. `FRESH_SIGN_IN_REQUIRED`) and nothing changes; below the limit the TD-301 behaviour is unchanged (tests: fresh sign-in clears the lock; a 6-minute-old session, a PIN-renewed session and a refreshed session older than 5 minutes get 401; below the limit any bound session works)
- [ ] The session records how and when it was started (sign-in method + time) in a way that survives refresh rotation; PIN unlock does not reset it (test)
- [ ] Refresh (`core/auth/service.py` refresh path): the DB lock and active-user check run before `consume_refresh`; a retry of an already-consumed refresh token within 30 seconds of its consumption gets a plain 401 (`REFRESH_RETRY` or the existing invalid code) without revoking the session; a replay after the grace still revokes the whole session (tests: lock timeout / failed commit leaves the token unconsumed; retry within grace does not end the session; replay after grace does; tests use an injected clock, not the wall clock (TD-509))
- [ ] `POST` magic-link request (`core/auth/router.py`) gets the same per-client lockout as `PasswordResetService.request` (`password_reset.py`), checked before the per-address limit; 429 with `Retry-After` (test: one client posting many different addresses is limited; a second client is not)
- [ ] `GET /auth/sso/entra/start` (`sso_router.py`) gets a per-client limit before it stores a state entry (test); TD-323 resolved
- [ ] TD-301 resolved (point (2) amendment built here; points (1), (3), (4) confirmed as built); README of `core/auth` documents fresh sign-in, the refresh grace and the per-client limits
- [ ] Module/README.md and docs updated
- [ ] All quality gates green (see CLAUDE.md §Quality gates)
