## Goal
One ltree tree whose levels are per-project configuration (ADR 0003 as amended): `oe_asset_level_def` carries the level roles; `oe_asset_node` keeps ltree `tree_path` NOT NULL + GiST, `parent_id` as source of truth, read-only `display_path`, subtree move in one ltree statement (diff §2.2). Work anchors to a work-anchor node — at most one per root-to-leaf path, never nested; no BOQ anchor.

## Acceptance criteria
- [ ] `oe_asset_level_def` with `key`, `depth`, `allowed_parent_keys`, `label_key`, `roles`, `code_pattern`, `code_uniqueness`, `field_schema_id`, `display_code_template`; unique `(project_id, key)`; `roles` limited to `grouping`, `physical`, `work_anchor`, `inspection_anchor`, `progress_unit`, `schedule_link`; a key in use cannot be changed (asset-and-tagging.md §oe_asset_level_def)
- [ ] `oe_asset_node.level_def_id` FK; create and move reject a parent whose level key is not in the child level's `allowed_parent_keys` (§oe_asset_node)
- [ ] `tree_path ltree NOT NULL` with a GiST index; `CREATE EXTENSION ltree` in the migration
- [ ] `parent_id` is the relational source of truth; `POST /assets/nodes/{id}/move` updates the whole subtree in a single ltree statement and writes old/new path to the audit ledger (§Restructure with history)
- [ ] `display_path text` maintained read-only (breadcrumb only; never queried against)
- [ ] PostGIS `spatial_location` (PointZ, EPSG:4326), `custom_fields jsonb`, `code` (text), computed `display_code`, `progress_unit` columns (`budget_qty`, `uom`, `budget_hours`, `earned_qty`) and lineage columns (`status`, `superseded_by`, `derived_from`; operations in T-0134) present
- [ ] Anchor invariant enforced on create and move: a work-anchor node may not have a work-anchor ancestor or descendant (never nested, at most one per root-to-leaf path); a path with no work anchor is allowed (TD-113 default); tested with two breakdown templates side by side in one project (remediation Site/Asset/RSW and CUI Scope/Job Package/Line) (§Anchor invariants)
- [ ] Code uniqueness enforced per the level's `code_uniqueness` (`per_parent`, `per_level`, `per_project`) — a duplicate is rejected (409) in each mode; `code_pattern` validated; codes like `101.1`, `SI-001` stored as text unchanged
- [ ] No BOQ anchor: no BOQ column or FK exists on node or level def (test)
- [ ] Both tables use `BaseRecordMixin` and have a project-scoped RLS policy
- [ ] `asset_management` `README.md` and docs updated
- [ ] All quality gates green (see CLAUDE.md §Quality gates)
