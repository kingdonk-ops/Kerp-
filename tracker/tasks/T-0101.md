## Goal
One ltree tree whose levels are per-project configuration (ADR 0003 as amended): `oe_asset_level_def` carries the level roles; `oe_asset_node` keeps ltree `tree_path` NOT NULL + GiST, `parent_id` as source of truth, read-only `display_path`, subtree move in one ltree statement (diff §2.2). Work anchors to a work-anchor node — at most one per root-to-leaf path, never nested; no BOQ anchor.

## Acceptance criteria
- [x] `oe_asset_level_def` with `key`, `depth`, `allowed_parent_keys`, `label_key`, `roles`, `code_pattern`, `code_uniqueness`, `field_schema_id`, `display_code_template`; unique `(project_id, key)`; `roles` limited to `grouping`, `physical`, `work_anchor`, `inspection_anchor`, `progress_unit`, `schedule_link`; a key in use cannot be changed (asset-and-tagging.md §oe_asset_level_def)
- [x] `oe_asset_node.level_def_id` FK; create and move reject a parent whose level key is not in the child level's `allowed_parent_keys` (§oe_asset_node)
- [x] `tree_path ltree NOT NULL` with a GiST index; `CREATE EXTENSION ltree` in the migration
- [x] `parent_id` is the relational source of truth; `POST /assets/nodes/{id}/move` updates the whole subtree in a single ltree statement and writes old/new path to the audit ledger (§Restructure with history)
- [x] `display_path text` maintained read-only (breadcrumb only; never queried against)
- [x] PostGIS `spatial_location` (PointZ, EPSG:4326), `custom_fields jsonb`, `code` (text), computed `display_code`, `progress_unit` columns (`budget_qty`, `uom`, `budget_hours`, `earned_qty`) and lineage columns (`status`, `superseded_by`, `derived_from`; operations in T-0134) present
- [x] Anchor invariant enforced on create and move: a work-anchor node may not have a work-anchor ancestor or descendant (never nested, at most one per root-to-leaf path); a path with no work anchor is allowed (TD-113 decision); tested with two breakdown templates side by side in one project (remediation Site/Asset/RSW and CUI Scope/Job Package/Line) (§Anchor invariants)
- [x] Seam for booking modules: `asset_management.service.work_anchor_for(node_id)` returns the work-anchor node on the node's root-to-leaf path (ancestor-or-self) and raises a `NoWorkAnchor` domain error, mapped to 422 by routers, when the path has none; tested on paths with and without a work anchor in both packs (TD-113; callers listed in TD-125)
- [x] Code uniqueness enforced per the level's `code_uniqueness` (`per_parent`, `per_level`, `per_project`) — a duplicate is rejected (409) in each mode; `code_pattern` validated; codes like `101.1`, `SI-001` stored as text unchanged
- [x] No BOQ anchor: no BOQ column or FK exists on node or level def (test)
- [x] Both tables use `BaseRecordMixin` and have a project-scoped RLS policy
- [x] `asset_management` `README.md` and docs updated
- [x] All quality gates green (see CLAUDE.md §Quality gates)

  - **Paths**: `/api/v1/asset-management/projects/{project_id}/level-defs|nodes|nodes/{id}/move|nodes/{id}/work-anchor` (loader prefix + project in the path), not `/assets/...` (TD-477). Reads need `V`, node create `C`, move `E`, level defs `admin`.
  - **Tree path**: one ltree label per node = the node id (`uuid.hex`), so paths never depend on free-text codes; `display_path` is the breadcrumb of codes. A move is one `UPDATE` over the subtree (`new || subpath(tree_path, nlevel(old))`); SQLite (fast suite) uses the equivalent text-prefix forms.
  - **Concurrency**: every tree mutation (node create / move, level def create / update) takes a per-project `pg_advisory_xact_lock` first and re-reads what it checks, so the anchor invariant, code uniqueness, the allowed-parent rule and the in-use freeze hold under concurrent edits (PostgreSQL tests make a second writer wait and then fail). Relies on READ COMMITTED.
  - **Level template**: strict layering (depth 0 <=> no parents; a parent's depth is smaller; no self-nesting); once nodes use a level its key, depth, code_uniqueness and `work_anchor` role are frozen and `allowed_parent_keys` only grows (TD-478).
  - **Code uniqueness**: `per_parent` / `per_level` within the level, `per_project` across every level both ways; a partial unique index on `(project_id, code_scope_key, code)` backs same-scope duplicates, the cross-level half is service-only under the lock (TD-479). `code_pattern` is an RE2 regex for validation; generation is undefined (TD-480).
  - **Columns** the spec does not name or type (`name`, `planned_start` / `planned_finish`, NUMERIC(18,4), lineage as id lists): TD-481. External keys and planned dates exist as columns but this API does not write them.
  - `run_checks` is not called: these are hard structural invariants (ADR 0003), not configurable verification rules.
  - "Visible is not mine": every query filters the session's bound project explicitly; another project's node or level id is 404 in a path, 422 in a body (tests with an allowed-list session and a non-member System admin session, which ADR 0016 lets read and write every project).
