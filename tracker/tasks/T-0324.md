## Goal
The inspection template settings of the product-owner decisions (user, 2026-11-21; quality-and-inspection.md §Template settings): area (= `category`, plain labels, `health_safety` added), the optional issue category, the **formal** tick (informal = record-only, submit is final), the **audit** tick with scope, presets for "New template", and the locked-setting rule. Backend only; the Templates menu is T-0328, linked issue types T-0327.

## Acceptance criteria
- [ ] `category` accepts `health_safety` (additive); `GET /api/v1/inspections/template-areas` returns every area with its i18n label key (Quality (QA/ITP), Pre-start, Equipment check, Repair / fault, Health & Safety, General); labels are never hard-coded in the API
- [ ] Template revisions gain `issue_category` (optional key validated through `issues.service` against the active issue category list, which also holds non-discipline categories such as vehicle, equipment, pre-start, general; 422 otherwise), `is_formal` (bool, default true), `is_audit` (bool, default false) and `audit_scope` (`internal | external`, required when `is_audit`, else NULL; 422); all part of the canonical revision hash (test: changing any of them makes a new revision)
- [ ] `kind = itp` revisions and templates attached to an ITP line are always formal: `is_formal = false` on them → 422; attaching an informal template to an ITP line → 422 (tests)
- [ ] Presets: `GET /api/v1/inspections/template-presets` lists QA inspection, H&S check, Pre-start, Equipment check, Repair/fault, Internal audit, External audit with the settings of the spec table; `POST` of a new template with `preset` pre-sets area, formal and audit, and any explicit value in the payload wins (tests per preset)
- [ ] Locked settings: a draft revision that changes area, `is_formal`, `is_audit` or `audit_scope` against the latest published revision can be published only by the project's QA authority (`qa_reviewer_persona`) or PER-09 (PER-13 for a tenant-library template); others 403; existing records keep their pinned revision and its settings (test)
- [ ] Informal records: submit is final — the review step is skipped and the record moves straight to `INSPECTED_PASSED` / `INSPECTED_FAILED` from the proposed result, still signed (T-0119) and through `run_checks(context, "inspection.submit")`; no return, no QA verification queue item; `record.is_formal` is in the rule context (tests)
- [ ] The inspections service and `GET /api/v1/inspections` filter by `is_formal`, `is_audit`, `audit_scope`, `issue_category`; the service's progress/KPI helpers default to formal records only (consumers T-0251 tiles toggle, QMS KPIs); `inspections.service.mdr_collectable(scope)` applies the documents-and-mdr.md collection rule (formal `qa_itp` records of the scope; formal project-level records only with a location inside the scope; never internal-audit or informal records) for E-05-05 (tests per case); documented in the module README
- [ ] Records copy `is_formal`, `is_audit`, `audit_scope` and `issue_category` from the pinned revision; they cannot be changed on the record
- [ ] Settings are copied with client packs (T-0108)
- [ ] Module `README.md` and docs updated
- [ ] All quality gates green (see CLAUDE.md §Quality gates)
