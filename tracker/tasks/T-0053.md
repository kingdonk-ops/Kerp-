## Goal
The invite link in the SPA (diff §4.1 Invites): join confirmation for signed-in users, token carried through sign-in for everyone else, then straight into the project.

## Acceptance criteria
- [ ] Route `/invite` reads the token from the URL fragment (`/invite#<token>`), removes it from the address bar and sends it only in POST bodies; the route is served with `Referrer-Policy: no-referrer`. Signed in → preview (T-0052) and a one-click **"Join project"** confirmation; accepting opens the project and makes it the remembered project (T-0042)
- [ ] Not signed in → the sign-in screen with the token kept only for this flow (memory / `sessionStorage`, cleared after use or failure, never in `localStorage` or logs) and passed as `invite_token` to password login, the magic-link request and the SSO start (T-0055); on `joined_project_id` the app opens that project and skips the lobby
- [ ] The sign-in screen reached from an invite is the normal one (T-0055: "Sign in with Microsoft" primary when enabled, password secondary); the magic-link request is offered too, but only PER-14 invites get a link (server-side, neutral response; T-0052, T-0057), so the screen tells the user to use their password (or Microsoft, company staff only) if no e-mail arrives. A brand-new invitee without credentials gets the "Create your password" / "Send me an e-mail to set my password" screens of T-0078 instead of the sign-in form (diff §4.1; externals never use SSO)
- [ ] Wrong user, expired, revoked or used invites show a neutral message with a link to the lobby (and sign-out for the wrong-user case)
- [ ] Pending invites panel on the project's members screen (PER-09 of the project or System admin; T-0026 owns the screen, this task adds the panel): lists pending and expired invites (e-mail, persona(s), expiry, last sent) with **Resend** and Revoke (T-0052); Resend asks for confirmation ("the previous link stops working"), then shows the new copyable link once (`invite_token` only) and states that a new e-mail was sent; a 429 shows when re-sending is possible again; accepted and revoked invites offer no Resend
- [ ] All strings through `t()`; component tests (including Resend: confirmation, new link shown once, 429 message) and one e2e journey (PER-09 creates an invite → an existing user follows the link and signs in → lands in the project; the brand-new external journey with first-password set is T-0078's), synthetic data only
- [ ] Module `README.md` and docs updated
- [ ] All quality gates green (see CLAUDE.md §Quality gates)
