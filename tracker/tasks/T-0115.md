## Goal
The Request for Inspection (RFI) record and its first half of the workflow (quality-and-inspection.md §`inspection_requests` 1–8, 12, 13): a request with 1..N slots, multi-anchor (ADR 0003 §2), linked to ITP lines and ITRs, drafted, issued with an RFI no. and notice check, and cancelled. The lifecycle after issue (confirm, reschedule, outcomes, witness check) is T-0333; delays T-0334; notifications T-0335; PDF T-0336; calendar T-0337/T-0339; screens T-0338.

## Acceptance criteria
- [ ] Module `inspection_requests` with tables `oe_inspection_requests_request`, `_slot`, `_slot_inspection`, `_slot_party`, `_comment`, `_event`, `_discipline`, `_counter` and `oe_inspections_request_anchor(request_id, slot_id, node_id | item_id)` (CHECK exactly one of `node_id`/`item_id`) with the columns of §2; every table `BaseRecordMixin` + project RLS; a request of another project → 404 (test)
- [ ] Draft API under `/api/v1/projects/{project_id}/inspection-requests`: create/read/update a draft request, add/edit/remove slots; more than the discipline's `max_slots` → 422; a slot links ≥ 1 `qa_itp` inspection record (other category → 422, other project → 404, via `inspections.service`); an inspection already on a live slot → 409 `INSPECTION_ALREADY_REQUESTED` (tests)
- [ ] Slot anchors = the linked records' anchors plus optional nodes/Items inside the subtree of one of them; an extra anchor outside → 422 (test); anchors resolved through `asset_management.service` only
- [ ] Party rows defaulted from the linked ITP line(s) through `qms.service`: strongest point per party across several lines (test with two lines, H beats W); a manual point needs a reason and returns the non-blocking finding `POINT_DIFFERS_FROM_ITP` when it differs from the ITP (test)
- [ ] Discipline defaults: code-declared `M` / `C` / `CV` with the titles, inspection types, location labels and `max_slots` 4 of §10.2, copied to the project on first use and read through `inspection_requests.service` (editing is T-0340)
- [ ] Issue (request-level) runs `run_checks(context, "inspection_request.issue")`: every slot has a type, a future `scheduled_start` (else 422) and linked records in `PENDING` or `RE_INSPECT` (else 409 `INSPECTION_NOT_REQUESTABLE`); all draft slots → `requested`
- [ ] RFI numbering (§8): module-owned project setting `inspection_request.number_pattern` (default `{project}-RFI-{discipline}-{seq:4}`) with whitelisted placeholders (unknown placeholder refused on save, test); a pattern must contain exactly one `{seq:N}` and, when `counter_scope = discipline`, `{discipline}` — 422 `NUMBER_PATTERN_INVALID` for a pattern without `{seq}` or with two (test), and for `discipline` scope with a pattern lacking `{discipline}` both on pattern save and on scope change (two tests); counter key `rfi | rfi:<discipline>`; module-owned counter `oe_inspection_requests_counter` only (no T-0108 dependency); `counter_scope` `project` (default: test: an `M` then a `C` request give `…-RFI-M-0001`, `…-RFI-C-0002`) or `discipline` (test: `…-RFI-M-0001`, `…-RFI-C-0001`), changeable only before the first issue (409 test); row-locked allocation in the issue transaction: two concurrent issues get distinct consecutive numbers and a rolled-back issue uses none (tests); a new counter row starts at `last_value = seq_start − 1` (test: `seq_start = 57` → first number `…-0057`); raising `seq_start` above every allocated number sets `last_value = seq_start − 1` under the row lock (test: after `…-0003`, `seq_start = 100` → next `…-0100`), a value not above the last allocated → 422 (test); drafts have no number; a cancelled request keeps its number and it is never reused (test)
- [ ] Notice (§6): `required_notice_hours`, `notice_given_at`, `notice_met` stored at issue from `inspection_request.min_notice_hours` (default 24); short notice returns the `NOTICE_SHORT` warning and still issues (test); a project rule copy that makes it blocking blocks (test)
- [ ] Linked records move `PENDING | RE_INSPECT → INSPECTION_REQUESTED` through `inspections.service` (this task adds `RE_INSPECT → INSPECTION_REQUESTED` to the lifecycle), `prior_status` saved, `planned_start` set to the slot date in the project time zone (tests)
- [ ] Cancel (slot or whole request): reason required unless draft; linked records still `INSPECTION_REQUESTED` and on no other live slot return to `prior_status`, records that moved on are untouched (tests); a draft request may be soft-deleted
- [ ] Derived request status `draft | open | closed | cancelled` as §2 (tests over slot combinations)
- [ ] Permissions for these actions per §12: PER-03/PER-04/PER-06/PER-07 with every anchor in their scope may create/issue; PER-15, PER-09 and a `system_admin` without one of those personas get 403 (tests); cancel by requester or PER-06 only
- [ ] Every action writes an `oe_inspection_requests_event` row (UPDATE/DELETE refused — test) and, except draft edits, a T-0006 ledger entry (chain `inspection_request:<id>`)
- [ ] `inspection_requests.service.rfi_refs_for_inspection(inspection_id)` returns the RFI nos. linking a record (for the ITR header/PDF, T-0158)
- [ ] **Product-owner gate:** this task is not set `done` until TD-045 carries a dated product-owner note that the spec was checked against a client RFI sample (or an explicit product-owner waiver of that check); the coordinator checks TD-045 before marking it done (decision 2026-11-16)
