## Goal
Make the delegation of T-0292 effective in the Phase-1 flows that address a named person (quality-and-inspection.md §Delegation of authority).

## Acceptance criteria
- [ ] Notifications: inspection-request call-outs for hold/witness points (T-0115), verification-item assignment (T-0181) and the T-0182 reminders and escalations addressed to a user also go to that user's active delegates for the matching kind (in-app + e-mail, link + project code/name only); an escalation whose target user has an active delegate notifies both
- [ ] At delegation start the delegate gets one summary notification of the delegator's open items of those kinds (TD-434 default: already-assigned items are in scope)
- [ ] Acting on behalf: verification approve/reject (T-0181) and named-party H/W sign-off accept the delegate of the assignee; the action still requires the delegate's own qualified persona on the project, site scope and valid credentials (TD-099/TD-100) and passes the same `run_checks`; failing that → 403 as for any user (test: a delegate without PER-06 cannot approve)
- [ ] SoD unchanged: a delegate cannot approve or sign work they performed or submitted, and `allow_self_approval` is evaluated for the delegate (tests); no system_admin authority is added (ADR 0016)
- [ ] The sign-off ledger entry is the delegate's (`created_by` = delegate) with `attestation.on_behalf_of_user_id` and `delegation_id`; the PDF block of T-0291 prints "Signed by X on behalf of Y" (test on the rendered text)
- [ ] Delegator and delegate both may act; the first conditional update wins and the second gets 409 (test)
- [ ] Calls go through the qms, inspection_requests and signing services only
- [ ] Module `README.md` and docs updated
- [ ] All quality gates green (see CLAUDE.md §Quality gates)
