## Goal
The user-facing half of T-0289: every formal sign-off shows the intent statement and asks for re-authentication before it is sent (quality-and-inspection.md §Signing attestation).

## Acceptance criteria
- [ ] One reusable `SignCeremony` component: shows the rendered intent statement (record summary, kind, signer name, persona, "on behalf of" when acting as a delegate), an explicit confirm checkbox, then the re-auth prompt; nothing is sent before both
- [ ] Online: signing PIN (default) or password; calls `/signing/reauth` then the consumer's sign-off with the grant; `REAUTH_REQUIRED` and `INTENT_STATEMENT_OUTDATED` handled (re-render, ask again)
- [ ] Android offline: device-PIN re-entry against the keystore even while the app is unlocked; wrong PINs count toward the local lockout of diff §4.2; the queued mutation carries the attestation fields of T-0289
- [ ] Account settings: set and reset the signing PIN for every user (fresh sign-in within 15 minutes required, else a prompt to sign in again)
- [ ] Every string through `t()` (en-AU + one other locale fixture); glove-size targets and high-contrast tokens (T-0046)
- [ ] Component and e2e tests: online approve with signing PIN, password, wrong PIN lockout message, offline H/W sign-off queued with attestation
- [ ] Module `README.md` and docs updated
- [ ] All quality gates green (see CLAUDE.md §Quality gates)
