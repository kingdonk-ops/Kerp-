## Goal
For Pilot-0 there is no template designer (E-01-03 comes after the pilot), so we author the starting issue templates and seed them as tenant defaults (user, 2026-11-21; issues.md §2).

## Acceptance criteria
- [ ] Tenant-default seed (versioned YAML in the `issues` module, synthetic wording only) with published punch and NCR templates for the categories `painting`, `blasting`, `civil`, `mechanical`, `welding` (10 templates) and internal audit finding templates for punch and NCR in their own category `audit` (`default_origin = internal_audit`, `internal` + `excluded`)
- [ ] Every seeded template validates against T-0311 (type, category, flag defaults, a step for every section; NCR templates have containment, disposition, root-cause with an optional 5-whys section, corrective-action and effectiveness sections); the discipline punch templates default `mdr_effect = blocks` (TD-445); the `audit` templates are `excluded` by design
- [ ] Seeding is idempotent (re-running changes nothing; a changed seed file creates a new library revision offered to projects, never forced)
- [ ] A new project gets project copies and a default template per category × type for these templates; the audit templates are the defaults for (`audit`, punch) and (`audit`, ncr), and the system `general` templates stay the defaults for (`general`, punch/ncr) (test)
- [ ] A plain `general` punch or NCR raise pre-selects the `general` template, never the audit one (test)
- [ ] The tenant defaults are seeded through the normal tenant provisioning path (the same path that seeds the system-default rule sets and categories), so every new tenant gets them too; not a one-off script (test with a fresh tenant)
- [ ] Module `README.md` and docs updated
- [ ] All quality gates green (see CLAUDE.md §Quality gates)
