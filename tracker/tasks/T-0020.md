  - Spec-gap TD-244: added nullable `team_id` (required iff `visibility=team`); `is_default` = owner's default on a private view, project default (PER-09) on a project view; other visibilities cannot be defaults.
  - Teams (T-0013) not built: the router passes no team ids, so team views are owner-only and only PER-09 can create one; `team_id` not validated (TD-242). Portal views: owner + PER-09 until the portal layout exists (TD-243).
  - Decision: private views for any member (`V`); sharing needs `C`; shared views edited by owner or PER-09; project default set/unset/deleted only by PER-09.
  - Missing columns: registers declare their column ids via `service.register_catalogue` (seam for E-01-01); `present` flags `columns[].missing` and `missing_columns`. No catalogue: nothing flagged (TD-246).
  - Default uniqueness is service-enforced only (TD-245). View changes are not written to the audit chain (user preferences, not records of work).
  - Filter AST: structure, op names and per-op value shapes are validated; column/op whitelisting is the filter compiler's (E-01-01). Conditional-format conditions are compiled as CEL on save.
- 2026-11-13 (implementer, review round 1): a `PATCH` that changes `visibility` without `is_default` now drops the default flag, so a personal default never silently becomes the project default (or the reverse). Stored configs that stop validating would 500 on load: TD-247.
