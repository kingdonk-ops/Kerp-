## Goal
Close the up-to-1-second window after a password change where a token with the same truncated `iat` still passes (PR #31 review).

## Acceptance criteria
- [ ] Exact behaviour (no fail-closed window): a per-user token generation counter (or a sub-second issued-at claim) decides validity, so a token issued before the change is rejected and a token issued after it is accepted, even within the same second
- [ ] Test: token issued before the change, in the same second, is rejected
- [ ] Test: token issued after the change, in the same second (e.g. login straight after `set_password`), is accepted
- [ ] Auth README documents the mechanism
