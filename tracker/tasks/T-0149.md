## Goal
TD-162 (client side): the inspector chooses what to take offline, sees how big it is, and the client pulls and purges through the client storage contract (diff §6.2, §6.4).

## Acceptance criteria
- [ ] Screen lists download candidates with status, anchor path, due date, size and a downloaded marker; the inspector adds and removes picks; the total selected size and the device storage usage (`MediaStore` usage) are shown
- [ ] The pull loop requests pages until `has_more` is false and applies upserts and removes through `RecordStore` / `MediaStore` only (no direct Dexie or SQLite import)
- [ ] On a `remove` delta, or a manual removal, local records and media of the pick are deleted only when the outbox has no pending mutation for them; otherwise the pick shows "waiting to sync" and is purged after the outbox drains (test with a fake outbox)
- [ ] Media of picked inspections are downloaded with the records; a failed media download is retried and shown, never silently skipped
- [ ] Field screen meets the 48 dp target and high-contrast tokens (T-0046); all strings through `t()`
- [ ] Contract tests run against the Dexie adapter; the same flows run against the SQLCipher adapter when T-0142 is present in CI
- [ ] `frontend/README.md` and sync docs updated
- [ ] All quality gates green (see CLAUDE.md §Quality gates)
