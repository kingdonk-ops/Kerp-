## Goal
Implement ADR 0005 (TD-075 must be accepted first): `oe_field_checkout` lease (user, device, expiry, per-record base_revision, pinned template_revision_id), checkout/release/force-release endpoints, 409 on office edits to field-owned values of a checked-out record, and the end-to-end contract proving that a P6 re-import during a checkout and the tablet's later sync both land without either overwriting the other (spec §8, §11 tests 10–15).

## Acceptance criteria
- [ ] `oe_field_checkout` with BaseRecordMixin + project RLS; one active checkout per record; `POST /sync/checkouts`, `DELETE /sync/checkouts/{id}` (release, supervisor force-release)
- [ ] Office write to a field-owned value of a checked-out record → 409 naming the holder
- [ ] Test 10: checkout → P6 re-import changes dates/name → tablet syncs two answers + one photo → server holds the new P6 values **and** the tablet values; no other field changed
- [ ] Test 11: tablet path owned by `p6` → `ERR_FIELD_NOT_OWNED` for that path, rest applied
- [ ] Test 12: activity removed during checkout → tablet work accepted, node flagged for review, nothing deleted
- [ ] Test 13: force-release + office edit, then stale tablet sync → server value kept, tablet value in `sync_conflict_log`, review item raised
- [ ] Test 14: signed-off inspection not changed by a later tablet sync; Test 15: `client_op_id` replay is a no-op
- [ ] All quality gates green (see CLAUDE.md §Quality gates)
