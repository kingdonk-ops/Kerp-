## Goal
When scope or tasks change, QA learns whether the active ITPs still cover the work, with an AI gap analysis and a proposed patch that changes nothing on its own (quality-and-inspection.md §ITP authoring, assignment and propagation *Alignment watchdog*; change-of-scope.md §5).

## Acceptance criteria
- [ ] AI governance (CLAUDE.md §6): every AI call runs as a SAQ job (heavy client libraries imported lazily); the provider is the deployment's configured AI provider (OpenAI, Anthropic Claude or a self-hosted Hugging Face model, hosted in an Australian region, TD-078; read-only deployment configuration, diff §4.7 / TD-398; `none` → 409 `AI_PROVIDER_NOT_CONFIGURED`); AI output is stored with `source="ai"` as a proposal and changes nothing until a human confirms; prompts and responses are never logged in full (hash + token counts only); synthetic fixtures and a fake provider in tests
- [ ] `oe_qms_itp_drift_review` (`BaseRecordMixin` + project RLS): `trigger_event_type`, `trigger_ref_id`, `anchor_node_id`, `itp_instance_id` (nullable), `alignment_status aligned | misaligned | missing_itp | obsolete_steps`, `ai_summary`, `proposed_itp_patch` JSONB (`source="ai"`), `status pending_review | dismissed | manual_updated | ai_patch_approved`, `reviewed_by`, `reviewed_at`, `review_notes`
- [ ] Idempotent outbox handlers (T-0285 events) enqueue a `batch` job per affected anchor (de-duplicated per anchor within a 10-minute window, planner default); the job first applies the deterministic `itp_assignment` rules (T-0188) and only then asks the AI provider to compare the changed scope/tasks with the active instance's lines and the published templates
- [ ] Patch schema: add lines (from published templates only), retire lines, change intervention points of **unstarted** lines only (TD-429); a proposal touching a started or signed line is rejected by the validator before it is stored
- [ ] `aligned` → stored, no notification; otherwise a high-priority in-app notification (T-0019) and an e-mail (registered core-mail template `qms.itp_alignment_review`, overridable through T-0227) to the reviewers: project setting, default PER-06 and PER-02
- [ ] No ITP changes in this task: nothing is applied until a human acts (T-0286)
- [ ] Tests: an implemented scope change and a P6 commit adding a new work type on an anchor create a review; duplicate events create one review; fake provider
- [ ] Module `README.md` and docs updated
- [ ] All quality gates green (see CLAUDE.md §Quality gates)
