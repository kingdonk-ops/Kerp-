## Goal
Extend the follow-ups and tagout gate of T-0257 to the equipment linked to a project-level inspection (user, 2026-11-21: equipment is a link, ADR 0003 amendment 2026-11-21; diff §5 *Out of service and tagout*). Split from T-0257 in PR #139 review round 1. No longer blocked: TD-411 is resolved.

## Acceptance criteria
- [ ] Additive nullable `equipment_id` on `oe_inspections_follow_up` (no FK across modules); exactly one of `anchor_node_id` / `anchor_item_id` / `equipment_id` (422 otherwise, tests)
- [ ] `create_action_task` on an inspection with an equipment link (T-0250) creates the follow-up with that link's `equipment_id`; with `tagout_confirmation` + `blocks_return_to_service`, the equipment is set `out_of_service` in the same transaction through the equipment service (whitelisted restrict call of T-0180)
- [ ] The inspections module registers a check provider used by the `equipment.activate` rule set (T-0260): equipment with an open blocking follow-up cannot return to `active` (422 from `run_checks`, test); closing it lets the gate pass (test)
- [ ] A critical defect on a pre-start: status `out_of_service` at once, supervisor notified, tagout follow-up created (integration test)

- [ ] Every step is an action-log row and a ledger entry (`source = "automation"` for automatic steps, the user's for confirmations)
