## Goal
Prove the Pilot-0 definition of usable end to end (DEVELOPMENT-PLAN §Milestones, Pilot-0).

## Acceptance criteria
- [ ] The inspector picks an assigned inspection for download, goes offline, finds the Item by a (fake) scan, answers, takes and annotates a photo, signs and submits; back online the outbox drains and the inspection is `SUBMITTED`
- [ ] The journey also records an audio note and scans a barcode answer; the client co-signs offline by the QR exchange from their own app (T-0175), and in a second run with a provisional wet signature that the client confirms in their account (T-0176) before the reviewer can approve; the device is handed back with the inspector's PIN
- [ ] Submit stays blocked while an upload is pending
- [ ] The reviewer returns it with a reason and an answer comment; the inspector sees both, edits and resubmits; the reviewer approves
- [ ] The reviewer downloads the PDF and a batch export containing it; the dashboard tiles reflect the approved inspection
- [ ] Runs in CI on the web build; the Android emulator run is documented
- [ ] `e2e/README.md` updated
- [ ] With the device wall clock set wrong while offline, the approved inspection shows the true submit time (`MONOTONIC_RECONSTRUCTED`); a checkout with skew above the setting is blocked
- [ ] All quality gates green (see CLAUDE.md §Quality gates)
