## Goal
Cut avoidable database round trips (audit items 18 and 19): returning a connection to the pool costs about 9 round trips, the rule-drift report runs 2 queries per project rule set without paging, and the saved-views list loads every private view and runs 2 queries plus a column-catalogue build per team view.

## Acceptance criteria
- [x] Pool return (`core/tenancy/rls.py`): the seven session settings are reset in one `SELECT set_config('app.current_tenant_id', '', false), …` followed by one commit; policies already treat an empty value as unset. Tests: after return, every setting is empty and a reused connection sees no tenant (PostgreSQL); a statement counter asserts the reset is one statement plus the commit
- [x] Drift report (`validation/upgrades.py`): tenant defaults loaded once, project rules fetched with one `IN (...)` query per page; a statement-count test asserts the query count does not grow with the number of projects
- [x] Drift report paging is additive: optional `limit` (default and max documented) and `offset`/cursor query parameters; without them the response stays the current `list[DriftEntryRead]` shape (backward compatible); the next page is signalled without changing the body shape (e.g. a header), or, if the shape must change, the frontend API client is regenerated (`npm run gen:api`) and committed. Test for paging over many projects
- [x] Saved views list (`saved_views/service.py`): private views filtered in SQL (owner = caller), team ids and the column catalogue computed once per list request; statement-count test that the query count does not grow with the number of views; TD-387 resolved
- [x] TD-289 resolved
- [x] Module/README.md and docs updated
- [x] All quality gates green (see CLAUDE.md §Quality gates)

## Notes
- 2026-11-21 (planner): Created from the 2026-11-21 codebase audit; one PR with T-0341..T-0349. Touches `core/tenancy`, `validation` and `saved_views`. The frontend has no drift-report consumer today, but adding query parameters changes the OpenAPI schema, so regenerate `frontend/src/api/` if `gen:api` output changes.
- 2026-11-22 (implementer): Pool return: `rls.reset_connection_settings` sends `rls.POOL_RESET_SQL` (one `SELECT set_config(name, '', false)` for all seven settings) and commits. On psycopg 3 that is three round trips (the driver's implicit `BEGIN`, the statement, `COMMIT`) instead of nine; `tests/test_pool_reset.py` proves it with libpq's protocol trace on PostgreSQL, with a fake driver everywhere, and shows a reused connection (same backend pid) has every setting empty and reads no scratch rows under RLS. Switching the connection to autocommit for the reset would save the `BEGIN`/`COMMIT` too; not done, the criterion asks for statement + commit.
- 2026-11-22 (implementer): Drift report pages by whole projects in project id order (`upgrades.drift_report_page`, `DriftPage`); four queries per page however many projects. `GET /drift-report` takes `limit` (default 100, max 500 projects) and `offset` (default 0); the body stays `list[DriftEntryRead]` and `X-Next-Offset` carries the next offset. Decision: the default limit applies when `limit` is absent (bounded by default, as the audit asks), so a tenant with more than 100 readable projects now needs a second request; there is no consumer yet. `X-Next-Offset` is not in the native-app CORS `expose_headers` (the drift report is a web admin screen, same origin). `gen:api` regenerated (`limit`/`offset` and the 422 response).
- 2026-11-22 (implementer): Saved views: `list_views` filters others' private views in SQL; `present_many` (used by the list endpoint; `present` delegates to it) builds the catalogue once per register and reads team links and linked teams once per list. TD-289 and TD-387 resolved. TD-529 (unbounded list endpoints) and TD-530 (pool size settings) stay open: not trivially in scope.
