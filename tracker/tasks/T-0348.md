## Goal
Cut avoidable database round trips (audit items 18 and 19): returning a connection to the pool costs about 9 round trips, the rule-drift report runs 2 queries per project rule set without paging, and the saved-views list loads every private view and runs 2 queries plus a column-catalogue build per team view.

## Acceptance criteria
- [ ] Pool return (`core/tenancy/rls.py`): the seven session settings are reset in one `SELECT set_config('app.current_tenant_id', '', false), …` followed by one commit; policies already treat an empty value as unset. Tests: after return, every setting is empty and a reused connection sees no tenant (PostgreSQL); a statement counter asserts the reset is one statement plus the commit
- [ ] Drift report (`validation/upgrades.py`): tenant defaults loaded once, project rules fetched with one `IN (...)` query per page; a statement-count test asserts the query count does not grow with the number of projects
- [ ] Drift report paging is additive: optional `limit` (default and max documented) and `offset`/cursor query parameters; without them the response stays the current `list[DriftEntryRead]` shape (backward compatible); the next page is signalled without changing the body shape (e.g. a header), or, if the shape must change, the frontend API client is regenerated (`npm run gen:api`) and committed. Test for paging over many projects
- [ ] Saved views list (`saved_views/service.py`): private views filtered in SQL (owner = caller), team ids and the column catalogue computed once per list request; statement-count test that the query count does not grow with the number of views; TD-387 resolved
- [ ] TD-289 resolved
- [ ] Module/README.md and docs updated
- [ ] All quality gates green (see CLAUDE.md §Quality gates)
