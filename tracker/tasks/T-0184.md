## Goal
Extend the shelf life of an expiring or expired material batch with a justified, documented and QA-approved extension (materials-and-traceability.md §Shelf-life extension). Workflow half of the user's T-0184; the offline bundle is T-0268 and the MDR rule lives in E-05-05.

## Acceptance criteria
- [ ] `oe_material_shelf_life_extension` (`BaseRecordMixin` + project RLS): `material_batch_id`, `extension_seq`, `previous_expiry_date`, `proposed_expiry_date` (DB CHECK proposed > previous), `reason_notes` (non-blank, 422), `document_id` (a complete T-0016 upload, else 422), `issuer_kind` (`manufacturer | quality_engineer`), `requested_by_user_id`, `requested_at`, `status` (`pending_approval | approved | rejected`), `approved_by_user_id`, `approved_at`, `rejection_reason`; unique `(project_id, material_batch_id, extension_seq)`; index `(project_id, material_batch_id, status)`; one pending extension per batch (409)
- [ ] The batch record (from the E-03-03 breakdown, TD-421) keeps `original_use_by_date` immutable (update → 422, test) and `effective_use_by_date` changed only by an approved extension through the materials service
- [ ] "Extend shelf life" on an expiring or expired batch creates the pending extension and a T-0181 verification item with `target_kind = material_shelf_life_extension` (new target kind registered by this module's provider; notes and file side by side in the two-lane window T-0262)
- [ ] Routing: the project's QA reviewer persona (default PER-06); a PER-06 requester is routed to a PER-13 with access to the project (TD-422); the requester can never approve (403, test), whatever `allow_self_approval` says
- [ ] Approve: `effective_use_by_date = proposed_expiry_date`; batch passes the as-of-date eligibility again (materials provider of T-0139); readiness conflicts and expiry alerts re-evaluated through the compliance service (T-0183, T-0266; conflict resolved, test); ledger entry with original date, new date, document SHA-256, requester, approver
- [ ] Reject: mandatory reason, batch stays expired/blocked, requester notified (T-0019)
- [ ] Gate: an inspection selecting the batch evaluates `material.effective_use_by_date >= context.inspection_date` (CEL, server side through `run_checks`); an expired paint batch blocks acceptance of a coatings inspection until an extension is approved (test)
- [ ] Cross-module access only through `service.py` (qms, compliance, eligibility, inspections)
- [ ] QA approval of an extension is an attested formal sign-off: kind `shelf_life_extension_approve` registered with T-0289, approval refused without a valid signing grant (401 `REAUTH_REQUIRED`), the attestation stored in the sign-off ledger entry and printed with T-0291's renderer; a delegate (T-0292, kind `verification`) may approve only with their own QA persona and credentials (quality-and-inspection.md §Signing attestation, §Delegation of authority)
- [ ] Module `README.md` and docs updated
- [ ] All quality gates green (see CLAUDE.md §Quality gates)
