## Goal
System admins adjust the wording of automated e-mails without a redeploy while the §4.6 safety rules hold (diff §4.7 Automated templates).

## Acceptance criteria
- [ ] New core table `mail_template_override` (`BaseRecordMixin`, tenant RLS; an ADR in `docs/decisions/` (next free number) is written in this PR): template key, locale, revision, subject, intro, outro, action label, is_current; unique current row per (tenant, key, locale)
- [ ] `GET /api/v1/mail/templates`: every registered template with its declared placeholders, shipped text and current override; `system_admin` only (403 otherwise)
- [ ] `PUT .../templates/{key}/{locale}`: plain text only; only declared placeholders (`{user_name}`, `{project_code}`, ...) accepted (422 otherwise); HTML tags, URLs in place of the action link and the link secret placeholder are refused; new revision, audited
- [ ] Rendering uses the override when present, else the i18n catalogue; values still escaped, the action link still built by the renderer; next send uses the change (cache invalidated on write)
- [ ] `POST .../preview` renders with synthetic sample values; `POST .../test-send` sends only to the caller's own address (rate-limited); `DELETE .../{key}/{locale}` resets to the shipped default (revision kept)
- [ ] Test: every registered template still renders in `en-AU` with and without an override
- [ ] Module `README.md` and docs updated
- [ ] All quality gates green (see CLAUDE.md §Quality gates)
