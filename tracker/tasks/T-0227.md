## Goal
System admins adjust the wording of automated e-mails without a redeploy while the §4.6 safety rules hold (diff §4.7 Automated templates).

## Acceptance criteria
- [x] New core table `mail_template_override` (`BaseRecordMixin`, tenant RLS; an ADR in `docs/decisions/` (next free number) is written in this PR): template key, locale, revision, subject, intro, outro, action label, is_current; unique current row per (tenant, key, locale)
- [x] `GET /api/v1/mail/templates`: every registered template with its declared placeholders, shipped text and current override; `system_admin` only (403 otherwise)
- [x] `PUT .../templates/{key}/{locale}`: plain text only; only declared placeholders (`{user_name}`, `{project_code}`, ...) accepted (422 otherwise); HTML tags, URLs in place of the action link and the link secret placeholder are refused; new revision, audited
- [x] Rendering uses the override when present, else the i18n catalogue; values still escaped, the action link still built by the renderer; next send uses the change (cache invalidated on write)
- [x] `POST .../preview` renders with synthetic sample values; `POST .../test-send` sends only to the caller's own address (rate-limited); `DELETE .../{key}/{locale}` resets to the shipped default (revision kept)
- [x] Test: every registered template still renders in `en-AU` with and without an override
- [x] Module `README.md` and docs updated
- [x] (product intake 2026-11-21) A template marked required (sign-in, invite, password reset, RFI call-outs) cannot be saved with an empty subject or empty text blocks (422); each template declares its audience group and placeholder list for the editor (diff §4.7 'Editor details')
- [x] All quality gates green (see CLAUDE.md §Quality gates)

New `app/core/mail/overrides.py`; `render(..., override=)`; `deliver` reads the override in its own unit of work.
- Revision column is `version` (the AC's "revision"): `BaseRecordMixin.revision` is already the row's update counter. API field names: `subject`, `intro`, `outro`, `action_label`, `version`, `is_current`.
- "Cache invalidated on write": there is no cache. The worker reads the current override in the unit of work it opens per send anyway (one indexed query, locale chain), so the next send uses a save/reset at once in every API and worker process; an in-process cache could not be invalidated across processes without Redis pub/sub (ADR 0021 §4).
- Declared placeholders = the template's params + `{app_name}` (the catalogue already uses it). Refused: HTML (`<tag`, `<!`, `<?`), URLs (`scheme://`, `www.`, `mailto:`, `javascript:`, `vbscript:`), control characters, line breaks in subject/action label, the secret placeholder, any attribute/index/conversion/format spec (`{app_name.__class__}` would otherwise leak through `str.format`). Checked on save and again at send time (a stale override is skipped with a warning).
- Required/empty rule (reading of the intake item): subject and action label are never empty for any template; intro/outro may be empty only for a non-required template (the paragraph is left out). Required: `auth.magic_link`, `auth.password_reset`, `admin.project_invite` (one-line edit in `app/modules/admin/invites.py`). All current templates declare audience `deployment_wide`. To confirm: TD-596. RFI call-outs must register `required=True`: TD-598.
- Extras for the editor (T-0229): `GET .../{key}/{locale}/revisions`; `POST .../preview` takes an optional draft body (checked like a save, never stored). DELETE is idempotent (204). A concurrent save that loses the unique index answers 409.
- Test send: queued through `send_mail` to `principal.user.email` in the path locale with `sample_context` values (fake link secret), audited; limit 5 per 10 minutes per caller counted from the send log (e-mails the caller queued to itself), 429 + `Retry-After`. It counts in the ledger stats: TD-597.
- `tests/test_runtime_role_grants_pg.py` now also checks `kerp_app`'s privileges on `mail_template_override` (ADR 0019 default privileges from `0039`).
