## Goal
`oe_welder` + `oe_welder_qualification` registers. Qualification validity (range / expiry /
continuity) is answered by the stateless `eligibility` service (T-0118) — no private
qualification-validity table.

## Acceptance criteria
- [ ] `oe_welder` with `contact_id`→contacts, `stamp`, `employer_kind[staff|subcontractor]`, `subcontractor_contact_id`, `status` (contacts arrives in Phase 3 — see Notes + TD for the interim linkage default)
- [ ] `oe_welder_qualification` with `welder_id`, `wps_id`→`oe_wps_record`, `qualified_date`, `expiry_date`, `continuity_last_welded_at`, `qualified_range{positions,thickness,diameter,material}`, `test_type`, `certificate_document_id`→uploads, `status[valid|expired|suspended|revoked]`, `verified_by`, `verified_at`
- [ ] `eligibility` reads these qualifications and returns pass/fail + reason: an `expired`/`suspended`/`revoked` qualification, or a weld outside the `qualified_range`, is blocked; `eligibility` owns no tables
- [ ] Both tables use `BaseRecordMixin` and have a project-scoped RLS policy
- [ ] `wps` module `README.md` and docs updated
- [ ] All quality gates green (see CLAUDE.md §Quality gates)
