## Goal
Idempotent sync ledger keyed on client_op_id; immutable-approval protection; per-field three-way apply with field ownership and conflict log (ADR 0005, accepted; amends master spec §1.3/§4.3 LWW). LWW with conflict log remains only for office-owned text edited by two desktop users. The checkout lease and the end-to-end P6 contract are T-0133.

## Acceptance criteria
- [ ] Replay is idempotent on client_op_id (p6 spec §11 test 15)
- [ ] Signed-off step cannot be regressed offline; a change to a locked record is rejected with `ERR_CONFLICT_IMMUTABLE_QUALITY_RECORD` and logged (master spec §4.3 rule 1; p6 spec §8.3 rule 2)
- [ ] `push-mutations` accepts per-path `changes` (`path`, `base_hash`, `value`) and `collection_ops`; a whole-record payload from a tablet is rejected (ADR 0005 §3; p6 spec §8.2)
- [ ] Per changed path: owner not `field` → `ERR_FIELD_NOT_OWNED` for that path while the rest of the batch applies; server value hash equals `base_hash` → applied; server value changed → server value kept, tablet value written to `sync_conflict_log` and a review item raised (ADR 0005 §4; p6 spec §8.3)
- [ ] Paths not sent are never written; child-collection ops are additive, never array overwrites (p6 spec §8.3; master spec §4.3 rule 3)
- [ ] `base_revision` is stored on the envelope for idempotency and diagnostics and never rejects a batch on its own (ADR 0005 §5, refines TD-035)
- [ ] The field-ownership map (`p6` / `office` / `field`) is read from the field registry (T-0110), not hard-coded in the sync module (p6 spec §7)
- [ ] LWW with conflict log applies only to `office` text edited concurrently by two desktop users (master spec §1.3 rule 4)
- [ ] Tables use `BaseRecordMixin` and have a project-scoped RLS policy
- [ ] `sync` `README.md` and docs updated
- [ ] All quality gates green (see CLAUDE.md §Quality gates)
