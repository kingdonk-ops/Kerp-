## Goal
Replace the always-clean stub with a real malware scanner (TD-211) so infected uploads are rejected with a signature the quarantine monitor can show (diff §4.7).

Also (absorbed from T-0220): the System-console queue monitor — KERP's own endpoints for System admins showing queue depths, cron runs and failed jobs (without payloads), with retry/abort (diff §4.7). Both halves are small worker-side backends for the System console; they touch disjoint modules (uploads, jobs).

## Acceptance criteria
- [x] `ClamdScanner` implements the T-0016 `Scanner` protocol over the clamd TCP/Unix socket (`INSTREAM`, chunked, size limit honoured); selected by deployment configuration (`KERP_UPLOAD_SCANNER=clamd`, address from config, nothing hard-coded); the stub stays for dev/tests and T-0213's production refusal still applies
- [x] A detection rejects the file with reason `infected` and stores the signature name in a new nullable column on `oe_uploads_file` (additive migration; codes not text, signature as returned by clamd, ≤ 200 chars)
- [x] Scanner unavailable or timeout: the file stays `verifying` and the job retries with back-off (never `available` unscanned); after the T-0215 stuck limit it becomes `rejected` / `verify_failed`
- [x] `ping()` on the scanner (clamd `PING` → `PONG`) for the health probe of T-0219; no host or port in any API answer
- [x] docker-compose gets a clamd service for development; tests use a fake clamd socket server (EICAR-style synthetic signature string, no real malware in the repo)
- [x] Module `README.md` and docs updated
- [x] Every endpoint is `system_admin` only: any other caller, PER-09 included, gets 403 (test per endpoint, including a PER-09 of every project) — from T-0220
- [x] `GET /api/v1/admin/system/queues`: per queue (`interactive`, `batch`) queued, active, scheduled and failed counts and the oldest queued age — from T-0220
- [x] Cron jobs (on the batch worker; no separate cron queue) listed with last run, next run and last outcome — from T-0220
- [x] `GET /api/v1/admin/system/queues/failed`: kind, queue, project code, attempts, error class and a message truncated to 500 characters; **never job kwargs, payloads or Redis mail payloads** (test with a job carrying a synthetic secret) — from T-0220
- [x] `POST .../failed/{job_id}/retry` and `POST .../{job_id}/abort` (queued or active), each audited with actor and job kind; unknown id 404 — from T-0220
- [x] SAQ's own web UI is not mounted (it has no KERP auth) — from T-0220
- [x] All quality gates green (see CLAUDE.md §Quality gates)
