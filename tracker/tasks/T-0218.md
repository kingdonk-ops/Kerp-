## Goal
Replace the always-clean stub with a real malware scanner (TD-211) so infected uploads are rejected with a signature the quarantine monitor can show (diff §4.7).

## Acceptance criteria
- [ ] `ClamdScanner` implements the T-0016 `Scanner` protocol over the clamd TCP/Unix socket (`INSTREAM`, chunked, size limit honoured); selected by deployment configuration (`KERP_UPLOAD_SCANNER=clamd`, address from config, nothing hard-coded); the stub stays for dev/tests and T-0213's production refusal still applies
- [ ] A detection rejects the file with reason `infected` and stores the signature name in a new nullable column on `oe_uploads_file` (additive migration; codes not text, signature as returned by clamd, ≤ 200 chars)
- [ ] Scanner unavailable or timeout: the file stays `verifying` and the job retries with back-off (never `available` unscanned); after the T-0215 stuck limit it becomes `rejected` / `verify_failed`
- [ ] `ping()` on the scanner (clamd `PING` → `PONG`) for the health probe of T-0219; no host or port in any API answer
- [ ] docker-compose gets a clamd service for development; tests use a fake clamd socket server (EICAR-style synthetic signature string, no real malware in the repo)
- [ ] Module `README.md` and docs updated
- [ ] All quality gates green (see CLAUDE.md §Quality gates)
