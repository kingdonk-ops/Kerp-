## Goal
ADR 0004 §4 and §6: when a default changes, projects are offered the change and accept it rule by
rule; admins can test a rule before enabling it.

## Acceptance criteria
- [ ] When a system or tenant default set gains a new version, `GET .../rule-sets/{key}/updates` on a project returns a per-rule diff (new, changed, removed) against the project copy; nothing is applied automatically (ADR 0004 §4)
- [ ] Accepting one rule from the diff applies only that rule, versions it and audit-ledgers it; a rule the project soft-deleted is shown as removed-by-project and not re-added (ADR 0004 §3–§4)
- [ ] New projects created after the upgrade get the latest defaults (ADR 0004 §4)
- [ ] Tenant report lists project rules that differ from the tenant defaults (ADR 0004 Consequences, risk mitigation)
- [ ] "Try it": evaluating a rule against a supplied sample context returns the result and any finding without persisting a finding (ADR 0004 §6)
- [ ] Module `README.md` and docs updated
- [ ] All quality gates green (see CLAUDE.md §Quality gates)
