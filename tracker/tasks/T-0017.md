## Notes
- **Fixtures**: `tests/contract/conformance_fixtures.json` (schema, value encoding and error
  taxonomy in `tests/contract/README.md`). 251 fixtures: 240 with exact parity of value / error
  code on both runtimes (≥ the 120 T-0131 needs), plus 11 `known_gap` fixtures where one runtime
  deviates from the CEL spec. Gap fixtures are not skipped: the deviating runtime is asserted
  against its pinned current result, the other against the spec result (TD-041).
- **Fix round 1**: TODOs re-created as TD-041 (gaps), TD-042 (count) and TD-040 (encoding) after id collisions with dev (old
  TD-032/033/034). Server strictness (`backend/app/core/cel/strict.py`: celpy function-table
  overrides for `+ - * / % && || [] string()`, plus compile-time checks for `has(x)` and literal
  non-bool operands/predicates) closed 9 server fail-open gaps. Expression cap 4096 UTF-8 bytes
  on both sides; `$timestamp` case-sensitive on both sides. Fail-closed contract (pass only on
  exactly `true`) documented in both CEL READMEs and TD-041 (also tagged T-0018). One server
  fail-open gap remains (non-literal non-bool `filter()` predicate; celpy macros are not
  overridable) — TD-041.
- **Server**: `backend/app/core/cel/` (platform kernel in `app/core`, not a domain module: no
  tables/routes). `evaluate(expr, context) -> CelOk | CelError`, `lru_cache` of compiled programs,
  celpy + lark imported lazily (both on the TID253 ban list). Deps `cel-python>=0.5,<0.6` and
  `lark>=1.1` added; `requirements.lock` regenerated per backend/README (all wheels exist for
  cp312 / manylinux_2_28 — checked with `pip download --require-hashes`).
- **Client**: `frontend/src/lib/cel/` on `@marcbachmann/cel-js` ^8 (MIT, pure JS, zero deps,
  maintained) rather than `cel-js` (chevrotain + ramda deps, stale). The spec diagram's
  "cel-js / WebAssembly" is not needed for offline use — no WASM.
- **Encoding decision (TD-040)**: plain JSON numbers are CEL doubles on both runtimes; ints,
  timestamps etc. are `$tag` objects. Without this the server would treat `20` as int and break
  `fields.steel_temp >= fields.dew_point + 3.0`.
- **Error codes**: one list in the fixture file; Python `CelErrorCode` and TS `CEL_ERROR_CODES`
  are asserted equal to it by each suite.
- **`count()` (TD-042)**: not registered; the §2.1 hold-gating rule is fixture-tested with
  `size()`, and a fixture asserts `count(...)` is `NO_MATCHING_OVERLOAD` on both runtimes.
