## Goal
Migrations must replay exactly the DDL that shipped (TD-060 decision): each revision inlines the
SQL that `rls_policy_sql` / `ledger_guard_sql` produced at the time, and a test fails when the live
helpers drift from what the latest revision applies.

Also close the CI follow-ups decided on 2026-11-10 (absorbed from T-0032): automate the `backend/requirements*.lock` refresh (TD-047), pin the remaining workflow actions and CI service images (TD-048), and publish the exact image that passed the smoke test instead of a rebuild (TD-051). Both halves are platform hardening with no product code; they touch disjoint files (`backend/migrations/` + core READMEs vs `.github/` + `scripts/ci_gate.py`).

Deviation from the literal criterion: some revisions change only part of a table's policies (`0025` the membership write/census policies, `0029` the tenants census policy), so comparing *only* the newest revision with the full helper output cannot work. The test replays every revision's `FROZEN_RLS_DDL` in order per table (ENABLE/FORCE, DROP/CREATE POLICY, the `CREATE OR REPLACE FUNCTION` a policy calls; whitespace-insensitive) and compares the result with what `apply_rls_policies` runs today; each drifted table is named with the newest revision touching it and the instruction to add a new migration. For a table only one revision touches this is exactly the criterion. Ledger guard: the newest frozen guard (and drop) must equal `ledger_guard_sql` / `ledger_guard_drop_sql`. Also: no revision may import the helper modules, and every frozen statement must appear in the revision's offline `--sql` output.
  - **Same DDL as before.** `alembic upgrade head --sql` and `downgrade head:base --sql` (PostgreSQL dialect) are byte-identical to `dev`. On a local PostgreSQL 16 + PostGIS 3 + ltree cluster: `upgrade head` from `dev` and from this branch give identical `pg_policies`, RLS/FORCE flags + ACLs, non-internal triggers, `kerp_*`/`audit_*` functions (definition hash, SECURITY DEFINER, ACL) and `information_schema.role_table_grants`; `downgrade base` leaves no policy/trigger/function and re-`upgrade` gives the same catalog. The RLS, ledger, migration, tenants, teams/admin suites (19 files) pass on PostgreSQL as `kerp_app` (2 Redis-only skips).
