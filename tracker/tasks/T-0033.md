## Goal
Migrations must replay exactly the DDL that shipped (TD-060 decision): each revision inlines the
SQL that `rls_policy_sql` / `ledger_guard_sql` produced at the time, and a test fails when the live
helpers drift from what the latest revision applies.

## Acceptance criteria
- [ ] Migrations `0001` and `0002` (and any later revision on `dev` when this lands) no longer import `rls_policy_sql` / `ledger_guard_sql`; they contain the frozen SQL strings
- [ ] A test compares, per table, the frozen DDL of the newest revision that touches it with the current helper output and fails on any difference, naming the table and telling the author to add a new migration
- [ ] `alembic upgrade head` on a fresh PostgreSQL database produces the same policies, grants and triggers as before (existing RLS and ledger tests unchanged and green)
- [ ] `backend/app/core/tenancy/README.md` and `backend/app/core/audit/README.md` describe the new convention (replace the "call the live helper" instruction)
- [ ] All quality gates green (see CLAUDE.md §Quality gates)
