## Goal
Every ledger entry written while impersonating names both identities, inside the hash, so the attribution can never be edited away (ADR 0015 §Audit; ADR 0010 precedent).

## Acceptance criteria
- [ ] Additive migration on `audit_ledger` (core table, ADR 0015): nullable `impersonated_by_user_id` (UUID, no FK); CHECK `hash_version >= 3 OR impersonated_by_user_id IS NULL`; `hash_version IN (1, 2, 3)`
- [ ] Hash v3 = v2 body + `"impersonated_by_user_id"` with `"v": 3`; v1 and v2 entries keep verifying (known-answer tests for v1, v2, v3; a mixed chain verifies)
- [ ] `audit.append` takes the impersonator from the request context only (set by T-0277's principal), never from arguments of callers or the request body; `created_by` stays the acting (target) user (= `acted_as_user_id`); outside impersonation entries are written exactly as today (v2)
- [ ] Ledger reads (T-0222 audit explorer API) expose `impersonated_by_user_id`; filter by it; display string "{target} (impersonated by {admin})" key added to the i18n catalogue
- [ ] Downgrade documented as development-only (like ADR 0010)
- [ ] Module `README.md` and docs updated
- [ ] All quality gates green (see CLAUDE.md §Quality gates)
