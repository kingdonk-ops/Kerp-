## Goal
The data behind the RFI calendar in the main web app, the PER-15 client view and the tablet (quality-and-inspection.md §`inspection_requests` 11).

## Acceptance criteria
- [ ] `GET /api/v1/projects/{project_id}/inspection-requests/calendar?from=&to=&discipline=&status=&mine=` returns one event per slot with the fields of §11; range > 62 days → 422; times UTC plus the project IANA time zone (tests)
- [ ] Visibility: internal members with `V` (PER-07 only in their site nodes); PER-15 only slots of issued requests whose every anchor is in their granted subtree; named witnesses the slots naming them; draft slots only for internal members (tests per persona, incl. a PER-15 with a partly covered multi-anchor slot seeing nothing of it)
- [ ] `mine=true` limits to requester, named witness or PER-15 call-out recipient (test); several slots on one day and overlapping slots are all returned (test)
- [ ] The same visibility rule backs the register and detail endpoints (shared query, test)
- [ ] Pull-scope provider (T-0147): requests and slots whose anchors intersect the device's downloaded anchors or where the user is requester or named witness, scheduled from 7 days ago to 28 days ahead, delivered read-only in pull deltas with updates on reschedule/cancel/outcome (tests)
- [ ] A service function `calendar_events(...)` that E-04-15 can register as its `inspections_rfis` provider
- [ ] Module `README.md` and docs updated
- [ ] All quality gates green (see CLAUDE.md §Quality gates)
