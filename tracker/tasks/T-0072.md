## Goal
A duplicated browser tab copies `sessionStorage`, so two tabs hold the same rotating refresh
token; the second refresh looks like reuse and the server revokes the whole session (repo
review 2026-11-13, finding 3). Keep the refresh token in `sessionStorage` (decided by the
owner) and coordinate tabs: one refresh at a time across tabs, and the rotated pair handed to
every tab that held the old token.

## Acceptance criteria
- [ ] Refresh runs under a Web Lock (`navigator.locks`, name `kerp-refresh`) when available
- [ ] The rotating tab broadcasts the new pair on `BroadcastChannel("kerp-auth")`; a tab holding the same old refresh token adopts it; other tabs ignore it
- [ ] Inside the lock, a tab whose stored refresh token changed since it started waiting uses the new token instead of refreshing again
- [ ] Without `navigator.locks` / `BroadcastChannel` behaviour is unchanged
- [ ] Unit tests: two token stores on a shared fake channel; the duplicate never sends the old refresh token
- [ ] All quality gates green
