## Goal
Entra ID provisioning and deprovisioning maps onto `auth_user.is_active` and session revocation (diff §4.9 *SCIM provisioning*).

## Acceptance criteria
- [ ] `/scim/v2/ServiceProviderConfig`, `/ResourceTypes`, `/Schemas` (User only; groups, bulk, sort and changePassword unsupported); `/Groups` → 404 SCIM error
- [ ] `GET /Users` with `filter=userName eq "…"` and `externalId eq "…"`, `startIndex`/`count`; `GET /Users/{id}`
- [ ] `POST /Users`: creates an account with no credentials, memberships or grants (TD-437); `userName` = e-mail (case-insensitive, unique → 409 `uniqueness`); `externalId` = Entra object id, linked like an SSO link (diff §4.5; linked to a different oid → 409); `is_internal` derived as in §4.1
- [ ] `PATCH` (Entra op shapes incl. `replace` of `active`, `name`, `emails`) and `PUT`; `active=false` and `DELETE` deactivate (`is_active=false`, never a hard delete) and revoke every live session through T-0244's service (next request 401, not `DEVICE_REVOKED`, no wipe); `active=true` reactivates without sessions
- [ ] Deactivating the last active `system_admin` → 409 SCIM error, audited, in-app notice to every System admin (TD-437)
- [ ] Every change audited `scim.user_created | updated | deactivated | reactivated` with the token id as actor context (`source="api"`)
- [ ] Tests with synthetic Entra request payloads (no real tenant data), including idempotent repeated PATCH and an unknown attribute
- [ ] Module `README.md` and docs updated
- [ ] All quality gates green (see CLAUDE.md §Quality gates)
