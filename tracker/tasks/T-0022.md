## Goal
Heavy libs imported lazily inside worker tasks.

## Acceptance criteria
- [x] Lint fails on a top-level heavy import
- [x] All quality gates green (see CLAUDE.md §Quality gates)

## Notes
- Two checks share the job, both reading `banned-module-level-imports` under
  `[tool.ruff.lint.flake8-tidy-imports]` in `backend/pyproject.toml`:
  1. ruff **TID253** (`ruff check .` in CI/editor) flags plain top-level imports, submodules
     included (`fitz.utils`, `from pyhanko.sign import ...`).
  2. **TID253 limitation:** it only sees statements directly at module level; imports nested
     at module scope (`try`/`except`, plain `if`, `with`, class body) pass it (verified with
     ruff 0.17.4). An AST contract test in `backend/tests/test_lint_heavy_imports.py` walks
     `backend/app/**/*.py` and fails on any banned import not inside a `def`/`async def` or
     an `if TYPE_CHECKING:` / `if typing.TYPE_CHECKING:` body (the `else` branch counts as
     eager). Relative imports are ignored.
  Not detected by either: dynamic `importlib.import_module(...)` / `__import__(...)` at
  module scope (documented in `backend/README.md` as not allowed).
- Banned list and justification (current spec only): `celpy` (CONSOLIDATION §3 CEL server),
  `rectpack` (§3 nesting), `pyhanko` (§4 PAdES), `fitz` + `pymupdf` (PyMuPDF, both import
  names; task title / PDF work), `cv2` (task title / CAD-image work), `pytesseract`
  (EDGE-SCREENS calibration pipeline "Tesseract OCR"; CONSOLIDATION OCR jobs).
  Not added: DXF/XER parsers, reportlab, trimesh, pyarrow - not named by the current spec;
  follow-up TD-026.
- `backend/tests/test_lint_heavy_imports.py`: writes synthetic samples and runs ruff
  (`sys.executable -m ruff`, project config via `--config`) once; asserts TID253 for 5 import
  forms per module, no TID253 for lazy + `TYPE_CHECKING` imports, plus an exit-code check;
  the AST check has synthetic eager (try, except, plain if, TYPE_CHECKING-else, class body,
  with) and lazy (function, async, method, TYPE_CHECKING, typing.TYPE_CHECKING) samples.
  The module list is read from the config, so new entries are tested automatically.
- Spec gap raised: TD-027 (ARQ vs SAQ wording).
