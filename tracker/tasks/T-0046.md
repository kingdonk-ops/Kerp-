## Notes
- Tokens in `frontend/src/index.css`: `--spacing-touch: 48px` (`min-h-touch`, `min-w-touch`,
  `size-touch`, `h-touch`), `--spacing-touch-gap: 8px` (`gap-touch-gap`), new `--color-focus`.
  Outdoor theme = `<html data-theme="outdoor">` overriding the semantic colours (text ≥ 7:1).
  Checkboxes are `size-touch`; on phones the side navigation wraps into rows above the content.
- "Remembered per user": no backend preference store exists, so `ThemeProvider` keeps the choice
  client-side under `kerp.theme.<userId>` (like the project scope); the sign-in page follows the
  device's last choice (`kerp.theme.device`). Server-side preferences: TD-258. OS
  `prefers-contrast` default: TD-259.
- axe needs real layout and CSS (jsdom measures neither contrast nor size), so the
  `*.a11y.test.tsx` suites run in Vitest browser mode in the installed Google Chrome (Playwright
  `channel: "chrome"`, no browser download; `KERP_CHROME_PATH` overrides). They are a second
  Vitest project, so `npm run test` runs them and CI needs no change. CI Chrome dependency: TD-260.
- axe `target-size` is configured to 48 px; because axe also passes a small target that has free
  space around it, the harness adds a strict `glove-target` measurement (every rendered control
  ≥ 48 × 48 px). Undecidable contrast results fail too. The harness has its own tests proving it
  fails on low contrast and small targets.
- Two `waitFor` callbacks in `App.test.tsx` got braces: the browser-mode matcher types make
  jest-dom matchers return `void`, which `no-confusing-void-expression` rejects.
