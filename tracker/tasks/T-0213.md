## Goal
Review finding 4 (security: medium): `StubScanner` marks every upload clean, so in production any member with Create can publish a malicious PDF/Office file to the project. Owner decision 2026-11-15: a production guard now; the real ClamAV scanner stays TD-211.

- [x] New setting `KERP_UPLOAD_SCANNER_ALLOW_STUB` (default false)
- [x] With `KERP_ENVIRONMENT=production`, the SAQ worker refuses to start while the scanner is the stub and the override is not set (clear error naming the setting)
- [x] Development and test keep working with the stub without any setting
- [x] Tests for both cases; README (uploads) documents the setting
- [ ] All quality gates green

## Context
