## Goal
In-app notifications.

## Acceptance criteria
- [ ] In-app notification model + API (create, list, mark-read), project-scoped
- [ ] Delivery test: a created notification is listable by its recipient and can be marked read
- [ ] Notification carries `priority` (`low|normal|high|critical`), an optional `label` and a `pinned` flag that stays until a caller-defined action (e.g. handover acknowledged) clears it; the list returns pinned first, then priority, then newest (needed by E-04-11)
- [ ] Delivery goes through a channel interface (`NotificationChannel`: deliver(notification, recipient) → result); `in_app` is the only channel built here; channels are registered by configuration so FCM push (T-0144) and e-mail (TD-084) plug in without changing callers (TD-168)
- [ ] A test registers a fake second channel and shows one notification delivered to both; a failing channel does not block in-app delivery
- [ ] All quality gates green (see CLAUDE.md §Quality gates)
