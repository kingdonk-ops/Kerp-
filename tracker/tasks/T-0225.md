Verify chain and verify all need no confirmation dialog: they are read-only (the server records them). Verify all polls `GET /jobs/{id}` every second while queued/running; the backend reports no intermediate progress yet (TD-495), so the bar sits at 0 until the result.
- 2026-11-22 (implementer): "The project's admin page" read as `/admin/projects/:projectId/members` (the only per-project admin page): new `ProjectAdminPanel.tsx` at its top. No UI deleted projects before, so the criterion "a delete attempt under hold shows the translated `LEGAL_HOLD_ACTIVE` message" needed a **Delete project** action (confirmation, `DELETE /projects/{id}`; `team_links_present`, 403, 404 explained; success returns to Backbone → Projects). It is shown only to callers with the project's `admin` capability (PER-09 of the project or a System admin, `useAdminAccess`), like `ProjectsPage` admin actions; the server checks `admin` too (fix round 1). The hold toggle is System-admin only; the state is shown to all, since it explains a refused delete. Only the flag is readable (TD-562). The reason is a single-line input (a textarea failed axe contrast measurement in the in-flow dialog). No `gen:api` needed: the client already had every endpoint.
