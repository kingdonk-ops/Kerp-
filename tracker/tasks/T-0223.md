## Goal
A project under legal hold cannot be soft-deleted, and its archives cannot be deleted (diff §4.7 Legal hold; TD-175).

## Acceptance criteria
- [ ] Additive migration on `oe_projects_project`: `legal_hold` boolean not null default false, `legal_hold_reason`, `legal_hold_set_by`, `legal_hold_set_at`; an ADR in `docs/decisions/` (next free number) is written in this PR (the project table is the root of every project RLS policy)
- [x] `PUT /api/v1/admin/system/projects/{id}/legal-hold` `{on, reason}`: `system_admin` only (403 otherwise, PER-09 included); reason required (1–500 chars) for both on and off; audited in the tenant-level chain `admin-system:<tenant>` (same naming as `deployment-settings:<tenant>` and T-0219's console events; a System admin need not be a project member, so nothing is written to a project-scope chain) with `event: legal_hold_set|legal_hold_cleared` and the project id
- [x] `DELETE /api/v1/projects/{id}` while on → 409 `{code: LEGAL_HOLD_ACTIVE}`; nothing changes
- [x] `projects.service.is_on_legal_hold(project_id)` contract for other modules (archive, T-0233); `ProjectRead` shows the flag
- [x] Module `README.md` and docs updated
- [x] All quality gates green (see CLAUDE.md §Quality gates)
