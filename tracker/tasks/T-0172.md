## Goal
The client half of the offline action time design (user, 2026-11-13; diff §6.4.1): every offline action carries evidence the server can turn into a trustworthy `occurred_at`.

## Acceptance criteria
- [ ] A `ClockSource` interface (`wallTime()`, `monotonicMs()`, `clockSessionId()`) used by app code; no direct `Date.now()` / `performance.now()` for action stamps (lint or test guard)
- [ ] Web/PWA implementation: `performance.now()` with a `clock_session_id` minted per JavaScript realm, so a reload starts a new session; the anchor is persisted and re-taken on reload whenever online (diff §6.4.1 platform notes)
- [ ] Android implementation: a small Capacitor plugin returning `SystemClock.elapsedRealtime()`; a new `clock_session_id` after a device boot (elapsed time below the last stored value or boot count changed) (planner default: plugin choice and boot detection); licence permissive
- [ ] Every outbox mutation (answers, sign-offs, submit, co-sign, comments, field NCR/punch) is stamped with `device_wall_time` (UTC ISO 8601), `monotonic_ms` and `clock_session_id` atomically with the record write; every push batch carries `device_sync_wall_time`, `device_sync_monotonic_ms` and the current `clock_session_id`
- [ ] Anchors `(server_time, monotonic_ms, clock_session_id, token)` are stored from `GET /api/v1/time` (T-0147; the request sends the current `clock_session_id` and `monotonic_ms`, which the token binds) at login, pre-shift (app resume after 4 h idle, planner default) and each sync; an action in the same session as the stored anchor carries that anchor
- [ ] A `measureSkew()` helper returns device-vs-server skew using the round-trip midpoint (used by T-0149 for the checkout block)
- [ ] Tests with fake monotonic and wall clocks: device wall clock set to 2022 still produces correct stamps and anchors; a simulated reboot / reload mints a new session; Android plugin covered by a fake in unit tests and documented for the emulator run
- [ ] `frontend/README.md` and sync docs updated
- [ ] All quality gates green (see CLAUDE.md §Quality gates)
