## Goal
TD-135 decision 8a: replace T-0009's 'PIN on every refresh' with the hybrid model of diff §4.2.

## Acceptance criteria
- [x] The PIN hash (scrypt) moves from `pin:<sid>` in Redis to the device record (T-0043); a magic-link or password sign-in on an enrolled device starts a session without resetting the PIN; the PIN is set once at enrolment and can be changed after an online sign-in
- [x] `/auth/refresh` rotates PIN-gated sessions normally while the session has been idle less than `KERP_PIN_IDLE_MINUTES` (default 30, user 2026-11-13); after a longer idle it refuses with a `PIN_REQUIRED` code and `/auth/pin/unlock` (refresh token + PIN) renews it (diff §4.2)
- [x] A PIN alone still never starts or renews a session (contract test from T-0009 kept)
- [x] Lockout numbers unchanged (4 immediate tries, 30 s doubling to 15 min, 10th wrong PIN ends PIN renewal until a full sign-in, user 2026-11-13); the counter is per device on the server and accepts a report of offline failures from the device (`failed_offline` count, applied with the same escalation)
- [x] PIN failures never revoke the device or trigger a wipe
- [x] Every token response (login, magic-link redeem, refresh, PIN unlock; SSO in T-0054) carries `session_expires_at` (sign-in + 12 h, the refresh token's end), so field clients can start the offline grace without reading the token (product owner, 2026-11-14; diff §4.2 Offline grace)
- [x] Tests cover renewal inside and after the idle limit, the 10th failure, offline-failure reports and `session_expires_at` staying constant across rotations
- [x] `app/core/auth/README.md` updated (remove the per-session PIN description)
- [x] All quality gates green (see CLAUDE.md §Quality gates)

- 2026-11-15 (implementer): Done as follows.
  - PIN on the device row: `oe_identity_device.pin_hash` (scrypt) + `pin_set_at`, migration `0019` (additive). `pin:<sid>` and `RevocationStore.set_pin/get_pin` are gone. The PIN is set by `POST /devices/enrol {pin}` (once; `409 PIN_ALREADY_SET` if the device has one) and changed by the new `PUT /devices/{device_id}/pin` from a session bound to the device (no old PIN; clears the counter; audited `pin_set` / `pin_changed`). Magic-link redeem no longer takes a PIN (`422`). A sign-in (password or magic link) naming an active device of the user in `X-KERP-Device-Id` binds the new session at once and clears the device's PIN failures, without touching the PIN; so does the first binding of a session by enrolment.
  - `/auth/refresh`: a session of a device with a PIN rotates normally while `now - iat(refresh token) < KERP_PIN_IDLE_MINUTES` (new setting, default 30, 1..1440); otherwise `401 {code: PIN_REQUIRED}`, token unspent; `/auth/pin/unlock` renews. Idle definition: TD-300.
  - Lockout: same `PIN_POLICY` numbers, subject = tenant + device (scope `pin-device`), window = refresh lifetime + 1 day (a new session on the device clears it, so it only has to outlive one session). The 10th wrong PIN answers `401 PIN_EXHAUSTED`, and so does every later attempt (`LockoutPolicy.lock_after`: no lock is armed from the cap on, so they are not `429`); nothing is revoked. Offline failures: `failed_offline` on unlock, added atomically before the attempt (`begin_attempt(..., extra)`), only when the attempt runs. Wrong PIN: `401 PIN_INVALID`. API details: TD-301.
  - `session_expires_at` (the refresh token's `exp`) on every `TokenResponse`; constant across rotation and unlock (tests). SSO gets it with T-0054 through the same `_token_response`.
  - TD-142 resolved: the session's device is carried as an optional `did` claim on tokens issued after the binding (sign-in binding or any rotation), so evicting `device:sid:<sid>` no longer opens the gate (test). Residual (first refresh token of a session bound by enrolment) noted in TD-142 and the README; follow-up for per-request resolution: TD-302.
  - Tests changed by design (contract change): `test_auth_field.py` PIN sections rewritten (per-session PIN, "PIN-gated session refuses /refresh", "10th wrong PIN revokes the session", "lockout per session" replaced by per-device / idle / offline / exhaustion tests; the T-0009 "no PIN without a session credential" contract test kept and extended to enrolment and PIN change); `test_auth_lockout.py` store PIN tests removed (API gone), new `extra` / `lock_after` tests; redeem bodies without `pin` in `test_devices.py`, `test_native_transport.py` (field flow now enrols with the PIN), `test_auth_internal.py`; migration head `0019`.
  - Client side (send `failed_offline`, handle the PIN codes, start the offline grace at `session_expires_at`): T-0143.
