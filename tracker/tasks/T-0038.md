## Goal
TD-135 decision 8a: replace T-0009's 'PIN on every refresh' with the hybrid model of diff §4.2.

## Acceptance criteria
- [ ] The PIN hash (scrypt) moves from `pin:<sid>` in Redis to the device record (T-0043); a magic-link or password sign-in on an enrolled device starts a session without resetting the PIN; the PIN is set once at enrolment and can be changed after an online sign-in
- [ ] `/auth/refresh` rotates PIN-gated sessions normally while the session has been idle less than `KERP_PIN_IDLE_MINUTES` (default 30, user 2026-11-13); after a longer idle it refuses with a `PIN_REQUIRED` code and `/auth/pin/unlock` (refresh token + PIN) renews it (diff §4.2)
- [ ] A PIN alone still never starts or renews a session (contract test from T-0009 kept)
- [ ] Lockout numbers unchanged (4 immediate tries, 30 s doubling to 15 min, 10th wrong PIN ends PIN renewal until a full sign-in, user 2026-11-13); the counter is per device on the server and accepts a report of offline failures from the device (`failed_offline` count, applied with the same escalation)
- [ ] PIN failures never revoke the device or trigger a wipe
- [ ] Tests cover renewal inside and after the idle limit, the 10th failure, and offline-failure reports
- [ ] `app/core/auth/README.md` updated (remove the per-session PIN description)
- [ ] All quality gates green (see CLAUDE.md §Quality gates)
