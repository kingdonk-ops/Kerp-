## Goal
A production API or worker must refuse to start when the database role it connects as can bypass tenant isolation or the audit-ledger guard, or when Redis or the JWT signing key is missing (audit items 2 and 17). Today `rls_enforcement_problems`, `rls_coverage_problems` and `ledger_guard_problems` are only called by tests and the Redis/JWT checks run on the first signed-in request.

## Acceptance criteria
- [x] In `app/main.py` `lifespan`, when `KERP_ENVIRONMENT=production`, the app calls `rls_enforcement_problems` (`core/tenancy/rls.py`), `rls_coverage_problems` and `ledger_guard_problems` (`core/audit/guard.py`) against `KERP_DATABASE_URL` and raises (startup fails, clear log line naming each problem) if any reports a problem; outside production it logs a warning only
- [x] The SAQ worker startup runs the same three checks with the same production rule (one shared function, not a copy)
- [x] `lifespan` calls `app_auth_runtime(app)` so a missing or invalid JWT signing key fails startup; in production `KERP_REDIS_URL` is required (settings validation error) for API and worker
- [x] Tests: production startup with a superuser / `BYPASSRLS` role, with a role that owns an RLS table without `FORCE`, with `audit_ledger` UPDATE/DELETE granted, without `KERP_REDIS_URL`, without a signing key each fail; a correctly set-up runtime role starts (PostgreSQL tests for the role checks; SQLite/dev skips the DB checks with a logged reason)
- [x] `/health` stays a liveness check; `docs/deploy/first-run.md` states the startup refusals and how to read the error
- [x] TD-124 resolved; TD-059 gets a dated note (startup assert done here, grants in T-0343); TD-056 gets a dated note (startup assertion done here, role split in T-0343)
- [x] Module/README.md and docs updated
- [x] All quality gates green (see CLAUDE.md §Quality gates)

## Notes
- 2026-11-21 (planner): Created from the 2026-11-21 codebase audit; one PR with T-0341..T-0349. CI's backend jobs do not set `KERP_ENVIRONMENT=production`, so the existing jobs are unaffected; T-0343 adds the owner/runtime split in CI.
- 2026-11-21 (implementer): One shared module, `backend/app/core/startup_safety.py`: `check_database_role(database, settings)` runs `rls_enforcement_problems`, `rls_coverage_problems` (all models imported) and `ledger_guard_problems`; production logs `unsafe database role: <problem>` per problem and raises `StartupRefusedError` naming all of them; elsewhere warnings; no database or SQLite skip with a log line. Called by the API `lifespan` (before any database write) and by the worker's `serve` (after the module startup checks, before Redis; the worker imports the same function). `ledger_guard_problems` now reports `audit_ledger: table not found` instead of crashing on an unmigrated database.
- 2026-11-21 (implementer): `app_auth_runtime(app)` runs in the lifespan in production only; outside production the runtime stays lazy (ephemeral key, in-memory store), so dev/test behaviour is unchanged. Redis: `require_redis(settings)` refuses production without `KERP_REDIS_URL` in the lifespan; the worker already refused without it in every environment. Deviation: a startup refusal, not a `Settings` validation error, because `Settings` also serves alembic and the first-run CLI, which run in production without Redis (spec-gap TD-536).
- 2026-11-21 (implementer): Tests: `tests/test_startup_safety.py` (the rule; lifespan refusals without Redis, without or with an invalid key, with an unsafe role; production with both starts and `/health` is 200; the worker runs the shared check before Redis); `tests/test_startup_safety_pg.py` (the runtime role passes; superuser, `BYPASSRLS` role, `NO FORCE` table, ledger UPDATE/DELETE grant, disabled trigger and missing ledger are refused; warnings outside production). Production lifespan tests now pass `PRODUCTION_RUNTIME` (synthetic key, Redis URL, no database) and run the broker and settings cache on fakeredis (`fake_production_redis`). The `backend-image` smoke test runs the container with a throwaway Redis and a per-run key and adds two negative checks (no Redis, no key).
- 2026-11-21 (implementer): TODOs raised: TD-536 (spec-gap, Redis rule placement), TD-534 (bug: `SaqBroker.close()` raises when Redis is unreachable at shutdown), TD-535 (later: also refuse a runtime role that owns tables once every setup uses the split).
