## Goal
A PR that changes only the frontend still runs every backend job (`backend`, `backend-pg`,
`backend-image`), because `detect` only asks whether `backend/` exists, not whether the PR
touched it. Skip the backend jobs when nothing the backend depends on changed. The reverse
stays as it is: backend changes keep running the frontend jobs, because the generated API
client (`frontend/src/api/`) and the shared contract fixtures couple them.

## Acceptance criteria
- [x] `scripts/ci_changes.py` reports, per pull request, whether the backend jobs are needed: true when any changed path is under `backend/`, `infra/`, `tests/contract/`, `.github/`, `scripts/` (CI and gate scripts), or is `docker-compose.yml`, `Makefile`, or a `tracker/todo/TD-xxx.md` cited by the conformance fixtures; false only when every changed path is under `frontend/` or a docs/tracker/.claude path T-0081 already skips; an empty change list runs everything
- [x] `detect` emits `backend=false` for such PRs (frontend and e2e flags unchanged); `ci-gate` accepts the backend jobs as expected skips through the existing `detect` outputs, so `scripts/ci_gate.py` needs no special case
- [x] Pushes to `dev`/`main` and `workflow_dispatch` still run every job; `backend-publish` behaviour unchanged
- [x] Frontend jobs still run on every PR that touches `backend/` (no reverse skip)
- [x] `scripts/tests/test_ci_changes.py` covers frontend-only, mixed, contract-fixture, workflow, infra and empty change lists; `scripts/tests/test_ci_gate.py` covers a PR with backend skipped and frontend green
- [x] `docs/WORKFLOW.md` updated
- [x] All quality gates green (see CLAUDE.md §Quality gates)

## Notes
- Depends on T-0082 only to avoid editing `ci.yml` in parallel with it; the change itself is independent.
- After T-0082 the PostgreSQL job is expected to take a few minutes, so the saving is mainly runner time and queueing on frontend-heavy phases, not a large wall-clock cut.
- Implementation: `scripts/ci_changes.py:needs_backend` (shares `_only_under` with `is_docs_or_tracker_only`); the CLI prints `docs_or_tracker_only=` and `backend_needed=` lines; `detect` reads both with `grep -qx`. `scripts/ci_gate.py` unchanged: the new gate test passed before any code change.
- The `detect` step's shell was run locally against four cases (frontend-only → backend=false frontend=true; backend+frontend → both true; docs-only → all false; push → all true).
- `e2e/` counts as needing the backend (e2e journeys drive the API); revisit when `e2e/` exists if that proves too broad.
- Also carries the non-blocking suggestions from the PR #141 (T-0082) review: `test_superuser_role_is_reported` reads role attributes on the `postgres` maintenance database instead of the template source; `pg_databases._build_templates` refuses a source database that still holds a schema (new `tests/test_pg_databases.py`, PostgreSQL-only) and registers the head template before migrating so a failed build is still dropped; T-0082 criterion wording aligned with `kerp_tmpl_head_<worker>`.
