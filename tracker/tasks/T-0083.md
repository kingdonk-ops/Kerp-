## Goal
A PR that changes only the frontend still runs every backend job (`backend`, `backend-pg`,
`backend-image`), because `detect` only asks whether `backend/` exists, not whether the PR
touched it. Skip the backend jobs when nothing the backend depends on changed. The reverse
stays as it is: backend changes keep running the frontend jobs, because the generated API
client (`frontend/src/api/`) and the shared contract fixtures couple them.

## Acceptance criteria
- [ ] `scripts/ci_changes.py` reports, per pull request, whether the backend jobs are needed: true when any changed path is under `backend/`, `infra/`, `tests/contract/`, `.github/`, `scripts/` (CI and gate scripts), or is `docker-compose.yml`, `Makefile`, or a `tracker/todo/TD-xxx.md` cited by the conformance fixtures; false only when every changed path is under `frontend/` or a docs/tracker/.claude path T-0081 already skips; an empty change list runs everything
- [ ] `detect` emits `backend=false` for such PRs (frontend and e2e flags unchanged); `ci-gate` accepts the backend jobs as expected skips through the existing `detect` outputs, so `scripts/ci_gate.py` needs no special case
- [ ] Pushes to `dev`/`main` and `workflow_dispatch` still run every job; `backend-publish` behaviour unchanged
- [ ] Frontend jobs still run on every PR that touches `backend/` (no reverse skip)
- [ ] `scripts/tests/test_ci_changes.py` covers frontend-only, mixed, contract-fixture, workflow, infra and empty change lists; `scripts/tests/test_ci_gate.py` covers a PR with backend skipped and frontend green
- [ ] `docs/WORKFLOW.md` updated
- [ ] All quality gates green (see CLAUDE.md §Quality gates)
