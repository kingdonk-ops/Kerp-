## Goal
A deployment that forgets `KERP_ENVIRONMENT` must fail safe: production defaults (no
ephemeral JWT key, no in-memory revocation, magic-link tokens never logged). Development,
tests and CI opt in to `development` explicitly (repo review 2026-11-13, needs-validation C;
decided by the owner).

## Context
Repo review 2026-11-13 (quality + security), owner-accepted.
Needs-validation C: `Settings.environment` defaults to `development`; outside the Docker image (which sets production) a missing variable gives ephemeral JWT keys, in-memory revocation, and magic-link tokens logged in plain text. Owner decided (2026-11-13) to default to production. Related: TD-124 / T-0064 (startup fail-fast) — this task only changes the default; the startup check stays with T-0064.
