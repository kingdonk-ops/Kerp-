## Goal
Transactional e-mails for the lobby and invites once outbound e-mail exists (TD-084): the requester hears about approve/reject by e-mail as well as in the lobby, and invite links are delivered by e-mail.

## Acceptance criteria
- [ ] Approving or rejecting an access request (T-0050) sends a transactional e-mail to the requester through the outbound mail service of TD-084 (project code and name, outcome, the rejection reason if given, link to the lobby or the project); sending runs in the SAQ worker after commit, and a mail failure never rolls back the decision
- [ ] Creating an invite (T-0052) e-mails the invite link to the invited address; the inviter still sees the link once
- [ ] A brand-new account with no credentials can set its first password from an e-mailed invite link (the token proves possession of the address; single use, then accepted as in T-0052); this path is refused for invites whose link was only shown to the inviter
- [ ] Templates through the i18n layer (no hard-coded strings); no project data beyond code and name in the e-mail; every send recorded in the send log of TD-084
- [ ] Tests with a fake mail transport
- [ ] Module `README.md` and docs updated
- [ ] All quality gates green (see CLAUDE.md §Quality gates)
