## Goal
First-run provisioning for a deployment under the access model of diff §4.1 (TD-120 3a): one hidden
tenant, a first System admin, and the deployment settings. Projects are created afterwards by
Project Admins, not by provisioning.

## Acceptance criteria
- [ ] A first-run command creates the deployment's one tenant, its deployment-settings record with the defaults of diff §4.4 (T-0044), and a first user holding `system_admin` (e-mail from the command line or environment; no password in the repo or logs; the user sets it via a one-time link or SSO)
- [ ] It prints / writes the tenant id for `KERP_DEFAULT_TENANT_ID`; login works without any tenant input afterwards (T-0037)
- [ ] It refuses to create a second tenant in a deployment that already has one (one tenant per deployment)
- [ ] No default project is created in production; a `--demo` option (development only) also grants the System admin `create_projects` and creates one synthetic demo project with the admin as PER-09
- [ ] Fresh deploy yields a usable tenant + System admin; re-running is idempotent (no duplicates)
- [ ] Module `README.md` and deploy docs updated
- [ ] All quality gates green (see CLAUDE.md §Quality gates)
