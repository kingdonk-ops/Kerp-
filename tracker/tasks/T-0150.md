## Goal
TD-165 (review part): a reviewer approves or returns a submitted inspection; returned inspections go back to the inspector and are resubmitted (quality-and-inspection.md §Review and return).

## Acceptance criteria
- [ ] States `SUBMITTED` and `RETURNED` added; submit from `PENDING`, `INSPECTION_REQUESTED` or `RETURNED` with proposed result `pass|fail`; other source states → 409
- [ ] Submit writes the inspector's sign-off ledger entry (signer, signature hash, UTC time, geolocation, `device_id`) and calls `run_checks(context, "inspection.submit")`; the rule set includes the built-in `ATTACHMENTS_INCOMPLETE` check (every referenced attachment `complete` per T-0016); a failing check leaves the state unchanged and returns the findings
- [ ] The submit signature (sign-off ledger entry) and the inspection's submit (`submit_` columns) store `occurred_at`, `recorded_device_at`, `synced_at`, `clock_skew_ms` and `time_confidence` from the T-0177 reconstruction (user, 2026-11-13; column placement planner default); the reviewer approval entry stores the same with `VERIFIED_ONLINE`; additive migration; raw evidence never overwritten; the submit geolocation is the signature geolocation required for `INSPECTED_PASSED`
- [ ] `occurred_at` (not sync time) orders history and review queues and is the sign-off time shown; tests: a submit queued offline for 3 days with the tablet wall clock set to 2022 shows the true signing time (`MONOTONIC_RECONSTRUCTED`); after a reboot `SKEW_ADJUSTED` / `UNVERIFIED_REBOOT`
- [ ] An offline submit is authorised by the local PIN unlock (diff §4.2): the server accepts it without a live session at signing time only if `occurred_at` is inside the offline window, the envelope user and `device_id` match the pushing session, and the device is not revoked; otherwise that mutation fails (planner default; tests for each refusal)
- [ ] A submit arriving through `push-mutations` that fails its checks fails only that mutation with the findings and notifies the inspector
- [ ] Answers are read-only in `SUBMITTED` (a write → `ERR_CONFLICT_IMMUTABLE_QUALITY_RECORD` through sync, 409 through the API)
- [ ] Approve calls `run_checks(context, "inspection.approve")` and moves to `INSPECTED_PASSED` or `INSPECTED_FAILED` as proposed; the reviewer cannot change the result; the approval is a sign-off ledger entry; `INSPECTED_FAILED` still raises the Cat A punch or NCR path
- [ ] Return needs a non-blank reason (422 otherwise), moves to `RETURNED`, makes answers editable, and the next submit increments `review_round`; the earlier submit signature stays in the ledger
- [ ] Approve/return: PER-06 on the whole project, PER-07 only for inspections anchored inside their site node(s) (403/404 outside) (user, 2026-11-13, R3a); by default nobody approves an inspection they performed (403); when `allow_self_approval` is effectively on (project setting, off by default, with the per-template override `inherit|allow|deny` from T-0140) a PER-06 may approve their own inspection, a PER-07 never (user, 2026-11-13); a self-approval is audited with the setting/override that allowed it and flagged `self_approved` for the badge (tests for each case)
- [ ] Submit notifies the project's reviewers; return and approve notify the inspector (T-0019 channel interface; push via T-0144 when present)
- [ ] Record history exposes rounds, return reasons, reviewers and times
- [ ] Additive migration; `inspections` `README.md` and docs updated
- [ ] All quality gates green (see CLAUDE.md §Quality gates)
