## Goal
M1 critical gate (diff §7 / edge §7.1 incl. its freeze-scope amendments): schema immutability on the core tables (ADR-gated); CEL JS/Python parity suite; run_checks/eligibility/VFS seam hashes. The freeze covers role names and shapes, never project data such as level names.

## Acceptance criteria
- [ ] Schema-immutability test fails on an unapproved column change to `oe_asset_node`, `oe_asset_item` (incl. `work_anchor_id`) or `oe_asset_level_def`; passes with an ADR (edge §7.1 invariant 1 + amendments)
- [ ] The six role names (`grouping`, `physical`, `work_anchor`, `inspection_anchor`, `progress_unit`, `schedule_link`) are frozen: adding, removing or renaming one fails the gate without an ADR; level keys/labels stay data and are not frozen (ADR 0003 Consequences)
- [ ] Rule-store shape (`oe_validation_rule_set`, `oe_validation_rule`) and its `kind` values (`check`, `digest`, `autolink`, `notify`, `p6_grammar`, `p6_eligibility`) and `engine` values (`cel`, `regex`) are frozen (ADR 0004 Consequences, Amendment E)
- [ ] The per-record override record (`oe_validation_override`, T-0035) shape is frozen (ADR 0004 Amendment A)
- [ ] The field-ownership map (`p6` / `office` / `field` per field) is frozen; a change of owner fails the gate without an ADR (ADR 0005 §1)
- [ ] CEL parity suite green both runtimes
- [ ] Seam hash-check fails on signature drift of `run_checks`, `eligibility` (T-0139) and the VFS resolver
- [ ] Wired into ci-gate
- [ ] The per-kind CEL context schemas, the `p6_grammar` named groups and the `check` / `p6_eligibility` action vocabularies are frozen as recorded in ADR 0004 Addendum F; a change fails the gate without an amendment (TD-139)
- [ ] All quality gates green (see CLAUDE.md §Quality gates)
