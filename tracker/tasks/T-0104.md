## Goal
Idempotent on (project_id, external_activity_id); parse in SAQ batch queue (diff §3). `.xer` SAQ parser → staging → hierarchy mapping onto `oe_asset_node`. Name grammar and eligibility are rules in the single rule store (`p6_grammar`, `p6_eligibility`; ADR 0004 Amendment E, TD-079); activities link to the `schedule_link` level and resolve the work-anchor node by role (ADR 0003).

## Acceptance criteria
- [ ] Re-import is idempotent on the unique composite key `(project_id, external_activity_id)` (re-running does not duplicate nodes)
- [ ] `.xer` parse runs in the SAQ **batch** priority queue (not inline, not ARQ)
- [ ] Staged rows map to `oe_asset_node` via `activity_id`/`external_id`; linkage recorded, not FK to the external system
- [ ] Name parsing uses the project's `p6_grammar` rules (RE2, tried in `sort_order`) and placeholders follow its `p6_eligibility` rules (CEL), both copied from the client-pack defaults; `oe_p6_import` records the mapping-profile revision and rule-set versions used (p6 spec §5)
- [ ] Shipped default (TD-076): a suffix (`512-21`) is a different work-anchor node; `512 Online` / `512 Shut` resolve to the same node `512` with `work_window` on each `oe_p6_anchor_link`; a project that edits the rule params gets the other behaviour (test both) (p6 spec §5.1)
- [ ] Links target the `schedule_link`-level node and resolve the work anchor by role per p6 spec §5.5 (TD-114 default); an unresolvable activity goes to the unmatched list, never guessed
- [ ] Commit calls `run_checks` with the locked default rule set `p6.import.commit` (p6 spec §5.5)
- [ ] The import writes `p6`-owned fields only (p6 spec §7, ADR 0005)
- [ ] `asset_management` `README.md` and docs updated
- [ ] All quality gates green (see CLAUDE.md §Quality gates)
