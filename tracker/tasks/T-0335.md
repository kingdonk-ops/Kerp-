## Goal
Notify the right people when an RFI is issued, confirmed, rescheduled, cancelled, reminded and closed (quality-and-inspection.md §`inspection_requests` 9).

## Acceptance criteria
- [ ] `call_out_recipients(slot)` per §9.1: named witness per external H/W party; for a client party without one, every active PER-15 whose granted subtree contains all slot anchors (test: a PER-15 whose subtree holds only one of two anchors is not notified); principal/third_party only when named; requester and PER-06 informed; a hook for delegates (filled by T-0293)
- [ ] One notification per request per recipient per event (test with a two-slot request); events, recipients and priorities per the §9.2 table (`high` when any `H` point on issue) through T-0019 with `kind` + params, push through T-0144 with ids and a title only
- [ ] Core-mail templates `inspection_requests.issued | rescheduled | cancelled | reminder` registered with `en-AU` keys; content per the TD-484 default: project code and name, RFI no., discipline title, event, link to the request page; no date/time, location, attachment or `.ics`; sent only to account holders (tests on the rendered mail and recipient list)
- [ ] Reminder: SAQ `batch` cron every 15 minutes per active project sends one reminder per `requested`/`confirmed` slot once `now ≥ scheduled_start − reminder_lead_minutes` (default 120); idempotent via `reminder_sent_at`; cleared by a reschedule so the new time gets one (tests)
- [ ] All notification texts are `t()` keys; no free text stored
- [ ] Module `README.md` and docs updated
- [ ] (product intake 2026-11-21) Delivery result kept per recipient and channel; when no channel reached any call-out recipient of an external party, the party row shows `notice_delivery = failed` with the reason and the requester and PER-06 get a `high` in-app notification; a failed delivery never sets attendance (test with a suppressed e-mail address). A reminder that cannot be sent before `scheduled_start` is recorded `too_late` and not sent (test) (§inspection_requests §9)
- [ ] All quality gates green (see CLAUDE.md §Quality gates)
