## Goal
Admins e-mail a targeted audience; PER-09 can never reach users outside its projects (diff §4.7 Broadcast e-mail).

## Acceptance criteria
- [ ] `oe_notifications_broadcast` (`BaseRecordMixin`, tenant RLS): sender, scope (`tenant` or project ids), audience filter, subject, plain-text body, status `draft | queued | sending | sent | failed`, counts; a PER-09 reads only broadcasts targeting its projects
- [ ] Audience: System admin — all active users, project(s), category (`internal`, `external`, `client` = PER-15), personas PER-01–PER-16; PER-09 — only users with a live membership on its own PER-09 projects (any other project id → 404); resolved through core auth / admin service calls, never by reading their tables
- [ ] `POST /api/v1/notifications/broadcasts/preview` returns the recipient count only; `POST .../broadcasts` queues a `batch` job calling `send_mail` per recipient with `broadcast_id`; deactivated and suppressed addresses excluded; rate limit (planner default 5 broadcasts per sender per 24 h)
- [ ] Template `notifications.broadcast`: body escaped plain text; `List-Unsubscribe` + `List-Unsubscribe-Post` (one-click) headers; the unauthenticated one-click endpoint takes an opaque token only: random, single-purpose (broadcast opt-out only), stored hashed at rest (or an HMAC-signed value with a server key), no user id or e-mail in clear in the URL; an unknown, used or malformed token gets the same response as a known one (no oracle; test); never `?user_id=`; opt-out table `oe_notifications_broadcast_optout` (`BaseRecordMixin`, RLS); opted-out users skipped; transactional mail never affected
- [ ] `GET .../broadcasts/{id}` with delivery counts from the send log (T-0226)
- [ ] Audited (sender, scope, filter, count; never addresses). Tests: PER-09 cannot target or count a foreign project's users; persona and category filters; opt-out
- [ ] Module `README.md` and docs updated
- [ ] All quality gates green (see CLAUDE.md §Quality gates)
