## Goal
R-WPS-1..4 as **CEL rule-set data** evaluated through `run_checks` (T-0124) on `welder.assign`,
weld create and `weld.accept`. Violations are blocked with **logged findings**. Qualification and
continuity validity are answered by the stateless `eligibility` service, not a private table.

## Acceptance criteria
- [ ] **R-WPS-1** — weld create / `welder.assign` requires an **approved** `oe_wps_record` is referenced
- [ ] **R-WPS-2** — the assigned qualification is **for that WPS**, `valid`, and its `qualified_range` covers the weld (position / thickness / diameter / material), resolved via `eligibility`
- [ ] **R-WPS-3** — welder **continuity** is within window at `welded_at` (via `eligibility`)
- [ ] **R-WPS-4** — `weld.accept` requires all required NDE results `= accept`, the ITP hold/witness point released, and no open NCR on the weld
- [ ] Rules are expressed as CEL data (no JSONLogic) and run through `run_checks`; violations are blocked and written as logged findings
- [ ] `wps` module `README.md` and docs updated
- [ ] All quality gates green (see CLAUDE.md §Quality gates)
