## Goal
Per-domain lead-time warnings before calibrations and credentials expire (quality-and-inspection.md §Expiry lead-time alerts). Part 1 of the user's T-0183; schedule readiness conflicts are T-0266 (inspections) and T-0267 (P6).

## Acceptance criteria
- [ ] Rule set `compliance.expiry_alerts` in the single rule store (ADR 0004, layers of T-0034; shipped in client packs; project copy editable by PER-06 and PER-09): rules of the existing `notify` kind, CEL bool over the resource (`event.resource_kind`, `event.subtype` such as equipment type, criticality or qualification type), with `params` `{lead_days: [int], notify_holder: bool, notify_personas: [PER-xx], notify_user_ids: [uuid]}`; first enabled matching rule per resource wins; `lead_days` 1–365, distinct, at most 6 values; invalid → 422 on save
- [ ] System defaults (not locked): calibration [30, 14, 3], credentials [60, 30, 7] (planner defaults from the paste)
- [ ] Expiring-resource provider seam: modules register providers in `service.py` (`equipment`: calibration due date and custodian; `credentials`: expiry and holder); compliance never reads their tables; welder continuity (T-0207, Phase 2) and material use-by (E-03-03/E-03-04) register later
- [ ] `oe_compliance_expiry_alert_log` (`BaseRecordMixin` + RLS): `resource_kind`, `resource_id`, `expiry_date`, `lead_days`, `sent_at`; unique `(project_id, resource_kind, resource_id, expiry_date, lead_days)`
- [ ] Daily `batch` SAQ cron per active project: for each resource and each threshold reached (today ≥ expiry − lead_days, expiry not passed) not yet logged, notify (T-0019, high priority; holder/custodian if `notify_holder`, personas resolved to project members, explicit users) and e-mail template `expiry_lead_warning` (registered with T-0227; code/name + deep link, diff §4.6); insert the log row in the same transaction; a renewed expiry date starts a new series (test)
- [ ] AC from the paste: [45, 10] for welding-type qualifications and [14, 3] for calibration gauges send separate warnings on exactly those days, no duplicates on reruns (time-frozen tests)
- [ ] Creates the `compliance` backend module (manifest, README) if T-0122 has not; T-0122's compliance rule sets live in the same module
- [ ] Module `README.md` and docs updated
- [ ] All quality gates green (see CLAUDE.md §Quality gates)
