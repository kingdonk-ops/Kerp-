## Goal
TD-164 decision 17a: know every field device, revoke it remotely (sessions killed, local data wiped on next contact) and record the device in the audit ledger.

## Acceptance criteria
- [ ] `oe_identity_device` (tenant-level, `BaseRecordMixin`, RLS): user, client-generated `device_id`, platform, OS and app version, `enrolled_at`, `last_seen_at`, `last_sync_at`, status `active|revoked`, revoked by/at, `wipe_confirmed_at` (diff §4.3)
- [ ] A field client enrols on sign-in (`POST /api/v1/devices/enrol`); the session (`sid`) is bound to the device; requests from a device send its id and update `last_seen_at`
- [ ] Revoke (`POST /api/v1/devices/{id}/revoke`) by a `system_admin`, a PER-09 of a project the device's user belongs to, or the user (user, 2026-11-13); others get 403/404; revoke kills every session of the device immediately
- [ ] When the revoker is a PER-09 (not the user or a `system_admin`) and the device's user belongs to other projects, the revoke API returns a warning that unsynced work of those other projects on the device will be wiped and needs `confirm_cross_project_wipe: true` (else 409); the revoke is written to the audit ledger with the actor, the role used (`system_admin` / `per_09` + project / `self`) and whether the warning was confirmed (diff §4.3)
- [ ] Any later call from a revoked device (incl. refresh and sync) returns 401 with `code: DEVICE_REVOKED`; `POST /api/v1/devices/{id}/wipe-confirmed` records the wipe
- [ ] Ledger entries written through a device carry `device_id`: additive nullable column included in the content hash from ledger `v` = 2, existing v1 rows still verify; the core-table change is recorded in a short ADR in `docs/decisions/` (CLAUDE.md §6, diff §4 ledger design)
- [ ] List devices per user (admin) and own devices (user) with last-seen and last-sync times
- [ ] `app/core/audit/README.md` and the identity README updated
- [ ] All quality gates green (see CLAUDE.md §Quality gates)
