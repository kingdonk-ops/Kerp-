## Goal
ADR 0004 Amendment A: one record may proceed past a blocking `check` rule with an approved,
reasoned override that is void as soon as the checked values change.

## Acceptance criteria
- [x] `oe_validation_override` (`BaseRecordMixin` + project RLS) with exactly the columns and `decision` states (`pending` → `approved` / `rejected` / `void`) in the table in quality-and-inspection.md §Per-record override; that table is the single source for the shape frozen at M1 (T-0131)
- [x] A request is accepted only while a blocking finding exists for that record and rule; an empty or whitespace reason → 422 (Amendment A.1–A.2)
- [x] Approver routing: default PER-06 QA/QC Lead; requester holds PER-06 → PER-02 Project Manager; requester holds PER-02 → PER-06; the requester can never approve their own request (403), tested for all three cases (Amendment A.4)
- [x] The approver is notified of a new request and the requester of the decision (T-0019) (Amendment A.3)
- [x] Request and decision are written to the record's activity history (its audit chain) and the audit ledger (Amendment A.5)
- [x] `run_checks` lets the record pass that rule only while the hash of the checked values (e.g. equipment id, specification revision, inspection date) equals `checked_values_hash`; changing any of them voids the override and the block returns (test) (Amendment A.6)
- [x] Module `README.md` and docs updated
- [x] All quality gates green (see CLAUDE.md §Quality gates)
