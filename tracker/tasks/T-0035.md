## Goal
ADR 0004 Amendment A: one record may proceed past a blocking `check` rule with an approved,
reasoned override that is void as soon as the checked values change.

## Acceptance criteria
- [ ] `oe_validation_override` (`BaseRecordMixin` + project RLS): record reference, `rule_key` + rule version, requester, `reason`, routed approver, `decision` (`pending`/`approved`/`rejected`), `requested_at`, `decided_at`, `checked_values_hash` (quality-and-inspection.md §Per-record override)
- [ ] A request is accepted only while a blocking finding exists for that record and rule; an empty or whitespace reason → 422 (Amendment A.1–A.2)
- [ ] Approver routing: default PER-06 QA/QC Lead; requester holds PER-06 → PER-02 Project Manager; requester holds PER-02 → PER-06; the requester can never approve their own request (403), tested for all three cases (Amendment A.4)
- [ ] The approver is notified of a new request and the requester of the decision (T-0019) (Amendment A.3)
- [ ] Request and decision are written to the record's activity history (its audit chain) and the audit ledger (Amendment A.5)
- [ ] `run_checks` lets the record pass that rule only while the hash of the checked values (e.g. equipment id, specification revision, inspection date) equals `checked_values_hash`; changing any of them voids the override and the block returns (test) (Amendment A.6)
- [ ] Module `README.md` and docs updated
- [ ] All quality gates green (see CLAUDE.md §Quality gates)
