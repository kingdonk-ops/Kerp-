## Goal
Split of the old overloaded rule-set task (diff §7): completion gates only, written against roles (`work_anchor.complete` replaces `rsw.complete`, ADR 0003 §2) and shipped as locked system defaults (ADR 0004 §5).

## Acceptance criteria
- [ ] Rule sets `inspection.close`, `work_anchor.complete` and `asset.status_change` ship as system-default YAML (`backend/app/modules/<m>/rules/defaults/`); the mandatory gates are `locked: true`; no rule set or rule refers to a level name such as "RSW" (ADR 0003 §2, ADR 0004 §2, §5)
- [ ] A work-anchor node cannot complete while an open Cat A punch or NCR is anchored to it, its descendants, its items or its lineage predecessors (asset-and-tagging.md §Anchor invariants)
- [ ] `inspection.close` requires quals/photos/sign-off; qualification and calibration checks go through `eligibility` (T-0139) as of the inspection date (ADR 0004 Amendment C)
- [ ] A project cannot disable, delete or change these locked rules (409) but can add a stricter rule to the same set (ADR 0004 §5; T-0034 behaviour)
- [ ] `validation` `README.md` and docs updated
- [ ] All quality gates green (see CLAUDE.md §Quality gates)
