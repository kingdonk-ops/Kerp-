## Goal
Product-owner decision 2026-11-14 (diff §4.1 *External invitees create their own password*): clients and subcontractors never use Microsoft sign-in; a brand-new invitee creates their own password from the e-mailed invite link while accepting the invite.

## Acceptance criteria
- [ ] Creating an invite (T-0052) enqueues the invite e-mail through T-0058 (never synchronous): project code and name, inviter name, expiry, link `/invite#<invite_token>.<setup_token>` (both in the fragment); the inviter's response still returns the copyable link once with the `invite_token` only (fallback)
- [ ] `setup_token`: ≥ 256-bit random, stored only as a hash on the invite, single-use, same expiry as the invite, revoked with it (re-invite and revoke); never in the invite response, logs or Sentry (test asserts)
- [ ] `POST /api/v1/invites/setup-preview` (not signed in; both tokens in the body) returns project code and name and whether a first password can be set (the account has no credentials); otherwise a neutral answer telling the client to sign in
- [ ] `POST /api/v1/invites/accept-with-password` (not signed in; `invite_token`, `setup_token`, new password): only for an active account without credentials whose e-mail is the invited one; enforces the T-0077 policy, sets the password, accepts the invite (membership) and issues the normal session (cookie or native body transport, `session_expires_at`, `joined_project_id`) in one transaction; any token problem → the neutral 410 of T-0052; an account that already has credentials → 409 `code: INVITE_SIGN_IN_REQUIRED` (sign in instead)
- [ ] With only the `invite_token` (copied link) no password can be set; the client offers the T-0077 reset ("Send me an e-mail to set my password") and accepts through T-0052 carry-through after sign-in
- [ ] Audited: invite e-mail queued, first password set, acceptance; the PER-09 never sees or can set the invitee's password
- [ ] Tests (fake mail transport): brand-new external invitee sets password from the e-mailed link and lands in the project; copied link cannot set a password; wrong/expired/revoked/used tokens; account with existing password gets 409; re-invite revokes the old setup token; policy rejection leaves the invite pending
