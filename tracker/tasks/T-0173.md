## Goal
Co-sign mode (ii) (user, 2026-11-13): each client device the PER-15 uses holds a signing key pair whose public half the server and the inspectors' tablets know.

## Acceptance criteria
- [ ] `oe_identity_signing_key` (`BaseRecordMixin` + tenant RLS): user, `device_id` (T-0043 registry), `key_id`, public key (JWK), algorithm ES256 (planner default), status `active|revoked`, enrolled/revoked times
- [ ] `POST /api/v1/signing/keys` enrols a public key for the caller's own enrolled device (PER-15 only; others 403); the private key is never sent (the API accepts only a public JWK)
- [ ] Revoking the device (T-0043) revokes its keys at the same time; revocation is audited
- [ ] The pull scope (T-0147) delivers public keys (with `key_id`, user, status, granted subtree) of active keys of PER-15 members whose subtree covers a picked anchor, and `remove` deltas on revocation; tests prove no private material and no other project's keys are sent
- [ ] A key-validity service answers "was key K active at time T" for T-0163
- [ ] Identity `README.md` and docs updated
- [ ] All quality gates green (see CLAUDE.md §Quality gates)
