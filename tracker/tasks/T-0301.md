## Goal
Cheap capture of storage usage from day one (diff §4.10 *Usage metering*); reports and chargeback come later (T-0303–T-0305).

## Acceptance criteria
- [ ] New module `metering`. Table `oe_metering_storage_event` (`BaseRecordMixin` + RLS; project-scoped rows, tenant rows with null project): `object_key_hash`, `event` (`ref_added | ref_removed | object_stored | object_deleted | class_changed`), `source_kind` (`upload | derivative | archive`), `source_id`, `bytes`, `storage_class` (`STANDARD | GLACIER_IR | DEEP_ARCHIVE`), `occurred_at`, `idempotency_key`; append-only in practice (soft delete only, no `ON DELETE CASCADE` from any table)
- [ ] Idempotency: column `idempotency_key` (text, not null) = hook name + the source row's transition or version id (e.g. `archive.class_changed:<archive_id>:<tier_transition_id>`, `uploads.available:<file_id>:<version>`), supplied by the calling hook; partial unique index on `(tenant_id, idempotency_key)` `WHERE deleted_at IS NULL` (plain columns, no expressions); a retried hook writes nothing twice (test), while distinct transitions of the same object are all kept
- [ ] Test: one archive moved STANDARD → DEEP_ARCHIVE → STANDARD → DEEP_ARCHIVE records three `class_changed` events with the right `storage_class` each, and replaying any of those hook calls adds no row
- [ ] Hooks called through `metering/service.py` in the same transaction: uploads file `available` (ref added, object stored on first reference), `expired`/orphan-swept/deleted (ref removed, object deleted when the last reference goes), derivatives created (T-0247), archive `ready` (DEEP_ARCHIVE or STANDARD per T-0233), tier change (T-0237, `class_changed`), restore-as-new copies (T-0240, new project's objects); rejected uploads never count
- [ ] Attribution (TD-436): physical bytes counted once per object (tenant and owning project); logical bytes per referencing file row; an object referenced from several projects is attributed in full to each, marked shared, counted once tenant-wide (tests)
- [ ] Backfill command (`python -m app.modules.metering.backfill`) builds the ledger once from existing file, derivative and archive rows through their services; idempotent
- [ ] No cross-module table access: uploads, archive and derivatives call metering; metering reads nothing of theirs
- [ ] No money anywhere: bytes and counts only
- [ ] Module `README.md` and docs updated
- [ ] All quality gates green (see CLAUDE.md §Quality gates)
