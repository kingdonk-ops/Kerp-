## Notes

- 2026-11-10: TD-052 (user decision: docker-compose Postgres 16 recipe with the kerp_app role) folded in here instead of a new task: this task already owns the local docker-compose stack.

- 2026-11-10 (implementer): **Shared SQL.** `infra/postgres/initdb/20-kerp-app.sql` (ltree + postgis, `kerp_app LOGIN NOSUPERUSER NOBYPASSRLS`, `GRANT ALL ON DATABASE current_database()`, `ALTER SCHEMA public OWNER TO kerp_app`) is the one copy: CI's "Create non-superuser app role" step now runs it with `psql -v ON_ERROR_STOP=1 -f` (same statements as before plus the two `CREATE EXTENSION IF NOT EXISTS`), and compose mounts it as a single file into `/docker-entrypoint-initdb.d/` (keeps the PostGIS image's `10_postgis.sh`). Postgres healthcheck uses TCP so `--wait` does not pass during initdb.
- **Guards.** `backend/tests/test_dev_infra.py` (runs everywhere) fails if compose's postgres/redis images or superuser env drift from CI, the init script loses `NOSUPERUSER NOBYPASSRLS`/extensions, CI stops using the shared script, or the Makefile URLs differ from CI's PG-step env. `backend/tests/test_pg_extensions.py` (PostgreSQL only, TD-052 skip reason) proves ltree + PostGIS work for `kerp_app` and that it is neither superuser nor BYPASSRLS; it runs in CI's PG step (criterion 1 is proven there, not locally). `KERP_FAIL_ON_SKIP=1` (`backend/tests/skip_guard.py`, wired in `conftest.py`, tested by `test_skip_guard.py`) makes any skip fail the run; `make test-pg` sets it.
- **Deviation: no `.env.example`.** The implementer agent's permission rules deny writing `.env*` files, so the dev defaults are `?=` variables in the root `Makefile` (exported; optional git-ignored `.env` overrides). Follow-up TD-131.
- **Not verified locally:** Docker and make are not installed on the implementer machine, so `docker compose up` and `make test-pg` were never executed. CI runs the same SQL script and the same PG tests (no skips there) but not compose or the Makefile, so criterion 3 ("with no skips") stays unticked until someone runs `make reset && make test-pg` (TD-132; also checks the pinned MinIO tag pulls).
- MinIO runs with a dev-only root login; no bucket, no backend storage settings, and no separate dev database yet (TD-133). TD-052 resolved here.
