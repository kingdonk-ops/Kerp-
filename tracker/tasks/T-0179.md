## Goal
Standalone inspections (daily pre-starts, safety checks, equipment checks, fault reports) on the one-engine, separate from the QA/ITP chain (quality-and-inspection.md §Standalone inspections). Non-public, authenticated part of the pasted T-0179.

## Acceptance criteria
- [ ] Templates (template revisions, T-0110) and `oe_inspections_inspection` get `category` (`qa_itp | safety_prestart | equipment_check | repair_fault | general`, default `qa_itp`) and `is_standalone` (bool, default false); additive migration, existing rows become `qa_itp` / not standalone (test)
- [ ] A standalone template has `kind = inspection` only and needs no parent ITP line; a standalone template attached to an ITP line, or a `kind = itp` template marked standalone → 422
- [ ] Anchors follow ADR 0003 and T-0111 unchanged in this task (one of `node_id` / `item_id`, `inspection_anchor` levels); project-level records for every area other than `qa_itp` (no anchor, location, links) are T-0325 (ADR 0003 amendment 2026-11-21); equipment is a link (T-0250), never an anchor
- [ ] A record copies `category` / `is_standalone` from its pinned template revision; they cannot be changed on the record
- [ ] The inspections service and `GET /api/v1/inspections` filter by `category` and `is_standalone` (repeatable), default all; the service exposes the filter to T-0160/T-0251 (no cross-module table access)
- [ ] Category is part of the template revision hash (changing it makes a new revision) and is copied with client packs (T-0108)
- [ ] Every transition still calls `run_checks`; rule sets may branch on `record.category` (context key documented)
- [ ] Tables keep `BaseRecordMixin` + project RLS; another project's template or record → 404 (test)
- [ ] Module `README.md` and docs updated
- [ ] All quality gates green (see CLAUDE.md §Quality gates)
