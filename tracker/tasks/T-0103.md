## Goal
Typed items; reserve CML JSONSchema fields only — no corrosion/trending engine (diff §2.4). Items reference their work anchor by role (`work_anchor_id`, ADR 0003 §2), not an RSW column.

## Acceptance criteria
- [ ] Typed items: `asset_id→node`, `parent_item_id` self-FK, `item_type_id`, `tag`, `work_anchor_id` (nullable), `inspectable`, `custom_fields jsonb`; no `rsw_id` column (asset-and-tagging.md §oe_asset_item)
- [ ] `work_anchor_id`, when set, must reference a node whose level has the `work_anchor` role and that lies on the same root-to-leaf path as `asset_id` (ancestor-or-self or descendant); otherwise 422 (test with remediation and CUI packs)
- [ ] Reserved CML JSONSchema stub fields only (no calc engine): `cml_tag`, `nominal_thickness_mm`, `minimum_structural_thickness_mm`, `design_corrosion_allowance_mm`, `active_corrosion_rate_mm_yr`, `last_measured_thickness_mm`, `last_inspection_date`
- [ ] No corrosion/trending/degradation engine and no auto re-inspection interval code exists
- [ ] Item types are versioned JSONSchemas; an item keeps the type revision it was captured on (§Dynamic attributes)
- [ ] Table uses `BaseRecordMixin` and has a project-scoped RLS policy
- [ ] `asset_management` `README.md` and docs updated
- [ ] All quality gates green (see CLAUDE.md §Quality gates)
