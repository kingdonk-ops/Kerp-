## Goal
ITPs land on the right work anchors by rule, and nothing reaches the field before QA has reviewed the mapping (quality-and-inspection.md §ITP authoring, assignment and propagation).

## Acceptance criteria
- [ ] Rule kind `itp_assignment` (engine `cel`) in the ADR 0004 store per Amendment H (TD-430 default): variables `anchor`, `item`, `activity`, `project`, `params`; action `assign` with `params.template_key`; first match by `sort_order` wins; compile-on-save refuses other variables/actions; editors PER-06 (project) / PER-13 (tenant); system defaults seed file with two synthetic examples (e.g. coatings, piping welding)
- [ ] `oe_qms_itp_instance` (`BaseRecordMixin` + project RLS; TD-428 default): anchor (`node_id` | `item_id`, exactly one), `template_key`, pinned `template_revision_id`, `status pending_qa_review | active | superseded`, `matched_rule_key`, `is_customized` (false), `batch_id`; additive nullable `itp_instance_id` on `oe_inspections_inspection` through the inspections service (no cross-module table access)
- [ ] Manual instantiation `POST /api/v1/qms/itps` `{template_key, anchors[]}`: PER-06 (or PER-03 where the project setting allows, default off); only a **published** revision (else 422 via `run_checks` rule `itp.template_published`); the anchor must satisfy the template's required roles/level keys (T-0111); creates an active instance and its `kind = itp` line records in `PENDING`
- [ ] `POST /api/v1/qms/itps/auto-generate` `{node_id (subtree) | node_ids[]}`: `batch` SAQ job; evaluates `qms.itp_assignment` per work/inspection anchor; writes **proposals only** (instances in `pending_qa_review`, no line records; TD-429 default); anchors already covered by an active instance of the same template are skipped; result counts (matched, unmatched, skipped) on the job
- [ ] Activation: `GET /api/v1/qms/itps/batches/{id}` (mapping matrix: anchor, matched rule, template, revision); `PATCH` a proposal's template (published only) or drop it; `POST .../activate` (PER-06 only; never PER-09 or `system_admin` alone, ADR 0016) creates the line records in `PENDING` in one transaction, sets instances `active` and writes one ledger entry per batch (T-0006) with the actor and counts
- [ ] Field sync and dashboards never see a `pending_qa_review` proposal (test)
- [ ] Tests: rule match/no-match per attribute; draft revision refused; activation by PER-09 → 403; RLS cross-project 404
- [ ] Module `README.md` and docs updated
- [ ] All quality gates green (see CLAUDE.md §Quality gates)
