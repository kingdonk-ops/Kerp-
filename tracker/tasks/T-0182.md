## Goal
Reminders and escalation for pending QA verification items, driven by a project-editable CEL rule set (quality-and-inspection.md §Verification SLA and pending-approval banners). Backend half of the user's T-0182; the banner is T-0263, SLA for override requests and tagout follow-ups T-0264.

## Acceptance criteria
- [ ] Rule set `verification.sla` in the single rule store (ADR 0004): rules of the existing `notify` kind, CEL bool over the item context (`event.target_kind`, `event.criticality`, `event.category`, `event.p6_start_in_hours` when a P6 link exists, `now`), with `params` `{remind_after_hours, escalate_after_hours, escalate_to_persona}`; the first enabled matching rule in `sort_order` wins; a system default (24 h, 48 h, PER-02) ships as a tenant/project-editable rule (not locked); bounds checked on save (remind < escalate, 1–720 h; persona must exist) → 422
- [ ] Additive columns on `oe_qms_verification_item`: `due_remind_at`, `due_escalate_at`, `reminder_sent_at`, `escalated_at`, `escalated_to_user_id`, `escalated_to_persona`, `sla_rule_key`, `sla_rule_version`; computed at create and on reassignment
- [ ] A `batch` SAQ cron every 15 minutes per active project (not archived or soft-deleted): reminder when now ≥ `due_remind_at` and `reminder_sent_at` is null (pinned high-priority in-app notification to the assignee + e-mail template `verification_reminder` through core mail, registered with T-0227's template overrides); escalation when now ≥ `due_escalate_at` and `escalated_at` is null (status `escalated`, target persona/user added, both notified in-app + e-mail, ledger event `verification.escalated`)
- [ ] Idempotent: a second run, two concurrent runs or a retried job send nothing twice (conditional update on the stamp column; test)
- [ ] Escalation does not widen approval: approve/reject still needs QA authority (T-0181); the escalation target is notified and can reassign (planner default, TD-418)
- [ ] `GET /api/v1/qms/pending?record_type=&record_id=` returns the active pending/escalated items for one record (verification items here; overrides and follow-ups through providers, T-0264): status, assignee persona/user display name, submitted at, `due_remind_at`, `due_escalate_at`, overdue flag
- [ ] `POST /api/v1/qms/verifications/{id}/remind` (submitter, PER-02, PER-03 or PER-09 of the project): one nudge per item per 4 h (planner default), 429 with `Retry-After`; audited
- [ ] P6 start proximity is read through the P6 module's service from `oe_p6_anchor_link` when T-0104 exists; absent → the variable is missing and rules must guard with `has()` (test without P6)
- [ ] E-mails carry project code/name and a deep link only (diff §4.6; TD-413)
- [ ] Module `README.md` and docs updated
- [ ] All quality gates green (see CLAUDE.md §Quality gates)
