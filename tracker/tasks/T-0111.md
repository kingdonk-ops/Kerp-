## Goal
Single record store; kind IN (inspection,itp,rfi). Stateless eligibility service (person/instrument/material valid now?) owning no tables, spanning WPS/credentials/calibration (diff §2.1).

## Acceptance criteria
- [ ] Single `oe_inspections_inspection` store with `kind IN (inspection, itp, rfi)`; no per-kind duplicate tables
- [ ] Anchors at any level (Asset / sub-Asset / RSW / Item) and pins `template_revision_id`
- [ ] Lifecycle `PENDING → RFI_ISSUED → INSPECTED_PASSED → LOCKED_FOR_TURNOVER`, with `INSPECTED_FAILED → (Cat A punch | NCR) → RE_INSPECT`; every transition calls `run_checks`
- [ ] `INSPECTED_PASSED` requires signature hash + UTC timestamp + geolocation; `LOCKED_FOR_TURNOVER` is immutable
- [ ] `eligibility` is a stateless service owning no tables, spanning WPS/credentials/calibration, and is the single gate consulted
- [ ] Table uses `BaseRecordMixin` and has a project-scoped RLS policy
- [ ] All quality gates green (see CLAUDE.md §Quality gates)
