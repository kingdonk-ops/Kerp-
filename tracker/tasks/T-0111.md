## Goal
Single record store for inspections and ITPs (diff §2.1) anchored by **role**: any node whose level has `inspection_anchor`, or an Item (ADR 0003 §6). Lifecycle transitions call `run_checks`. The stateless `eligibility` service is T-0139; inspection date/backdating, self-approval and soft-delete are T-0140; the Request for Inspection is its own record (T-0115, TD-045).

## Acceptance criteria
- [ ] Single `oe_inspections_inspection` store with `kind IN (inspection, itp)`; no per-kind duplicate tables; no `rfi` kind and no `RFI_ISSUED` state — the requested state is `INSPECTION_REQUESTED` (TD-045; names confirmed by the user 2026-11-10)
- [ ] Anchor: exactly one of `node_id` / `item_id`; a node whose level lacks `inspection_anchor` → 422; a retired node → 422; an `inspection_anchor` node with no work under it is accepted (quality-and-inspection.md §Unified inspection record; ADR 0003 Amendment 5)
- [ ] Pins `template_revision_id`; a template that declares required roles/level keys cannot be attached to an anchor lacking them (422); header fields resolve by role/level key (`context.work_anchor.code`, `context.level('asset').name`) — tested under the `remediation-rsw` and `cui-line` packs (ADR 0003 §6)
- [ ] Lifecycle `PENDING → INSPECTION_REQUESTED → INSPECTED_PASSED → LOCKED_FOR_TURNOVER`, with `INSPECTED_FAILED → (Cat A punch | NCR) → RE_INSPECT`; every transition calls `run_checks`
- [ ] `INSPECTED_PASSED` requires signature hash + UTC timestamp + geolocation; `LOCKED_FOR_TURNOVER` is immutable
- [ ] `GET /assets/nodes/{id}/inspections` aggregates descendants and lineage predecessors via the `asset_management` service (T-0134), without cross-module table access
- [ ] Table uses `BaseRecordMixin` and has a project-scoped RLS policy
- [ ] `inspections` `README.md` and docs updated
- [ ] All quality gates green (see CLAUDE.md §Quality gates)
