## Goal
Extend the §4.6 send log into a delivery ledger with stats (diff §4.7 Delivery ledger).

## Acceptance criteria
- [x] Additive migration on `mail_send_log` (core table; an ADR in `docs/decisions/` (next free number) is written in this PR): nullable `recipient_user_id`, `project_id`, `broadcast_id`; status `delivered` added to the CHECK
- [x] SES `Delivery` notifications through the existing hardened SNS endpoint set `delivered` (same topic pinning, signature and certificate-host checks; tests with signed synthetic messages)
- [x] Recipient stays SHA-256 + masked only; no clear address, body, link or token is ever stored (existing tests extended)
- [x] `GET /api/v1/mail/stats?from=&to=&template=`: sent, delivered, bounced, complained, failed, suppressed counts and delivery rate; `system_admin` only
- [x] `GET /api/v1/mail/sends` gains filters template, status, date range, broadcast id and exact-address lookup (hashed server-side)
- [x] Every automated and manual send writes one row (existing) and status changes from callbacks are idempotent
- [x] Module `README.md` and docs updated
- [x] All quality gates green (see CLAUDE.md §Quality gates)
