## Goal
Master spec §1.1 requires every relational table's `tenant_id` to be a foreign key to the `tenants` directory table. No such table exists yet (TD-032, split out of T-0014 by TD-271, product owner 2026-11-15). Add the tenants directory table and the FK on every tenant-scoped table, under an ADR because it is a core-table change (CLAUDE.md §6). Done early in phase 0: every new table adds to the cost.

## Acceptance criteria
- [x] ADR in `docs/decisions/` (next free number): tenants directory table, FK on `tenant_id` for every tenant-scoped table, how new tables get the FK (the `BaseRecordMixin` / metadata contract), migration strategy and rollback
- [x] `tenants` table following the `BaseRecordMixin` conventions as far as they apply to the directory itself (UUID id, timestamps, soft delete; the row's own id is its tenant; RLS lets a session see only its own tenant row); at least a display name; no tenant name or id is ever shown to users (diff §4.1, TD-120)
- [x] First-run provisioning: an idempotent step (migration data step or start-up/CLI hook used by T-0023) guarantees the `KERP_DEFAULT_TENANT_ID` row exists before any tenant-scoped insert; re-running creates no duplicate; T-0023's first-run command writes its tenant through this path
- [x] FK `tenant_id -> tenants.id` on every existing tenant-scoped table, added additively: `ADD CONSTRAINT ... NOT VALID` then `VALIDATE CONSTRAINT` in a separate step (no long `ACCESS EXCLUSIVE` lock); a migration test fails if any table carrying `tenant_id` lacks the FK, so later tables cannot skip it
- [x] Test fixtures seed synthetic tenant rows for every tenant id they use (synthetic data only); cross-tenant and RLS contract tests still pass (cross-tenant -> 404)
- [x] Migrations reversible (downgrade drops the FKs and the table) and covered by the upgrade/downgrade migration test
- [x] TD-032 resolved with a pointer to this task
- [x] Module/README.md and docs updated (platform README, deploy docs on provisioning order)
- [x] All quality gates green (see CLAUDE.md §Quality gates)
