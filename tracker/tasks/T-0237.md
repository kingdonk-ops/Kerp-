## Goal
Move archives between storage classes and download them (documents-and-mdr §Registry, tiers and download).

## Acceptance criteria
- [ ] `PUT /api/v1/admin/system/archives/{id}/storage-class` (`system_admin`): S3 `CopyObject` onto the same key with the new class; registry updated only after success; audited
- [ ] Shared content-access gate `archive.service.require_content_access(session, archive, caller)` (reused by T-0239 and T-0240): `system_admin` (else 403), any archive of the tenant, live or deleted project; no membership check (documents-and-mdr §Access, ADR 0016)
- [ ] `admin.service.memberships_at_deletion(session, project_id) → dict[user id, set[Grant]]` (no longer a gate; T-0239 uses it to revive exactly the deletion's memberships), built on `app/core/auth/memberships.py`: the project's soft-deleted membership rows with `source_type = 'direct'` only, filtered to the `"<user id>:<persona>"` pairs of the `revoked_memberships` payload of the latest `delete` entry in the `project:<id>` chain **and** to the rows soft-deleted by that deletion (`deleted_at` / `updated_by` matching the deletion's time and actor, which `deletion_revoked_memberships` returns with the pairs; if the stamps cannot be matched exactly, the `delete` payload additively records source and site id per grant instead; the unique key also has `source_type`, `source_id` and `site_node_id`, so the pair alone is not precise), which `projects.service.deletion_revoked_memberships(session, project_id)` (new, projects module) returns; no module reads another's tables or the ledger directly
- [ ] Test: a membership removed **before** the deletion (soft-deleted, not in `revoked_memberships`) is not returned by `memberships_at_deletion`; a membership re-granted and then revoked by the deletion is returned
- [ ] Test (PR #137 review round 3): a `team_link` row of the same user and persona soft-deleted earlier (team unlinked) is not returned; a PER-07 grant of the same user on **another site** removed before the deletion is not returned, while the PER-07 grant revoked by the deletion is
- [ ] `GET .../{id}/download` (through the gate above): short-lived presigned GET for `STANDARD`, `GLACIER_IR` or a `restored_temp` copy; `DEEP_ARCHIVE` → 409 `ARCHIVE_NOT_RESTORED`
- [ ] Test: a `system_admin` without a membership gets the URL for an archive of a live and of a deleted project; a non-admin (PER-09 of the project included) gets 403
- [ ] Storage-class change needs `system_admin` only (it moves the object without exposing content)
- [ ] Tests against a fake S3 (storage class reflected in the registry)
- [ ] Module `README.md` and docs updated
- [ ] All quality gates green (see CLAUDE.md §Quality gates)
