## Goal
Inspection template → issue types (user, 2026-11-21; issues.md §8): an inspection template revision links 0..many issue templates; raising an issue from an inspection uses the single linked one, lets the user pick among several, or falls back to the category × type default for the template's discipline (audit templates: `audit` templates matching the scope).

## Acceptance criteria
- [ ] `linked_issue_templates` (list of issue template keys) on inspection template revisions, part of the revision hash; each key must be a published issue template visible to the project, checked through `issues.service` (422 with the path)
- [ ] `issues.service.templates_for_inspection(inspection, issue_type?)` and `GET /api/v1/issues/templates?for_inspection={id}&issue_type=`: one linked → `{mode: "single"}`; several → `{mode: "pick", options}`; none → the project default for (discipline or `general`) × type; an audit template with none → the `audit` templates whose `default_origin` matches the scope (tests for each branch)
- [ ] Raising an issue from an inspection with a template outside the resolved options → 422
- [ ] For an audit template the raised issue gets `origin = internal_audit` (internal scope) or `external_audit` (external scope) whatever the chosen template says (test); test: an internal-audit issue template (`internal` + `excluded`) linked on an external-scope audit → the issue is `client` + `register_only` (forcing of T-0314, issues.md §5), with the template defaults in the raise ledger entry
- [ ] Seed revision (T-0322 seed file, new library revision offered, never forced): external audit finding templates, punch and NCR, category `audit`, `default_origin = external_audit`, `client` + `blocks`
- [ ] Module `README.md` and docs updated
- [ ] All quality gates green (see CLAUDE.md §Quality gates)
