## Goal
Apply TD-120 (tenant hidden, one per deployment) and TD-121 (decision 4c) to the T-0008 token layer: users never name a tenant, and a session ends 12 hours after sign-in.

## Acceptance criteria
- [ ] `POST /api/v1/auth/login` (and magic-link request) take no tenant field; the tenant is the deployment's (`KERP_DEFAULT_TENANT_ID`); a request body that still sends `tenant_id` is rejected with 422; no response or error message names the tenant (diff §4.1)
- [ ] Startup in production fails fast when `KERP_DEFAULT_TENANT_ID` is unset or names no tenant row (diff §4.1)
- [ ] `KERP_REFRESH_TOKEN_HOURS` (default 12) replaces `KERP_REFRESH_TOKEN_DAYS`; the refresh token's expiry is sign-in + 12 h and rotation never extends it (user, 2026-11-13); a refresh after that returns 401 and the user must sign in again (diff §4.2)
- [ ] Tests: rotation at 11 h 59 min succeeds and the new token keeps the original expiry; refresh at 12 h fails; reuse detection still revokes the session
- [ ] Web SPA: login and refresh set the refresh token as an `httpOnly`, `Secure`, `SameSite=Strict` cookie scoped to the auth path and never return it in the body; `/auth/refresh` reads it from the cookie and rejects a cross-origin request (Origin check); logout clears it; the SPA (T-0024 auth client) stops storing the refresh token in `sessionStorage` (diff §4.2, TD-203)
- [ ] Cookie-only: no response of this task returns the refresh token in the body, for any client; the JSON-body transport for the Capacitor Android build is added later by T-0043 (Origin allow-list), not here (diff §4.2, TD-203)
- [ ] `app/core/auth/README.md` documents the cookie transport, its CSRF protection and the allowed web origin
- [ ] The PIN failure-counter window follows the new refresh lifetime until T-0038 moves the PIN to the device
- [ ] `app/core/auth/README.md` updated
- [ ] All quality gates green (see CLAUDE.md §Quality gates)
