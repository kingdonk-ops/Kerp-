## Goal
Automatic client delay attribution (diff §2.1; quality-and-inspection.md §`inspection_requests` 7): every no-show, failed call-out and late reschedule leaves an attributable, internal delay record that the Look-Ahead (E-04-02) and delay/TIA work (E-06-03) can read.

## Acceptance criteria
- [ ] `oe_inspection_requests_reason_code` with the code-declared defaults of §7 copied on first use; PER-06/PER-09 edit labels, `applies_to`, default cause party, active (tests)
- [ ] `oe_inspection_requests_delay` (`BaseRecordMixin` + project RLS) with the columns of §7
- [ ] `no_show`: an entry when an absent party had `H` or notice was short; cause = absent party (client before principal before third_party) when `notice_met`, else `contractor`; no entry when only `W` parties were absent after valid notice (tests for the three cases)
- [ ] `failed`: an entry with the reason code's default cause party (test)
- [ ] Open entries close when the slot reaches `witnessed`/`waived` (`ended_at` = outcome time) or is cancelled (cancel time), `hours` = wall-clock with 2 decimals (tests across a reschedule)
- [ ] Reschedule from `requested`/`confirmed` to a later time: one closed entry old → new start with the action's cause party; earlier time or from `no_show`/`failed`: no new entry (tests)
- [ ] PER-02/PER-06 change `cause_party` with a mandatory reason (event + ledger, history kept); others 403 (tests)
- [ ] `GET /api/v1/projects/{project_id}/inspection-requests/delays` with filters `cause_party`, `status`, `from`, `to`, `anchor` and `inspection_requests.service.delays(...)`; routes and fields classed `internal_commercial` (T-0295): 404 for PER-15 and every `is_internal = false` account (test)
