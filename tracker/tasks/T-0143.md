## Goal
The client side of diff §4.2–§4.3: work offline on local unlock, independent of the 12-hour server session.

## Acceptance criteria
- [ ] On first sign-in the app enrols the device (T-0043) and sets the PIN (T-0038)
- [ ] Local unlock verifies the PIN on the device against the keystore-held key without any network call and without a valid access or refresh token: a test with an expired session and no network unlocks, reads downloaded work and queues a change (diff §4.2)
- [ ] Offline lockout uses the same numbers as the server; the 10th wrong PIN ends PIN unlock until an online sign-in; failures are reported on the next contact; PIN failures never delete data (user, 2026-11-13)
- [ ] Once the deployment's offline window (T-0044) passes without a successful contact, the app keeps queued data, blocks new edits and asks for an online sign-in; inside the window it does not (user, 2026-11-13, TD-206; interim until the native Android app, TD-210)
- [ ] On reconnect with an expired session the user signs in again and the outbox drains under the new session
- [ ] A `DEVICE_REVOKED` response wipes the local store (`wipe()`), confirms the wipe to the server when possible and returns to sign-in
- [ ] All strings through `t()`; tests with a fake clock and fake network
- [ ] Module `README.md` and docs updated
- [ ] All quality gates green (see CLAUDE.md §Quality gates)
