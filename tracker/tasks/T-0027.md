## Goal
Stand up the `e2e/` Playwright harness (local + CI) and prove the Phase 0 exit criterion end to end on a real stack (PostgreSQL + RLS as the runtime role, Redis, API, built frontend): **tenant/project created, user authed and scoped, module toggled, rule set run — CI green** (DEVELOPMENT-PLAN.md, Phases table, Phase 0).

## Acceptance criteria

### Harness
- [ ] `e2e/package.json` (pinned `@playwright/test`, `package-lock.json` committed) with `npm test` = `playwright test`; its presence makes CI's `detect` emit `e2e=true` (`.github/workflows/ci.yml`, `flag e2e/package.json`)
- [ ] `e2e/playwright.config.ts`: Chromium only, `baseURL` from `KERP_E2E_BASE_URL` (default the local frontend), `retries: 0` locally / at most 1 in CI, `trace: "retain-on-failure"`, HTML report to `e2e/playwright-report` (the path CI uploads on failure); `webServer` starts the API (`uvicorn app.main:app` with `KERP_ENVIRONMENT=development`, runtime role `kerp_app`, NOSUPERUSER NOBYPASSRLS) and the frontend (built bundle served by `vite preview`, `/api` proxied to the API), each waited on a health URL, `reuseExistingServer` locally only
- [ ] `globalSetup` prepares the database idempotently: `alembic upgrade head`, `python -m app.modules.onboarding.first_run --demo --admin-email e2e-admin@example.test`, then a dev-only seed script (`e2e/seed/seed.py`, refuses with exit 2 unless `KERP_ENVIRONMENT=development`) that, given the run id, sets the synthetic passwords and creates the synthetic data below (including this run's QA user `e2e-qa-<run>@example.test`) through the modules' `service.py` (no direct cross-module table writes)
- [ ] Synthetic data only (CLAUDE.md §6): `@example.test` addresses, invented names, no client data; passwords come from env with dev-only defaults, never a real secret; a second run of the suite against the same database passes (unique project code per run, e.g. a run-id suffix)
- [ ] CI `e2e` job runs the suite on PostgreSQL (same `postgis/postgis:16-3.4` service + `infra/postgres/initdb` scripts as `backend-pg`) and Redis services, sets up Python + backend deps and the frontend build; no job is weakened, skipped or made `continue-on-error`; `ci-gate` still requires `e2e`
- [ ] Locally: `make up` then `cd e2e && npm ci && npx playwright install chromium && npx playwright test` runs the same suite (documented in `e2e/README.md`, with the env variables and how to reset)

### Phase 0 exit journey (`e2e/tests/phase0-exit.spec.ts`, one serial describe; every step asserts what the user or API observably gets)
- [ ] **Tenant:** after `globalSetup`, `GET /health` on the API is 200 and the first-run output carries `KERP_DEFAULT_TENANT_ID`; a second `first_run` exits 0 with "present" (idempotent, asserted in setup)
- [ ] **Auth (UI):** the System admin signs in on `/login` with e-mail + password and lands in the shell (8-group navigation visible, user menu shows the synthetic name); a wrong password shows the generic sign-in error and no session (no token in storage, `GET /api/v1/auth/me` 401)
- [ ] **Project created (UI):** Backbone → Projects → create project `E2E-<run>`; the success message shows and the project is listed; `GET /api/v1/projects/{id}` is 200 and the creator holds PER-09 on it (Members screen lists them)
- [ ] **Persona assigned (UI):** on Admin → Members of the new project the admin assigns this run's synthetic QA user `e2e-qa-<run>@example.test` (created by the seed, one per run, member of nothing before this step) PER-06; the row appears in the members list
- [ ] **Module toggle (API, T-0084):** as the admin, `GET /api/v1/projects/{id}/modules` lists the loaded modules with `toggleable` and `enabled`; `PUT .../modules/validation {"enabled": false}` answers 409 (platform module) and a follow-up GET still shows it enabled; `PUT .../modules/no_such_module` answers 404. The positive step (switch the first `toggleable: true` module off, observe `enabled: false` and a 404 from one of its routes, switch it on again) runs when such a module exists and is otherwise `test.skip` with `TD-492` in the reason (planner default, TD-492)
- [ ] **Scoped (UI + API):** the admin signs out; the QA user signs in; the Project Switcher lists exactly the new project (not the demo project, not earlier runs' projects: the QA user is per run); after picking it the header shows its code; `GET /api/v1/projects/{demo_project_id}` with the QA user's session answers 404 (not 403)
- [ ] **Rule set run (API, ADR 0004):** the seeded tenant-layer `check` set `e2e_smoke` (owned by no module) was copied into the new project at creation (`GET /api/v1/projects/{id}/rule-sets` lists it, layer `project`); as PER-06 the QA user saves rule `qty_positive` (`context.qty > 0`, action `block`, severity `error`) with `PUT .../rule-sets/{rs}/rules/qty_positive` (200, compiled on save); a syntactically broken expression is refused with 422 and nothing is saved; `POST .../rules/qty_positive/try` with `{"context": {"qty": 1}}` returns `outcome: "pass"` and with `{"qty": 0}` returns `outcome: "fail"` plus the `finding` `run_checks` would log (rule key, severity, action)
- [ ] The journey uses only i18n-rendered UI text through role/label locators that do not depend on a hard-coded English string where a `data-testid` or role name is available; no `waitForTimeout`
- [ ] The suite passes 3 consecutive local runs without flakes, and green in CI on the PR
- [ ] `e2e/README.md` (what runs, how to add a journey, seed contract) and `docs/WORKFLOW.md` (e2e job: services, how the stack starts) updated
- [ ] All quality gates green (see CLAUDE.md §Quality gates)
