## Notes
- Generated client: `openapi-fetch` typed by the generated `src/api/schema.ts` (no codegen change, `src/api/` untouched apart from its README). Bearer token on every request; a 401 triggers one single-flight refresh rotation and one retry; a refused refresh clears the session.
- Auth: password login, session resume after reload, logout. Access token in memory, refresh token in `sessionStorage` (body transport per T-0008; cookie question stays in TD-121). Field-worker magic-link/PIN screens deferred: TD-147.
- Nav: 8 groups (`src/app/nav.ts`) with landing pages; group descriptions are provisional and no module items exist yet — module-to-group mapping is a spec gap: TD-148.
- Project switcher + All-Projects: built on a `ProjectDirectory` seam because T-0014/T-0010 are not done; the default directory lists no projects, so production shows the portfolio scope only until TD-145. The scope is client state (stored per user); sending it with requests / scope-keyed caches: TD-146. Default scope: stored choice, else the first project, else All-Projects.
- Design tokens: semantic Tailwind v4 `@theme` colours in `src/index.css`.
- Services (`api`, `tokens`, `projects`, `preferences`) are injected via `AppRoot` for tests (`src/test/fakeApi.ts`, synthetic data only).
