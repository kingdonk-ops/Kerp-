## Goal
One row per tenant/project, day and metric so later statements and advisories read a small table (diff §4.10).

## Acceptance criteria
- [ ] Table `oe_metering_daily_snapshot` (`BaseRecordMixin` + RLS): `project_id` (null = tenant-wide), `snapshot_date`, `metric_key`, `value` (bigint), `unit` (`bytes | count`), `computed_at`, `source_version`; `UNIQUE NULLS NOT DISTINCT (tenant_id, project_id, snapshot_date, metric_key)` as a partial index `WHERE deleted_at IS NULL` (PostgreSQL 16); no `ON DELETE CASCADE`; rows are soft-deleted only and retained
- [ ] Metrics: storage physical/logical bytes and object counts per storage class (from the T-0301 ledger), active seats (tenant: users with `last_active_at` in the day and trailing 30 days, T-0243; project: live members active in the day), members, enrolled devices, inspections created, PDFs generated, e-mails sent per template (T-0226 project_id) — counts through the stats-provider registry of T-0219 extended with a per-project, as-of-date call (no second set of count queries); public capture submissions only once TD-410 accepts ADR 0013
- [ ] SAQ cron on the `batch` worker after midnight in the deployment default site timezone (TD-436); one run at a time (lock); re-running a date overwrites that date's rows idempotently (upsert on the unique key; test)
- [ ] Missed days: the next run computes ledger-based metrics for every missing date; count metrics that cannot be reconstructed are skipped and logged, never invented
- [ ] `GET /api/v1/metering/snapshots?project_id=&from=&to=&metric=` (`system_admin` every project, ADR 0016; PER-09 its own projects; others 403)
- [ ] Runs under normal RLS (no bypass role); the four RLS-bypass contract tests stay green
- [ ] Module `README.md` and docs updated
- [ ] All quality gates green (see CLAUDE.md §Quality gates)
