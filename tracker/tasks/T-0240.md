## Goal
Restore an archive as a new project without touching the original (documents-and-mdr §Restore).

## Acceptance criteria
- [ ] New project id and code; every entity id remapped by UUIDv5(new project id, old id); foreign keys inside the archive rewritten; ltree paths rebuilt from remapped nodes; content-addressed objects copied to the new project's keys and re-verified
- [ ] Audit: archived chains stored as read-only verified evidence; new chains start with a genesis entry referencing archive id and SHA-256; no ledger row rewritten; an ADR in `docs/decisions/` (next free number) is written in this PR (TD-401)
- [ ] From a registry `archive_id`, restore as new goes through T-0237's content-access gate (`system_admin`, any project of the tenant); from an uploaded zip, `system_admin` and the caller's own upload (T-0239) (documents-and-mdr §Access, ADR 0016)
- [ ] Test: a non-admin gets 403 on restore as new, no job is queued and nothing is written (no project, no rows, no objects, no membership)
- [ ] The restoring admin becomes PER-09 of the new project in the restoring transaction (through the admin module's `service.py`), audited in `project-members:<new project>`; test that the new project is openable by that admin and other `system_admin`s and by no other user until members are added
- [ ] Restoring into a clean project recreates nodes, Items, inspections, attachments and audit evidence with matching counts and verified hashes (test)
- [ ] Module `README.md` and docs updated
- [ ] All quality gates green (see CLAUDE.md §Quality gates)
