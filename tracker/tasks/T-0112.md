## Goal
oe_equipment_asset statuses (active/out_of_calibration/sent_for_calibration/quarantined/decommissioned/out_of_service); immutable cert ledger; SAQ OCR; discrepancy→QA task; new cert supersedes+locks prior; expired tool blocked (CEL gate) (diff §5). Test equipment is a dedicated module (TD-061); validity is judged on the inspection date (ADR 0004 Amendment C).

## Acceptance criteria
- [ ] Verified cert supersedes+locks prior
- [ ] OCR discrepancy raises QA review task
- [ ] A tool whose calibration was expired or quarantined **on the inspection date** is not selectable for that inspection and the CEL rule fails on sync; a tool valid on the inspection date but expired today passes (ADR 0004 Amendment C; quality-and-inspection.md §Dates)
- [ ] The calibration gate is evaluated through the `eligibility` provider seam (T-0139); the module registers its provider in `service.py`
- [ ] The calibration hard gate ships as a `locked` system-default `check` rule (ADR 0004 §5)
- [ ] Register columns are extensible: the equipment register's `custom_fields` follow a versioned register-type JSONSchema, records keep the revision they were captured on (ADR 0003 §6)
- [ ] Active certs auto-compile into MDR
- [ ] `equipment` `README.md` and docs updated
- [ ] All quality gates green (see CLAUDE.md §Quality gates)
