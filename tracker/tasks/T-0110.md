## Goal
core/fields palette: numeric, text, unit-bound measurement, photo, signature, instrument reference, calculated. One CEL evaluator shared by forms/ITP/asset schema (diff §2.1).

## Acceptance criteria
- [x] Every field type in the shared palette
- [x] CEL visible_if/required_if/calculated/range evaluate client+server identically
- [x] Template JSON schema: every user-facing string (`label`, option labels, `validation.error_message`, help, section titles) accepts a plain string or a per-locale map keyed by BCP 47 tag; templates declare `default_language` (default `en`); lint rejects an empty map or a map without the default language; keys, option values and CEL are never localised (edge §2.2 amendment, TD-183)
- [x] All quality gates green (see CLAUDE.md §Quality gates)

- 2026-11-21 (implementer): **Criterion 2, limit.** "Identically" holds for the template semantics on every shared case. - 2026-11-21 (implementer): **Decisions where the spec is silent** (all in TD-467, spec-gap): `range: {min, max}` flags an answer as `failed` and does not block (EDGE-SCREENS 2.1 "flags out-of-tolerance reading"; TD-065 open); calculated fields evaluate in template order, client-sent values ignored; `sections` reference field keys (flat `fields`, no section rules); `data_type` keeps its name, `number` is an alias of `numeric`, and `boolean` / `select` / `date` stay in the palette because the T-0025 renderer uses them; answer shapes for `signature`, `instrument_ref`, `measurement`, `date`; field keys are lower snake case and not CEL reserved words; unknown template properties are lint errors.
