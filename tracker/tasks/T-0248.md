## Goal
Field and web clients take their limits from the server instead of literals (diff §4.7 Client bootstrap). The API is T-0231 (phase 0); this is the client half, which needs the client storage contract of T-0127 (phase 1).

## Acceptance criteria
- [ ] The client fetches `GET /api/v1/settings/client` (generated client from `npm run gen:api`, never hand-edited) at sign-in and at every sync
- [ ] The response is stored through the client storage contract (`RecordStore`, diff §6.2), never by importing Dexie directly; a stale value is replaced on the next sync; `wipe()` clears it
- [ ] Limit checks (offline window, grace, clock skew, media size/duration caps, annotation cap) read the stored values instead of constants; a built-in fallback applies only before the first successful fetch (test with a fake server returning non-default values)
- [ ] Any user-visible limit message goes through `t()`
- [ ] Nothing here is specific to the Dexie adapter: the values go through the storage contract only, so when T-0142 (SQLCipher adapter, phase 1) lands, its run of the shared contract suite covers this with no extra code path (T-0142 is not a dependency)
- [ ] Module `README.md` and docs updated
- [ ] All quality gates green (see CLAUDE.md §Quality gates)
