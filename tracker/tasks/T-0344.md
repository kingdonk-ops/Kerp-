## Goal
On a shared device the next user must never see the previous user's data, and an open tab must never quietly act as a different user (audit items 4 and 5). The React Query cache is today cleared only by `logout()` in the current tab; a sign-out in another tab or a session expiry leaves it full, and a tab can take another user's refreshed or broadcast token.

## Acceptance criteria
- [ ] `queryClient.clear()` runs on every signed-in → signed-out transition, whatever the cause: local `logout()`, a cross-tab sign-out (`auth/crossTab.ts`), a failed refresh / session expiry (`lib/api/client.ts`), a 401 that ends the session
- [ ] `startSession` clears the whole query cache (not only `me`) before loading the new session
- [ ] When a refreshed token (`lib/api/client.ts`) or a broadcast token (`auth/crossTab.ts`) has a `sub` different from the loaded `me.id`, the tab treats it as a sign-out: cache cleared, token not used for any request, page reloaded to the sign-in route
- [ ] Tests (Vitest): user A's list data is gone after a sign-out broadcast from another tab; after a session expiry; after `startSession` for user B; a tab loaded as user 1 receiving user 2's broadcast token or refresh response makes no request with it and signs out; the same user's token is accepted as today
- [ ] No user-visible strings added without `t()`
- [ ] Module/README.md and docs updated (`frontend/src/auth` README or the auth section of the frontend docs)
- [ ] All quality gates green (see CLAUDE.md §Quality gates)
