## Goal
On a shared device the next user must never see the previous user's data, and an open tab must never quietly act as a different user (audit items 4 and 5). The React Query cache is today cleared only by `logout()` in the current tab; a sign-out in another tab or a session expiry leaves it full, and a tab can take another user's refreshed or broadcast token.

## Acceptance criteria
- [x] `queryClient.clear()` runs on every signed-in → signed-out transition, whatever the cause: local `logout()`, a cross-tab sign-out (`auth/crossTab.ts`), a failed refresh / session expiry (`lib/api/client.ts`), a 401 that ends the session
- [x] `startSession` clears the whole query cache (not only `me`) before loading the new session
- [x] When a refreshed token (`lib/api/client.ts`) or a broadcast token (`auth/crossTab.ts`) has a `sub` different from the loaded `me.id`, the tab treats it as a sign-out: cache cleared, token not used for any request, page reloaded to the sign-in route
- [x] Tests (Vitest): user A's list data is gone after a sign-out broadcast from another tab; after a session expiry; after `startSession` for user B; a tab loaded as user 1 receiving user 2's broadcast token or refresh response makes no request with it and signs out; the same user's token is accepted as today
- [x] No user-visible strings added without `t()`
- [x] Module/README.md and docs updated (`frontend/src/auth` README or the auth section of the frontend docs)
- [x] All quality gates green (see CLAUDE.md §Quality gates)

## Notes
- 2026-11-21 (planner): Created from the 2026-11-21 codebase audit; one PR with T-0341..T-0349. Frontend tasks use module `frontend`.
- 2026-11-21 (implementer): `TokenStore` binds a session to one user (the sign-in token's `sub`, else the first refreshed token's, and the loaded `me.id` via `bindUser`). Refreshed (`lib/api/client.ts`) and broadcast (`auth/crossTab.ts`) tokens go through the new `TokenStore.rotate`, which refuses a token for another user before storing it (so no request carries it and it is not re-posted), clears only this tab's session (no `/auth/logout`: the server session is the other user's) and fires `onForeignSession`; `AuthProvider` then clears the cache and calls `AppServices.reloadTo("/login")` (a full page load, `window.location.replace` in the browser).
- `AuthProvider` clears the whole query cache on every signed-in → signed-out transition (one `TokenStore` subscription covers local sign-out, cross-tab sign-out, refused refresh / session expiry) and before `startSession` and `adoptCookieSession`. `me` is keyed by a session generation so a new session in an already signed-in tab always loads `me` afresh.
- Decision: a token whose `sub` cannot be read is not compared (accepted as before). The server always sets `sub` (`backend/app/core/auth/tokens.py`); the test fakes use opaque `access-N` tokens.
- TD-521 fixed here (small and in scope): `RequireAuth` keeps pathname + search + hash; `LoginPage.returnPath` keeps the `/login` loop guard (now also for `/login?…`/`/login#…`) and accepts in-app paths only. The TODO can be closed with this PR.
- Tests: `frontend/src/auth/sessionIsolation.test.tsx` (9 of its tests fail without the change).
