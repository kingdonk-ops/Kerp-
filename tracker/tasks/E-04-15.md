## Epic
One calendar over every dated thing a user or project cares about (planner-and-work-plans.md
§15 Unified calendar; user addendum 2026-11-21).

**Status `needs-breakdown`:** the planner agent splits this into S/M tasks (`T-xxxx`,
`epic: E-04-15`) when its phase is next. Do not implement an epic directly.

## Scope (user, 2026-11-21)
1. `core/calendar` provider registry mirroring `core/refs` (E-04-11, handover.md §5.1): each
   module registers a `CalendarProvider` from its `manifest.py`; every provider applies the
   caller's project RLS and site scope (PER-07); no cross-module joins.
   - Personal layer (`scope=mine`): assigned inspections (T-0152); generic, scaffold and tagout
     tasks (E-04-07, E-04-13, T-0257); pending QA verifications (T-0181); shift/roster dates
     (E-04-12); handover due dates (E-04-11).
   - Project layers (`scope=project`): calibrations (due dates + pre-expiry markers, T-0112);
     credentials (expiry, T-0118; welder continuity windows, T-0207); materials_expiry
     (use-by, E-03-03/E-03-04); deliveries (expected PO dates, gate bookings: E-03-02,
     E-03-06); inspections_rfis (planned inspections T-0152, confirmed witness/hold RFIs T-0115);
     jobs_and_p6 (P6 activities T-0104/E-04-01, shutdown windows, committed work-plan lines
     E-04-12).
2. P6 linkage: items anchored to a node or work anchor cross-reference linked P6 activities
   (`oe_p6_anchor_link`, through the P6 service). **Readiness conflicts are computed by
   T-0183/T-0266/T-0267**; the calendar only renders them: a Schedule Readiness Conflict badge
   on the expiring resource event and on the affected P6 activity / inspection bar, linking to
   the blocking record. Clicking a P6 or work-plan bar navigates to the asset/RSW, its
   inspections and dependencies.
3. Frontend: Month / Week / Day / Timeline-Agenda views in the project's IANA time zone (master
   spec §1.2), layer filter chips, colour badges, quick-preview cards (`core/refs`), saved
   filter presets (T-0020).
4. Revocable token-authenticated iCal feed `GET /api/v1/calendar/ical/{token}.ics` for personal
   tasks and inspections: **decision TD-419** (same no-JWT pattern as ADR 0013); build it only as
   decided.

## Suggested breakdown (user, 2026-11-21; planner refines when Phase 4 is next)
1. `core/calendar` provider interface + unified query API (conflicts read from T-0266) + iCal
   feed per TD-419 (M).
2. Providers for personal tasks, inspections/RFIs, calibrations, credentials, material
   use-by/deliveries (M).
3. P6 and work-plan layer + readiness conflict badges (S; the detector itself is T-0266/T-0267).
4. Frontend calendar screen (M).
