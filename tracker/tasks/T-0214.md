## Goal
Close TD-155 (review finding 3). `service.sweep` re-enqueues jobs that never reached Redis, but nothing calls it, so a job committed during a Redis blip stays `queued` forever. Owner decision 2026-11-15: the worker lists scopes in a tenant-level unit of work with `is_system_admin=True` (reads project rows, never project-scoped records; no migration, no BYPASSRLS); the sweep runs every 5 minutes.

## Acceptance criteria
- [ ] A `projects` service function (no cross-module table access) returns the tenant-level scope plus one scope per live (not soft-deleted) project of the deployment tenant (`KERP_DEFAULT_TENANT_ID`), read under RLS
- [ ] An SAQ cron job on the batch worker runs `service.sweep` over those scopes every 5 minutes
- [ ] Tests: deleted projects are skipped; a `queued` row SAQ does not know is re-enqueued by the cron handler; running it twice enqueues nothing new
- [ ] All quality gates green

## Context
Repo review 2026-11-15, owner-accepted (finding 3). Closes the scheduling part of TD-155; its broker retry/backoff note and the optional GET heal moved to TD-304.
