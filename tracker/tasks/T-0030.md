## Goal
Stop outbound URLs (which can carry tokens) reaching the JSON logs, and apply the TD-022 decision that API docs are not exposed in production. Covers TD-024 and the docs part of TD-022 (user decisions 2026-11-09).

Also close the logging/config review notes (PR #7, #9; absorbed from T-0064): JSON logs that cannot fail on a non-UTF-8 console, client disconnects not logged as 500, and no `debug=True` in production. All of this lives in the same files (logging setup, settings, app factory).

## Acceptance criteria
- [x] `httpx` and `httpcore` loggers set to WARNING in the logging setup; a test proves an INFO request line with a query-string token is not emitted — TD-024
- [x] In production, `/docs`, `/redoc`, the OAuth2 redirect and `/openapi.json` return 404; available in dev/test (setting overridable); `npm run gen:api` still works in dev
- [x] backend/README.md updated (TD-022 values: no HSTS preload, docs hidden in production)
- [x] TD-024 resolved in the same PR
- [x] `JsonFormatter` output cannot fail on a non-UTF-8 console (e.g. `ensure_ascii=True` or an encoding-safe stream handler); tested — from T-0064 (PR #7, #9 review)
- [x] A client disconnect (`asyncio.CancelledError`) in the request-context middleware is logged as a disconnect (e.g. status 499), not 500; tested — from T-0064 (PR #7, #9 review)
- [x] Settings validation refuses `debug=True` with `environment=production` at startup; tested (absorbs the relevant part of TD-124) — from T-0064 (PR #7, #9 review)
- [x] All quality gates green (see CLAUDE.md §Quality gates)

New setting `KERP_API_DOCS_ENABLED` (`api_docs_enabled: bool | None`, `None` = off only in production, mirrors `hsts_enabled`/`hsts_active`). When off, `create_app` passes `openapi_url`/`docs_url`/`redoc_url`/`swagger_ui_oauth2_redirect_url=None`, so all four 404. `python -m app.openapi` calls `app.openapi()` in-process with test settings, so `npm run gen:api` works in any environment (verified in dev and with production + docs off; no diff in `frontend/src/api/`). README records the signed-off values (no HSTS preload, docs hidden in production).
  - TD-124: only the `debug=True` + `environment=production` part is covered (a `model_validator` on `Settings`, so `create_app()` fails at startup). The JWT key / `KERP_REDIS_URL` fail-fast stays open in TD-124.
  - JSON logs use `ensure_ascii=True` (tested with an ASCII-only console stream; no `handleError`).
  - `asyncio.CancelledError` in `RequestContextMiddleware` is logged by `kerp.access` with status 499 (`CLIENT_CLOSED_REQUEST`) and `disconnected: true`, with or without a started response; no `kerp.error` line, no 500 body; the cancellation is re-raised.
  - Two existing tests set `KERP_DEBUG=true` under the production default; they now set `KERP_ENVIRONMENT=development` (assertions unchanged).
  - Follow-up: TD-247 (deferred): starlette `ClientDisconnect` (an `Exception`, raised by `request.body()` after `http.disconnect`) still takes the 500 path.
