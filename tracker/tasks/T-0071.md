## Goal
Load the caller's project memberships once per request: `get_tenancy_context` already loads
them; the projects router, `get_project_access` and the uploads router read them again (repo review 2026-11-13, finding 5; scope widened in PR #53 review round 2).

## Context
Repo review 2026-11-13 (quality + security), owner-accepted.
Finding 5: every authenticated request loads memberships in `resolve_request_scope`; the projects router then runs the same `load_grants` again.

## Acceptance criteria
- [x] The grants resolved for the request's scope are kept on `request.state`
- [x] Every request-path re-load uses them: the projects router, `access.get_project_access`, and `uploads.router._bind_project`; each falls back to `load_grants` when absent (tests that override the tenancy dependency)
- [x] Test: `GET /api/v1/projects` runs exactly one query on the membership table (counted with a `before_cursor_execute` listener filtered on that table)
- [x] All quality gates green

## Notes
- `access.CallerGrants` (FastAPI dependency): reuses the grants `resolve_request_scope` stored on `request.state` for the authenticated tenant + user, else loads them. Used by `get_project_access`, the projects router and `uploads._bind_project`.
- Test counts SELECTs on `auth_project_membership` per request (GET list, GET one, PATCH): exactly one each; on the old code GET list made two.
