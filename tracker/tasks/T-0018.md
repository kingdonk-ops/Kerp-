## Goal
`run_checks` evaluates rule sets held as data in the **single rule store** of ADR 0004 §1 (with
Amendment E's P6 kinds); findings are logged with the rule key and version that produced them.
Layers, project copies, locked rules and unlock are T-0034; upgrade offers and "Try it" T-0036;
the per-record override (Amendment A) T-0035.

## Acceptance criteria
- [x] `oe_validation_rule_set(key, kind, layer, version, source_pack)` and `oe_validation_rule(rule_set_id, rule_key, engine, expression, params JSONB, action, severity, enabled, locked, sort_order, origin_rule_key, origin_version)`, both `BaseRecordMixin` + RLS; `project_id` NULL on the `system`/`tenant` layers (ADR 0004 §1)
- [x] `kind` ∈ {`check`, `digest`, `autolink`, `notify`, `p6_grammar`, `p6_eligibility`}, `engine` ∈ {`cel`, `regex`}, `layer` ∈ {`system`, `tenant`, `project`}; `regex` is accepted only for `autolink` and `p6_grammar`, every other kind requires `cel` — invalid combinations rejected on save (ADR 0004 §1, Amendment E)
- [x] Expressions compile on save against the kind's context schema: CEL through the T-0017 runtime (safe subset, TD-041), regex with RE2 syntax (`google-re2`, imported lazily) and a pattern-length limit; an invalid expression is rejected with the compile error (ADR 0004 §6)
- [x] `run_checks(context, rule_set)` evaluates the enabled `check` rules of the named set from the store, in `sort_order` (no code deploy to add a rule); signature stable (frozen at M1, T-0131)
- [x] Findings persisted to a findings log with `rule_key` + rule version; a failing blocking rule blocks the gated transition and the result carries a user-readable reason (ADR 0004 §3, Amendment A.1)
- [x] Every rule change creates a new rule version and an audit-ledger entry (T-0006) (ADR 0004 §3)
- [x] `validation` module `README.md` and docs updated
- [x] All quality gates green (see CLAUDE.md §Quality gates)

  - `app.core.cel.compile_expression` added to the T-0017 runtime (shared parse/static checks + free-variable check).
  - `google-re2` was already in the lock via cel-python; now a direct dependency (lock "via" comment updated only, no re-pin) and banned at module level (lazy import).
  - Rule changes with `source="ai"` are refused until a human-confirmation flow exists (CLAUDE.md §6).
