## Goal
TD-165 (comments part): reviewers and inspectors comment on one answer, so a return says exactly what to fix (quality-and-inspection.md §Comments on answers).

## Acceptance criteria
- [ ] `oe_inspections_answer_comment` with `inspection_id`, `question_key`, `repeat_index` (nullable), `review_round`, `body`, author, time, `resolved_at`/`resolved_by`; `BaseRecordMixin` + project RLS
- [ ] An address not in the pinned template revision → 422; a blank body → 422
- [ ] Comments are append-only once stored (no edit or delete endpoint); the inspector or a reviewer may resolve one
- [ ] Comments can be created offline with a client-generated id through `push-mutations` and are delivered by `pull-deltas` to devices holding the inspection (T-0147 scope)
- [ ] `GET /api/v1/inspections/{id}/comments` lists comments grouped by answer address and round
- [ ] `inspections` `README.md` and docs updated
- [ ] All quality gates green (see CLAUDE.md §Quality gates)
