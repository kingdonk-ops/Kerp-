## Goal
TD-162: records created offline keep their client id, and an answer whose tablet value lost a three-way apply is visibly flagged (diff §6.4).

## Acceptance criteria
- [ ] A create mutation carrying a client-generated UUIDv7 `id` is stored with that id (ad-hoc inspection, answer, answer comment, attachment metadata, NCR, punch item)
- [ ] A replay with the same `client_op_id` is a no-op; a create whose id already belongs to a different record fails that mutation with `ERR_ID_CONFLICT`; a non-UUIDv7 id fails with `ERR_ID_INVALID`; the other mutations of the batch still apply
- [ ] When the per-field apply keeps the server value (ADR 0005 §4), the answer gets a `conflict` flag referencing its `sync_conflict_log` entry; the flag is returned with the record and in `pull-deltas`
- [ ] `sync` sets and clears the answer conflict flag only through the `inspections` service (no cross-module table access; test asserts the service call)
- [ ] Writing a value to a flagged answer through a normal edit clears the flag and records who resolved it
- [ ] The `inspection.submit` rule set gains the built-in check `ANSWER_CONFLICT_UNRESOLVED` (fails while any answer is flagged)
- [ ] `sync` and `inspections` `README.md` and docs updated
- [ ] Time reconstruction in the `sync` service for every mutation (diff §6.4.1): same `clock_session_id` as the push → `occurred_at = server_sync_time − (device_sync_monotonic_ms − monotonic_ms)`, `MONOTONIC_RECONSTRUCTED`; same session as a carried anchor whose token verifies → `anchor.server_time + (monotonic_ms − anchor.monotonic_ms)`, `MONOTONIC_RECONSTRUCTED`; otherwise `clock_skew_ms = server_sync_time − device_sync_wall_time`, `occurred_at = device_wall_time + clock_skew_ms`, `SKEW_ADJUSTED`, or `UNVERIFIED_REBOOT` when |skew| > 2 min (planner default threshold); online API actions → `VERIFIED_ONLINE`
- [ ] The reconstructed values are handed to the owning module's service with each applied mutation; answer and answer-comment rows store `occurred_at`, `recorded_device_at`, `synced_at`, `clock_skew_ms`, `time_confidence` (additive migration; raw evidence never overwritten; column placement planner default)
- [ ] Audit entries for offline actions carry the five values in their hashed payload; the T-0006 ledger table is not altered (planner default; no core-table ADR)
- [ ] Tests with fake monotonic and wall clocks: a tablet wall clock set to 2022 reconstructs the exact time via monotonic; a forged or foreign anchor token is ignored; a reboot gives `SKEW_ADJUSTED`, or `UNVERIFIED_REBOOT` above 2 min; boundary at exactly 2 min
- [ ] All quality gates green (see CLAUDE.md §Quality gates)
