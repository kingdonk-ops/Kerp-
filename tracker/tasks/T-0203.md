## Goal
`oe_weld` records anchored to an **Item (`type=weld`)** — not a parallel store — with the weld
lifecycle state machine. Rule enforcement on transitions is wired in T-0206.

## Acceptance criteria
- [ ] `oe_weld` with `asset_item_id`→item (`type=weld`), `weld_number`, `wps_id` **required**, `welder_qualification_id` **required**, joint/size/thickness/diameter/material, `nde_required`, `nde_types[VT|PT|MT|RT|UT]`, `status`, `welded_at`
- [ ] A weld is created as an Item `kind=weld` (reuses T-0103 Item model); no parallel weld anchor or duplicate store
- [ ] State machine `fit_up → welded → nde_pending → accepted`, plus `… → rejected → cut_out → (re-weld) fit_up`; illegal transitions rejected by a transition table
- [ ] Each transition is routed through a guard hook ready for `run_checks` (rule sets attached in T-0206)
- [ ] Table uses `BaseRecordMixin` and has a project-scoped RLS policy
- [ ] `wps` module `README.md` and docs updated
- [ ] All quality gates green (see CLAUDE.md §Quality gates)
