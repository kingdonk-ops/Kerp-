## Goal
The RFI notification document (quality-and-inspection.md §`inspection_requests` 10): one layout whose title, inspection-type list and location column vary by discipline, printed from the record with no retyped data.

## Acceptance criteria
- [ ] SAQ `batch` job renders with PyMuPDF imported lazily (T-0022), stores through the storage service with SHA-256, returns a presigned link; `GET /api/v1/projects/{project_id}/inspection-requests/{id}/pdf` returns the latest; a draft renders on demand with a "Draft" watermark and is not stored
- [ ] A new revision on issue, reschedule, cancel and close; the close rendition is titled "<discipline title> – Results" and its key + SHA-256 are kept on the request (tests)
- [ ] Header, slot rows, result derivation and footer exactly per §10.3: contract no., RFI no., project, ITP no(s). via `qms.service`, scheduled date (per-row dates when slots span dates), shift, revision; party × H/W/S/R grid; asset details and RSW no(s). in the project terminology (T-0136); location label per discipline; scheduled time 24 h in the project time zone; result labels incl. Accepted/Rejected from the linked ITRs; one "Rescheduled from …" note per reschedule; comments prefixed with their party (tests on extracted text for one request per discipline)
- [ ] Title and field set follow the discipline configuration (§10.2): mechanical, coating and civil defaults and a project-edited inspection-type label appear on the PDF (tests)
- [ ] `max_slots` rows; unused rows and empty values print blank — never `0`, `12:00 AM`, `#N/A` (test)
- [ ] Fixed labels from the T-0158 backend message catalogue in the project default language with `en` fallback
- [ ] Module `README.md` and docs updated
- [ ] All quality gates green (see CLAUDE.md §Quality gates)
