## Goal
System admins see uploads that failed or are stuck in the check, with the scanner signature or rejection reason, and can nudge stuck ones (diff §4.7 Upload quarantine monitor).

## Acceptance criteria
- [ ] Every endpoint is `system_admin` only: any other caller, PER-09 included, gets 403 (test per endpoint, including a PER-09 of every project)
- [ ] `GET /api/v1/admin/system/uploads?status=verifying|rejected|expired&reason=&project=`: rows (project code, file id, original filename, size, SHA-256, status, reason code, scanner signature, uploader id, created/updated times; paged) **only for projects where the caller holds a membership**, read under the normal project RLS of `oe_uploads_file`
- [ ] `GET /api/v1/admin/system/uploads/counts`: for every project (member or not) the number of uploads per status and reason code, from a count-only `SECURITY DEFINER` function of the T-0219 pattern (pinned `search_path`, `EXECUTE` revoked from `PUBLIC` and granted to the app role, `system_admin` checked inside, returns project id/code, status, reason and a number only). The function and the endpoint accept **only** project, status and reason filters, never a file id, SHA-256, filename or uploader (no existence oracle; test that such parameters are rejected with 422); covered by the ADR of T-0219, or an ADR in `docs/decisions/` (next free number) is written in this PR if T-0219 has not landed
- [ ] The uploads RLS policy is **not widened** and **no bypass role** (`BYPASSRLS`, superuser, `is_system_admin` widening) is used; the RLS-bypass contract tests stay green
- [ ] Contract test (PostgreSQL, as `kerp_app`): a `system_admin` without a membership on project B sees B's counts per status but no row of B (the list returns none, `project=B` returns none, recheck of a B file → 404), and a test proves the count function returns numbers only
- [ ] Media-probe reasons of T-0169 appear once that task lands (reason codes are passed through, not enumerated here)
- [ ] `POST .../uploads/{file_id}/recheck` (member projects only; a file of a non-member project → 404) re-queues the check of a file stuck in `verifying` whose staging object still exists (else 409 `OBJECT_GONE`); audited
- [ ] `POST .../uploads/sweep?project=` queues T-0215's orphan sweep for that project now (housekeeping that returns no rows, exempt from the membership rule of §4.7; allowed for any project); audited
- [ ] Rejected rows show 'object deleted' (bytes are removed at rejection, TD-397); there is no purge action
- [ ] Module `README.md` and docs updated
- [ ] All quality gates green (see CLAUDE.md §Quality gates)
