## Goal
Restore a deleted project from its archive, refusing anything that fails verification (documents-and-mdr §Restore).

## Acceptance criteria
- [ ] `POST /api/v1/admin/projects/restore` `{archive_id | file_id, mode: deleted|new}` (`system_admin`, else 403); an uploaded zip comes through presigned uploads and must be `available` (scanned)
- [ ] From a registry `archive_id`, **both modes** go through T-0237's content-access gate (live project: live membership; deleted project: membership held at deletion), else 404 before any job is queued and nothing is written. From an uploaded `file_id` zip, `system_admin` only: the caller already holds the bytes (documents-and-mdr §Access, TD-396); the `file_id` must be readable by the caller under the normal upload RLS and ORM scope (their own upload), else 404, so the premise is enforced, not assumed; test: another user's `file_id` → 404 and nothing is queued
- [ ] Validation before any write: every file SHA-256, per-table checksums, schema versions (newer → 422; older → per-module upgrade steps), every audit chain verified; any failure writes nothing and reports why
- [ ] Test: from an `archive_id`, a `system_admin` who was not a member of the deleted project at deletion gets 404 on mode `deleted` and nothing is written; a former member succeeds; from an uploaded zip of the same archive a `system_admin` without membership succeeds
- [ ] Mode `deleted`: the soft-deleted rows still exist; each module's provider (restore side of the contract) verifies that its live rows match the archive manifest (per-table counts and checksums, file SHA-256s) and then **un-deletes them in place** (ids unchanged, never an upsert from the archive), together with exactly the memberships of `admin.service.memberships_at_deletion` (T-0237: `direct` rows soft-deleted by the deletion only); any difference → 409 `ARCHIVE_DIFF` listing the differing tables, nothing written; live project → 409
- [ ] Test: a membership removed before the deletion stays removed after the restore (it is not revived), while the memberships revoked by the deletion are live again (audited in `project-members:<project>`); also not revived: an earlier soft-deleted `team_link` row of the same user and persona, and an earlier removed PER-07 grant on another site (PR #137 review round 3)
- [ ] Batch job; counts and file hashes compared after the restore and stored as the job result; audited
- [ ] Module `README.md` and docs updated
- [ ] Restored image files get their derivatives regenerated by T-0247's job before they count as `available`
- [ ] All quality gates green (see CLAUDE.md §Quality gates)
