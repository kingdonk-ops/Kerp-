## Goal
Restore a deleted project from its archive, refusing anything that fails verification (documents-and-mdr §Restore).

## Acceptance criteria
- [ ] `POST /api/v1/admin/projects/restore` `{archive_id | file_id, mode: deleted|new}` (`system_admin`, else 403); an uploaded zip comes through presigned uploads and must be `available` (scanned)
- [ ] Validation before any write: every file SHA-256, per-table checksums, schema versions (newer → 422; older → per-module upgrade steps), every audit chain verified; any failure writes nothing and reports why
- [ ] Mode `deleted` needs the requesting admin to have held a membership on the project when it was deleted (a membership row revoked by that deletion, read through the admin module's `service.py`; a deleted project has no live memberships and the membership API answers 404 on it, T-0014); otherwise 404 (documents-and-mdr §Access, TD-396)
- [ ] Test: a `system_admin` who was not a member of the deleted project gets 404 on mode `deleted` and nothing is written; a former member succeeds
- [ ] Mode `deleted`: the soft-deleted rows still exist; each module's provider (restore side of the contract) verifies that its live rows match the archive manifest (per-table counts and checksums, file SHA-256s) and then **un-deletes them in place** (ids unchanged, never an upsert from the archive), together with the memberships revoked by the deletion; any difference → 409 `ARCHIVE_DIFF` listing the differing tables, nothing written; live project → 409
- [ ] Batch job; counts and file hashes compared after the restore and stored as the job result; audited
- [ ] Module `README.md` and docs updated
- [ ] Restored image files get their derivatives regenerated by T-0247's job before they count as `available`
- [ ] All quality gates green (see CLAUDE.md §Quality gates)
