## Goal
TD-165 (screens): the reviewer works a queue of submitted inspections; the inspector sees what was returned and why, fixes it and resubmits.

## Acceptance criteria
- [ ] Reviewer queue (RegisterPage) of `SUBMITTED` inspections in the project with anchor path, inspector, submitted time and round
- [ ] The review view shows answers in template order, photos with annotation overlays, conflict flags and comments per answer; the reviewer adds answer comments and approves or returns (reason required in the dialog)
- [ ] The inspector's view lists `RETURNED` inspections with the return reason and the comments per answer; after edits the inspector resubmits
- [ ] The submit button shows the pending upload count and stays disabled until attachments are complete and no answer has an open conflict flag
- [ ] "Download PDF" requests the report (T-0158), polls the job and opens the presigned link
- [ ] Review actions are online only; offline they are disabled with an explanation
- [ ] All strings through `t()`; component tests for approve, return and resubmit
- [ ] `frontend/README.md` updated
- [ ] Records and signatures with `time_confidence = UNVERIFIED_REBOOT` show a high-contrast warning badge (queue row, review view, inspection detail) with a tooltip asking to check the shift log; every shown time is `occurred_at`; component test for the badge
- [ ] A "self-approved" badge on inspections a PER-06 approved themselves, and a "provisional client signature" badge while a co-sign is `provisional_wet` (T-0174); each co-signature shows its mode; component tests
- [ ] All quality gates green (see CLAUDE.md §Quality gates)
