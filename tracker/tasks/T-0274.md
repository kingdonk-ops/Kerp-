## Goal
A `system_admin` session reads and writes project-scoped records of every project of its own tenant without a membership (user decision 2026-11-21, ADR 0016, diff §4.1), enforced in PostgreSQL RLS and mirrored by the ORM scope, while non-admins and other tenants stay exactly as isolated as today.

## Acceptance criteria
- [x] `rls_policy_sql` emits `project_isolation_policy` as USING and WITH CHECK `tenant_id = app.current_tenant_id AND (project_id IS NOT DISTINCT FROM app.current_project_id OR (project_id IS NOT NULL AND <app.is_system_admin is 'true'>))`, using the existing setting constants (`TENANT_SETTING`, `PROJECT_SETTING`, `SYSTEM_ADMIN_SETTING`) and the existing `SYSTEM_ADMIN_SQL` expression; `tenant_level_read_policy`, `allowed_projects_read_policy` and the special policies (membership, admin_grant, access_request, project_invite, team, tenants census) are unchanged
- [x] Tenant-level rows (`project_id IS NULL`) keep today's rule: a project-bound session, admin or not, never writes one (test)
- [x] A new **additive** Alembic revision replaces the policy on every table that has it, with the frozen SQL inlined per the T-0033 convention (no import of the live helper); downgrade re-creates the previous frozen policy; T-0033's drift test passes against the new revision. No edit of T-0033's revisions
- [x] ORM scope (`app/core/tenancy/scope.py`) mirrors the policy: project-scoped models are not filtered by project for an `is_system_admin` context of the same tenant; `site_node_ids` is `None` (unrestricted) for that context; SQLite suite covers the same cases
- [x] `TenancyContext` and `tenancy/README.md` docstrings updated ("reads no project-scoped record" removed); `app.is_system_admin` is still bound only by `resolve_request_scope` from the caller's admin grants (JWT `sub` + `tid`), never from claims, headers, query or body (test: a forged `is_system_admin` claim or `X-*` header changes nothing)
- [x] The four RLS-bypass contract tests of T-0007 (SAQ workers, cross-module service calls, raw-SQL aggregations, migrations) are **updated, not weakened**, to assert the new rule exactly, on PostgreSQL as `kerp_app`: a non-admin member of project A still gets 404 / zero rows on project B; a `system_admin` with no membership reads and writes rows of A and B; a `system_admin` of tenant A sees zero rows of tenant B and cannot insert a tenant-B row (tenant B seeded by the fixture); an unbound session still sees nothing; a worker job bound without `is_system_admin` stays project-exact
- [x] Cross-tenant: `app.is_system_admin = 'true'` with a different `app.current_tenant_id` grants nothing of the first tenant (test)
- [x] `rls_enforcement_problems` still reports no table without the policy
- [x] Module `README.md` and docs updated
- [x] All quality gates green (see CLAUDE.md §Quality gates)
