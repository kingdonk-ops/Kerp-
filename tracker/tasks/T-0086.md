## Goal
`backend-pg` (the full backend suite on PostgreSQL 16 + PostGIS + ltree as the NOSUPERUSER
NOBYPASSRLS runtime role, with the coverage floor; ~5 min) is the CI critical path. Split it into
a matrix of parallel shards so the wall clock drops, without losing or duplicating any test and
without weakening the coverage floor (TD-512, user request 2026-11-21).

## Acceptance criteria
- [x] `backend-pg` is a matrix of N shards with the same service containers, initdb/app-role and fsync-off steps, env, action pins and `persist-credentials: false` as before; each shard runs `pytest -n auto` on its slice
- [x] The split is deterministic and by test file, done by an in-repo splitter (no new dependency): every `backend/tests/**/test_*.py` lands in exactly one shard; balanced by stored approximate per-file durations, unknown files get a default weight
- [x] `scripts/tests` prove on the real tree that the shards partition every test file (no file lost, none duplicated) and that the shard count matches the `ci.yml` matrix
- [x] CI proves it on the real collection: `pytest --collect-only` of the full suite equals the disjoint union of the shards' collections (node ids), or the job fails
- [x] Each shard writes its coverage data with the per-shard floor off; a `backend-pg-coverage` job combines every shard's data (`coverage combine`) and enforces the same floor as `pyproject.toml` (read from it, not copied) on the combined result, and fails if any shard's data is missing
- [x] `ci-gate` needs and checks `backend-pg` (all shards) and `backend-pg-coverage`; any shard failing, cancelled or skipped when the backend should run fails the gate; `scripts/ci_gate.py` and its tests updated
- [x] `e2e` and `backend-publish` wait for all shards and the coverage job; the e2e services still equal the shard job's services (`scripts/tests/test_workflows.py`)
- [x] `docs/WORKFLOW.md` documents the sharding, the splitter and how to rebalance
- [x] All quality gates green (see CLAUDE.md §Quality gates)

- Branch `task/T-0086-backend-pg-shards`. TODO TD-512 (the request) is linked; TD-513 raised: the SQLite `backend` job (~6.5 min) is now the CI critical path.
- `backend-pg` keeps its job id, so `needs.backend-pg.result` is GitHub's matrix aggregate (any shard failing/cancelled/skipped = not success) and `ci-gate`, `e2e`, `backend-publish` keep depending on it; the new `backend-pg-coverage` job is added to all three and to `scripts/ci_gate.py` `EXPECTED`.
- Split: `scripts/shard_tests.py` (stdlib only, no new dependency), by file, greedy heaviest-first onto the lightest shard, weights = summed JUnit (xunit1) seconds per file from a green 4-shard CI run (`scripts/shard_weights.json`); unknown files weigh the mean. `fail-fast: false` so every failing shard is reported.
- Hardening: the old `|| [ $? -eq 5 ]` (no tests collected) allowance is gone for the shards, and an empty slice fails before pytest could fall back to `testpaths` (the whole suite).
- Coverage: shards run `--cov-fail-under=0` and upload `.coverage.pg-K` (`include-hidden-files: true`, `if-no-files-found: error`); `backend-pg-coverage` requires exactly `SHARDS` data files, `coverage combine`s them and runs `coverage report --fail-under=<floor>` with the floor parsed from `backend/pyproject.toml` addopts (90). The SQLite job still enforces the floor by itself as before.
