## Goal
`backend-pg` (the full backend suite on PostgreSQL 16 + PostGIS + ltree as the NOSUPERUSER
NOBYPASSRLS runtime role, with the coverage floor; ~5 min) is the CI critical path. Split it into
a matrix of parallel shards so the wall clock drops, without losing or duplicating any test and
without weakening the coverage floor (TD-512, user request 2026-11-21).

## Acceptance criteria
- [ ] `backend-pg` is a matrix of N shards with the same service containers, initdb/app-role and fsync-off steps, env, action pins and `persist-credentials: false` as before; each shard runs `pytest -n auto` on its slice
- [ ] The split is deterministic and by test file, done by an in-repo splitter (no new dependency): every `backend/tests/**/test_*.py` lands in exactly one shard; balanced by stored approximate per-file durations, unknown files get a default weight
- [ ] `scripts/tests` prove on the real tree that the shards partition every test file (no file lost, none duplicated) and that the shard count matches the `ci.yml` matrix
- [ ] CI proves it on the real collection: `pytest --collect-only` of the full suite equals the disjoint union of the shards' collections (node ids), or the job fails
- [ ] Each shard writes its coverage data with the per-shard floor off; a `backend-pg-coverage` job combines every shard's data (`coverage combine`) and enforces the same floor as `pyproject.toml` (read from it, not copied) on the combined result, and fails if any shard's data is missing
- [ ] `ci-gate` needs and checks `backend-pg` (all shards) and `backend-pg-coverage`; any shard failing, cancelled or skipped when the backend should run fails the gate; `scripts/ci_gate.py` and its tests updated
- [ ] `e2e` and `backend-publish` wait for all shards and the coverage job; the e2e services still equal the shard job's services (`scripts/tests/test_workflows.py`)
- [ ] `docs/WORKFLOW.md` documents the sharding, the splitter and how to rebalance
- [ ] All quality gates green (see CLAUDE.md §Quality gates)
