## Notes
- ci-gate logic lives in `scripts/ci_gate.py` (reads `toJSON(needs)` + event name), so it is unit-tested in `scripts/tests/test_ci_gate.py`. Every needed job must be `success`. `skipped` is accepted only when it is expected: the component is absent (`detect` output `false`), or the job is `backend-publish` on a non-push event. If `detect` is not `success`, every job must be `success`. The same test file also checks `ci.yml` line by line, without a YAML dependency: ci-gate needs every job, only `backend-publish` has `packages: write`, every `uses:` is a 40-hex SHA, and every checkout sets `persist-credentials: false`.
- `backend-publish` runs on push only. It needs `backend` and `backend-image`, so an image is never published unless the tests and the smoke test passed. `backend-image` now runs with the workflow-level `contents: read`.
- SHAs were resolved with `gh api repos/<repo>/commits/<tag>` for the major tags already in use, and the exact tag is in the trailing comment. All actions in ci.yml are pinned, including `actions/*`, not only `docker/*`. The base image digest is the multi-arch OCI index digest of `python:3.12-slim-bookworm`, read from the Docker Hub registry (manifest sha256 recomputed and matched). It is written into each `FROM` instead of an `ARG`, so Dependabot's docker updater can see it. A test requires both stages to use one digest-pinned base.
- I chose Dependabot over Renovate because it needs no app install. It covers the docker digest (minor/major Python bumps are ignored, so the image stays on 3.12) and the GitHub Actions SHAs. It cannot refresh the uv-compiled `requirements*.lock`, so that work is TD-047 (AC 5 left unticked for that half).
