## Goal
An anonymous caller must not be able to keep a known user locked out of password login
(repo review 2026-11-13, finding 1). Lock per tenant + e-mail + client IP; keep a looser
per-account backstop so rotating IPs cannot guess passwords without limit. Also remove the
test-only lockout API (finding 6, lockout/revocation part).

## Context
Repo review 2026-11-13 (quality + security), owner-accepted.
Finding 1 (security, medium): login lockout keyed by tenant + e-mail only; 6 bad passwords then one per lock expiry (~4 requests/hour at the 15-min cap) keep a known user locked out indefinitely, since attempts during a lock are refused before the password is checked. Finding 6 (part): `ProgressiveLockout.failures` / `RevocationStore.failure_count` are used only by tests. Implements TD-191 (keying + atomic begin) and TD-138 (per-client throttling, trusted proxy).

## Acceptance criteria
- [x] Login lockout subject includes the client IP (`request.client.host`; uvicorn rewrites it from `X-Forwarded-For` only for peers in `FORWARDED_ALLOW_IPS`)
- [x] Per-account backstop policy (50 free failures per 24 h, then the usual escalation) applies across all client IPs
- [x] A correct password from client B succeeds while client A is locked out; success clears both counters
- [x] `ProgressiveLockout.failures` and `RevocationStore.failure_count` (protocol + both stores) removed; tests read the counter directly
- [x] `ProgressiveLockout.begin` check-and-count is atomic (one Lua script on Redis; the in-memory store under its lock); a burst test shows no request passes once the lock is armed (TD-191)
- [x] Auth README and backend README document `FORWARDED_ALLOW_IPS` (the image's uvicorn trusts only 127.0.0.1 by default; deployments behind a proxy must set it — see TD-222)
- [x] Magic-link request lockout deliberately unchanged (mailbox-flood cap); its DoS is TD-224
- [x] All quality gates green

## Notes
- Atomic `begin()` uses a Redis WATCH/MULTI optimistic transaction (`RevocationStore.begin_attempt`), not a Lua script: same guarantee, and fakeredis in the test suite has no Lua (it would need the extra `lupa` dependency). The race is covered deterministically by `test_redis_attempt_retries_when_another_attempt_interleaves` (fails on the old code); the thread-burst test is a contract check only.
- `begin_attempt` replaces `lock_remaining` / `count_failure` / `set_lock`; `failure_count` / `ProgressiveLockout.failures` removed; tests assert behaviour (lock / no lock) instead.
- Per-client key falls back to `unknown` when `request.client` is missing.
- Review round 1 (#55): the backstop still lets an attacker hold an account locked at ~1 request per lock after the first 51 failures; docs corrected and the residual raised as TD-225 (owner decision). Also: WATCH retries capped (32, then fail closed), lock read with PTTL rounded up, `FORWARDED_ALLOW_IPS=*` warning, IPv6 /64 keying raised as TD-226.
