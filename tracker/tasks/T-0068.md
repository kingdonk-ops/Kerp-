## Goal
An anonymous caller must not be able to keep a known user locked out of password login
(repo review 2026-11-13, finding 1). Lock per tenant + e-mail + client IP; keep a looser
per-account backstop so rotating IPs cannot guess passwords without limit. Also remove the
test-only lockout API (finding 6, lockout/revocation part).

## Context
Repo review 2026-11-13 (quality + security), owner-accepted.
Finding 1 (security, medium): login lockout keyed by tenant + e-mail only; 6 bad passwords then one per lock expiry (~4 requests/hour at the 15-min cap) keep a known user locked out indefinitely, since attempts during a lock are refused before the password is checked. Finding 6 (part): `ProgressiveLockout.failures` / `RevocationStore.failure_count` are used only by tests. Implements TD-191 (keying + atomic begin) and TD-138 (per-client throttling, trusted proxy).

## Acceptance criteria
- [ ] Login lockout subject includes the client IP (`request.client.host`; uvicorn rewrites it from `X-Forwarded-For` only for peers in `FORWARDED_ALLOW_IPS`)
- [ ] Per-account backstop policy (50 free failures per 24 h, then the usual escalation) applies across all client IPs
- [ ] A correct password from client B succeeds while client A is locked out; success clears both counters
- [ ] `ProgressiveLockout.failures` and `RevocationStore.failure_count` (protocol + both stores) removed; tests read the counter directly
- [ ] `ProgressiveLockout.begin` check-and-count is atomic (one Lua script on Redis; the in-memory store under its lock); a burst test shows no request passes once the lock is armed (TD-191)
- [ ] Auth README and backend README document `FORWARDED_ALLOW_IPS`
- [ ] All quality gates green
