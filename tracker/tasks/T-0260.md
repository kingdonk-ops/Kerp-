## Goal
Equipment that needs calibration is active only with a verified current certificate (diff §5 *Activation gate*), with QA verification through the queue of T-0181.

## Acceptance criteria
- [ ] Rule set `equipment.activate` with a `locked` system-default `check` rule (ADR 0004 §5): `!equipment.requires_calibration || (has(equipment.active_cert) && equipment.active_cert.verification_status == 'verified' && equipment.active_cert.document_id != null && equipment.active_cert.expiry_date >= context.today)`; every transition to `active` calls `run_checks(context, "equipment.activate")`; failure → 422 with the reason
- [ ] New equipment (single create and import) starts `out_of_service`; existing rows per TD-414 (planner default: certs with a document count as verified, `verification_source = 'pre_gate'`)
- [ ] Creating equipment that requires calibration without a cert document sends a high-priority notification to the project's QA reviewer persona (T-0181 setting)
- [ ] A cert uploaded by a user without QA authority gets `verification_status = pending_qa_verification` even when SAQ OCR matches, and creates a verification item (`equipment_calibration`) with a deep-link notification; a QA reviewer's own upload creates a pending item like any other, decided by a different QA-authority holder; it is auto-verified only when the project's effective `allow_self_approval` (T-0140) is true, and is then flagged `self_approved` in the ledger (TD-431)
- [ ] The T-0112 OCR-discrepancy QA review is redirected into the queue (TD-416)
- [ ] Provider for `equipment_calibration`: details (specs, dates), OCR values, cert history (superseded certs), `apply_approved` (verify, supersede + lock prior, set active through the gate), `apply_rejected` (stays inactive)
- [ ] Equipment without a calibration file stays `out_of_service` and is not selectable in inspections (T-0112 gate) (test)
- [ ] Module `README.md` and docs updated
- [ ] All quality gates green (see CLAUDE.md §Quality gates)
