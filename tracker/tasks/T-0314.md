## Goal
The flags of issues.md §5 and the gate facts of §6, so completion, MDR and portal consumers decide from configuration, not code.

## Acceptance criteria
- [ ] At raise `visibility`, `mdr_effect` and `completion_effect` are copied from the pinned revision; an issue with `origin = client` or raised by an `is_internal = false` account is always `client` (override to `internal` → 422)
- [ ] `POST /api/v1/issues/{id}/flags` changes `visibility` / `mdr_effect` / `completion_effect` only for the project's QA authority or PER-09 (others 403), with a non-blank reason (422); the ledger entry holds old value, new value, reason and actor; the issue history shows it
- [ ] For every `is_internal = false` caller, internal issues are absent from lists, counts, search and ref resolution and answer 404 by id; internal-only links (`escalated_from_issue_id`) are omitted; an internal issue cannot be assigned to an external account (422, TD-442 default) (tests with synthetic external PER-15 and subcontractor accounts)
- [ ] Internal callers still see and count internal issues (QMS KPIs, T-0160 tiles) (test)
- [ ] `issues.service.gate_facts(scope)` returns the open issues of the scope with type, `punch_category`, `completion_effect`, `mdr_effect` and status, registered in the rule context schema (ADR 0004 Addendum F) of `work_anchor.complete` (consumed by T-0124) and `mdr.compile` (E-05-05); no cross-module table access
- [ ] `issues.service.mdr_register(scope)` returns the NCR / concession register rows: `client` issues with `mdr_effect` `blocks` or `register_only`, never `excluded`, `void` or `internal` (test)
- [ ] Module `README.md` and docs updated
- [ ] All quality gates green (see CLAUDE.md §Quality gates)
