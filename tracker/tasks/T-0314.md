## Goal
The flags of issues.md §5 and the gate facts of §6, so completion, MDR and portal consumers decide from configuration, not code.

## Acceptance criteria
- [ ] At raise `visibility`, `mdr_effect` and `completion_effect` are copied from the pinned revision; an issue with `origin = client` or raised by an `is_internal = false` account is always `client` (override to `internal` → 422)
- [ ] `client_seen_at` (nullable) and `client_seen_channel` on `oe_issues_issue`, set once and never cleared; `issues.service.mark_client_seen(issue_ids, channel)` (channel e.g. `api | offline_pull | portal | pdf_export | mdr`) is idempotent and the first value wins (test: a second call with another channel changes nothing)
- [ ] Every issue read by an `is_internal = false` account through the issues API (list, detail) and every issue delivered to such an account's device in the offline pull calls `mark_client_seen` in the same request (test)
- [ ] For every `is_internal = false` caller, internal issues are absent from lists, counts, search and ref resolution and answer 404 by id; links that point to or from an internal issue (`escalated_from_issue_id`, `upgraded_from_issue_id`, `successor_issue_id`) are omitted (test); an internal issue cannot be assigned to an external account (422, TD-442 default) (tests with synthetic external PER-15 and subcontractor accounts)
- [ ] Internal callers still see and count internal issues (QMS KPIs, T-0160 tiles) (test)
- [ ] `issues.service.gate_facts(scope)` returns the open issues of the scope with type, `punch_category`, `completion_effect`, `mdr_effect` and status, registered in the rule context schema (ADR 0004 Addendum F) of `work_anchor.complete` (consumed by T-0124), `mdr.compile` (E-05-05) and `closeout.final_handover` (E-04-10); no cross-module table access
- [ ] MDR gate rule (issues.md §6, TD-445): evaluated against the shipped default rule, the MDR facts block on open issues with `mdr_effect = blocks` only; tests: an open Cat A punch with `mdr_effect = excluded` does not block `mdr.compile` but does block `work_anchor.complete`; an open Cat B punch with `mdr_effect = blocks` blocks `mdr.compile`; system-default punch templates carry `default_mdr_effect = blocks`
- [ ] `issues.service.mdr_register(scope)` returns the NCR / concession register rows: `client` issues with `mdr_effect` `blocks` or `register_only`, never `excluded`, `void` or `internal`, and calls `mark_client_seen(rows, "mdr")` itself (tests)
- [ ] Other client-facing outputs (portal E-07-xx, inspection PDF exported by an external account T-0158/T-0159, shared saved views E-01-01) get issues through the service and call `mark_client_seen`; documented in the module README as the contract for consumers
- [ ] Module `README.md` and docs updated
- [ ] All quality gates green (see CLAUDE.md §Quality gates)
