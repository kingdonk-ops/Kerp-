## Goal
Make the PostgreSQL + RLS backend run (14–25 min, serial, every test migrates up and down on the
one shared `kerp_test` database) as fast as the SQLite run after T-0081, while keeping every test
on real, committed PostgreSQL with RLS exactly as production gets it.

## Acceptance criteria
- [x] Once per test session (per xdist worker) the owner role builds two templates: `kerp_tmpl_head_<worker>` (upgrade head as the runtime role + fixture tenants seeded) and `kerp_tmpl_empty_<worker>` (a copy of the source database: extensions and schema owner, as `infra/postgres/initdb` creates them); nothing stays connected to a template
- [x] Each test that needs a migrated database gets its own `CREATE DATABASE … TEMPLATE kerp_tmpl_head_<worker>`, dropped at teardown (`WITH (FORCE)`); tests that run migrations themselves (`test_migrations.py`, revision-targeted upgrades) copy `kerp_tmpl_empty`
- [x] `tests/db_support.py:database_url()` and `tests/audit_support.py:tamper()` point at the per-test database (runtime role `kerp_app` for the app, owner for tamper); RLS, REVOKEs, ledger triggers and grants come from the template unchanged
- [x] Database names are unique per xdist worker; the PostgreSQL job runs `pytest -n auto --durations=25`
- [x] CI Postgres runs with `fsync`, `synchronous_commit` and `full_page_writes` off, set by an `ALTER SYSTEM … ; SELECT pg_reload_conf()` step (service `options` cannot pass server flags)
- [x] The 90 % coverage floor applies to the PostgreSQL run (`--no-cov` removed there); the SQLite run keeps it too (it is the agents' local gate)
- [x] Database-level grants (`GRANT ALL ON DATABASE … TO kerp_app`, which `CREATE DATABASE … TEMPLATE` does not copy) are re-issued on every per-test copy and template
- [ ] `make test-pg` / `make test-pg-all` still work locally against docker-compose (the owner role can create databases); `test-pg-all` runs with `-n auto`
- [x] RLS bypass (T-0007), frozen migration DDL (T-0033) and CEL conformance (T-0017) tests unchanged and green; no test skipped, xfailed or weakened
- [x] `backend/README.md`, `docs/WORKFLOW.md` updated
- [x] All quality gates green (see CLAUDE.md §Quality gates)

## Out of scope
- Per-test SAVEPOINT/outer-transaction rollback (rejected 2026-11-21: `SET LOCAL` context would leak across units of work, the side-write pool and `tamper()` cannot see uncommitted rows, concurrency tests need real commits).

## Notes
- PostgreSQL already runs every test SQLite runs plus the PG-only ones (CI 2026-11-21: 2,899 passed / 1 skipped vs SQLite 2,822 / 78).
- Argon2 test parameters and session-cached JWT keys were considered and dropped: passwords use stdlib scrypt (0.04 s/hash) and the default EdDSA key generates in 0.3 ms.
- Implementation: `tests/pg_databases.py` (templates, per-test create/drop, owner/runtime URLs); `tests/db_support.py:database_url()` / `postgres_url()` hand out the test's database; `tests/audit_support.py:migrated_database` copies the head template (or migrates in place if the test already made an empty database), and `tamper()` runs as the owner on the test's own database; `tests/conftest.py` autouse fixtures drop each test's database and the worker's templates. Direct `POSTGRES_URL` uses in `test_rls_bypass.py`, `test_rls_multi_project.py` and `test_pg_extensions.py` now call `postgres_url()`. Without `KERP_TEST_OWNER_URL` the old shared-database path is kept.
- Local results (PostGIS 16 container, durability on, 3 workers, CPU shared with a second run): 2,869 passed / 6 skipped in 7 min 15 s, coverage 97.91 %; the 5 Redis-gated tests pass with Redis (19 passed in `test_jobs_saq.py` + `test_rls_bypass.py`); the 6th skip (MinIO, TD-208) skips in CI too. No per-test database or template left behind. SQLite suite unchanged: 2,797 passed / 78 skipped, coverage 97.40 %.
- `make test-pg` / `make test-pg-all` were not run against docker-compose in this session (same env and owner role as CI; left unticked for the reviewer or a local check).
