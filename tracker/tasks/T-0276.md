## Goal
A `system_admin` reaches any project of the tenant from the top-bar picker and sees all of them in the All-Projects portfolio scope (ADR 0016, diff §4.1, §6.1).

## Acceptance criteria
- [x] The T-0042 picker lists every project `GET /api/v1/me/projects` returns; projects with `access: system_admin` carry an "Admin access" badge (`t()`), searchable like the rest
- [x] Landing after sign-in unchanged for non-admins; a `system_admin` with no membership lands on the last-used project, else the picker (not the lobby)
- [x] All-Projects scope for a `system_admin` covers every project; actions needing `A` or `S` are not shown unless the API's capabilities for that project include them
- [ ] Component and e2e tests (admin without membership opens project B; non-admin still sees only its projects)
- [x] All strings through `t()`
- [x] Module `README.md` and docs updated
- [x] All quality gates green (see CLAUDE.md §Quality gates)

## Notes
- 2026-11-21 (planner): T-0042 (done) is not edited; this task extends its picker.
- 2026-11-21 (implementer): The badge is option text ("code — name (Admin access)"), so native type-ahead finds it, plus a visible text badge next to the picker for the picked project that describes the `<select>` (`aria-describedby`, tooltip). Not colour-only; axe-audited in `App.a11y.test.tsx`.
- Landing: an admin with no membership and no remembered project gets scope `none`, a disabled "Choose a project…" option and a prompt on the home page; the lobby redirect still fires only for an empty list. An admin with memberships falls back to its first member project, not the first admin-access one.
- All-Projects is offered when any project has `access: system_admin` (`offersPortfolio`). Gap: an admin that is a member of every project without a portfolio persona is not recognisable (TD-499).
- A/S: `MyProject` has no capabilities field, so `RequireCapability` derives them from the API's personas + `access` by mirroring the backend persona matrix (TD-500, spec-gap). No A/S actions exist in the UI yet; the gate is for the screens that add them.
- Component tests cover "admin without membership opens project B" and "non-admin sees only its projects"; there is no `e2e/` suite on dev, so the Playwright journey is TD-501 (criterion left open).
