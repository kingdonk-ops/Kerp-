## Goal
System admins see how big the deployment is and whether its services are healthy, without any project row leaving RLS (diff §4.7 Deployment stats).

## Acceptance criteria
- [ ] Every endpoint is `system_admin` only: any other caller, PER-09 included, gets 403 (test per endpoint, including a PER-09 of every project)
- [ ] `GET /api/v1/admin/system/stats`: projects (active, soft-deleted), users (active, deactivated), enrolled devices (active, revoked), plus every count a registered stats provider returns; numbers only, never ids, names or rows
- [ ] Stats-provider registry: each module registers a provider in its own `service.py`; the admin module never queries another module's tables (import-boundary test)
- [ ] Counts that RLS would hide come from count-only `SECURITY DEFINER` functions (pinned `search_path`, `EXECUTE` revoked from `PUBLIC` and granted to the app role, the ADR 0012 pattern); an ADR in `docs/decisions/` (next free number) is written in this PR; the RLS-bypass contract tests stay green and a test proves the functions return a number only
- [ ] Object-store totals per storage class (`STANDARD`, `GLACIER_IR`, `DEEP_ARCHIVE`, other): object count and bytes, computed by a `batch` SAQ job (paginated listing, cached with its `as_of` time) and refreshable on demand (one run at a time)
- [ ] `GET /api/v1/admin/system/health`: PostgreSQL, Redis, object store (head bucket), malware scanner (T-0218 `ping`); each with timeout (≤ 2 s, planner default), status `ok | degraded | down` and latency; never a host name, connection string or credential (test)
- [ ] Every call is audited in the tenant chain `admin-system:<tenant>` with `event` set
- [ ] Module `README.md` and docs updated
- [ ] All quality gates green (see CLAUDE.md §Quality gates)
