## Goal
System admins see how big the deployment is and whether its services are healthy; counts only, read under normal RLS (diff §4.7 Deployment stats).

## Acceptance criteria
- [x] Every endpoint is `system_admin` only: any other caller, PER-09 included, gets 403 (test per endpoint, including a PER-09 of every project)
- [x] `GET /api/v1/admin/system/stats`: projects (active, soft-deleted), users (active, deactivated), enrolled devices (active, revoked), plus every count a registered stats provider returns; numbers only, never ids, names or rows
- [x] Stats-provider registry: each module registers a provider in its own `service.py`; the admin module never queries another module's tables (import-boundary test)
- [x] Counts run under the caller's normal RLS, which shows a `system_admin` every project of the tenant (ADR 0016, T-0274); no `SECURITY DEFINER` function and no bypass role; test: a `system_admin` without memberships gets the counts of every project, and the RLS-bypass contract tests stay green. A table that still hid rows from a `system_admin` session gets a TODO, not a bypass
- [x] Object-store totals per storage class (`STANDARD`, `GLACIER_IR`, `DEEP_ARCHIVE`, other): object count and bytes, computed by a `batch` SAQ job (paginated listing, cached with its `as_of` time) and refreshable on demand (one run at a time)
- [x] `GET /api/v1/admin/system/health`: PostgreSQL, Redis, object store (head bucket), malware scanner (T-0218 `ping`); each with timeout (≤ 2 s, planner default), status `ok | degraded | down` and latency; never a host name, connection string or credential (test)
- [x] Every call is audited in the tenant chain `admin-system:<tenant>` with `event` set
- [x] Module `README.md` and docs updated
- [x] All quality gates green (see CLAUDE.md §Quality gates)
