## Goal
A new master ITP revision reaches the anchors that have not started the affected lines, without ever touching signed evidence (quality-and-inspection.md §ITP authoring, assignment and propagation *Propagation*; T-0119).

## Acceptance criteria
- [ ] Instance edit (`PATCH /api/v1/qms/itps/{id}/lines`): PER-06 adds a line from the pinned template or another published one, or retires a line, only while that line is **unstarted** (TD-429: `PENDING`, no `inspection_request`, no answers, no sign-off entry); any other line → 409 `ITP_LINE_STARTED`; sets `is_customized = true`; audited with the line diff
- [ ] `POST /api/v1/qms/itp-templates/{key}/propagate` `{revision_id}` (published revision only): dry run returns, per active instance of the template, the lines to re-pin, add and retire and the lines kept because they are started; customized instances are listed separately with their diff
- [ ] Confirm (PER-06; PER-13 for tenant masters): non-customized instances get their unstarted lines re-pinned/added/retired; for each customized instance the request carries `keep_customizations | apply_master`; `apply_master` still never changes a started line; one ledger entry per instance (T-0006) with old/new revision and line counts
- [ ] **T-0119 immutability:** a line with any sign-off ledger entry, or in `SUBMITTED`, `INSPECTED_PASSED`, `INSPECTED_FAILED`, `RE_INSPECT`, `RETURNED` or `LOCKED_FOR_TURNOVER`, is never re-pinned, edited or retired; contract test over every state
- [ ] Publishing a revision never propagates by itself; the instance keeps its pin until the wizard confirms (spec: records pin `template_revision_id`)
- [ ] Runs as a `batch` SAQ job for large projects; idempotent on retry
- [ ] Module `README.md` and docs updated
- [ ] All quality gates green (see CLAUDE.md §Quality gates)
