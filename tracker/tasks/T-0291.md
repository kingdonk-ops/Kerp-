## Goal
Make the formal sign-offs that exist in Phase 1 require T-0289's attestation, and show it on paper (quality-and-inspection.md §Signing attestation). Later consumers adopt it in their own tasks (T-0184 shelf-life, TQ in E-05-04, MDR in E-05-05).

## Acceptance criteria
- [ ] Inspection approve (T-0150), single-row `H`/`W` sign-off (T-0119 / T-0114) and internal_qa substitution approval (T-0185) call `attest()` with their registered kind; without a valid grant → 401 `REAUTH_REQUIRED` and nothing changes (tests per consumer)
- [ ] The offline single-row `H`/`W` sign-off arriving by sync calls `attest_offline()` (T-0310) instead; a `signer_inactive` sign-off leaves the point unreleased (test)
- [ ] Bulk close-out of `R`/`S`/`M` rows (TD-095), inspection return and the inspector's submit are not attested (TD-433 default); client co-sign keeps its own verification modes
- [ ] Inspection PDF (T-0158) prints per sign-off an attestation block: signer name and persona, "on behalf of <name>" when `on_behalf_of_user_id` is set, intent statement text and version, re-auth method, signed time (and occurred time + confidence offline), device id, IP, and any flags (`intent_outdated`, `grace_exceeded`, `signer_inactive` printed as "not effective"); entries without attestation (Pilot-0) print "no attestation recorded"
- [ ] The block layout is a shared renderer in `signing` that the MDR dossier (E-05-05) reuses (documented in the module README)
- [ ] Inspections and materials call the signing service only (no cross-module table access)
- [ ] Module `README.md` and docs updated
- [ ] `ncr_close_verify` (NCR effectiveness verification, T-0313) requires a signing grant and records the attestation like the other formal kinds (issues.md §4.2)
- [ ] All quality gates green (see CLAUDE.md §Quality gates)
