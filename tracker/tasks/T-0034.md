## Goal
ADR 0004 §2, §3, §5, §7 and Amendment B on top of the rule store built in T-0018: every project
gets a copied default rule set it can change, delete or add to; mandatory gates ship locked.

## Acceptance criteria
- [x] System defaults load from versioned seed files `backend/app/modules/<m>/rules/defaults/*.yaml` into the `system` layer; reloading the same version is idempotent (ADR 0004 §2.1)
- [x] The `system` layer is stored as **per-tenant copies** (`tenant_id` = the tenant, `project_id` NULL, `layer = system`) written at tenant creation and when a seed version changes; no tenant-less rows exist, so the T-0007 tenant RLS policies apply unchanged (test: tenant B cannot read tenant A's system rows; a new seed version reaches every tenant's system layer)
- [x] Creating a tenant seeds the `tenant` layer from the system defaults; creating a project, or first enabling a module on a project, **copies** the tenant layer (or the chosen client pack's sets) into the `project` layer; a later change to a default does not change an existing project copy (test) (ADR 0004 §2.2–2.3)
- [x] Project operations: edit (expression, params, severity, label, order), disable/enable, soft-delete that keeps `rule_key` (`deleted_at`), add (`origin_rule_key` NULL), reset one rule or the whole set to the current default; each change creates a new version and an audit-ledger entry (ADR 0004 §3)
- [x] A `locked` rule cannot be deleted, disabled or changed at the project layer (409); the project can still add new rules to the same set (ADR 0004 §5)
- [x] Unlocking a locked rule happens only at the tenant layer: PER-13 requests with an ADR reference, a second, different approver confirms (TD-116 decision: until `approval_routes` (E-06-07) exists, the second approver is a different PER-13 or PER-01 user); both steps audit-ledgered; a single person cannot complete an unlock (ADR 0004 §5, Amendment B)
- [x] Permissions per ADR 0004 §7: tenant `check` rules PER-13, other kinds PER-01; project `check` rules PER-06, other kinds PER-09; PER-09 can never disable, delete or change a `check` rule (SoD); everyone else 403
- [x] Module `README.md` and docs updated
- [x] All quality gates green (see CLAUDE.md §Quality gates)
