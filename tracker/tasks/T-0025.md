## Notes
- Shells live in `frontend/src/shells/` (usage + semantics: `frontend/src/shells/README.md`); no module page uses them yet, no route added.
- **RegisterPage**: quick filter + per-column contains filters, column visibility, CSV export (RFC 4180, formula-injection guard) and saved views — all client-side over the loaded rows. Saved views are local (`localSavedViewStore` on the preferences storage, per user + register). Server-side views TD-179, PDF/full-result export TD-180, server filter/sort/paging TD-182.
- **DetailPage**: gate banner (`open|passed|hold|blocked` + reasons), ARIA tabs routed via `?tab=`, lazy audit-log tab (TanStack Query) with AI-source badge. Audit and gate data come through props (`AuditSource`, `GateStatus`) because no endpoints exist yet (TD-181); tests use fakes.
- **Dynamic Form Renderer**: reuses the existing one-engine CEL runtime (`src/lib/cel`, T-0017) through a `RuleEvaluator` seam; no new dependency. Fail closed on every rule (visible_if → hidden, required_if → required, validation → blocked); hidden fields are sanitised and visibility runs to a fixpoint. Implements visible_if, required, required_if and validation. Shared field-type registry / dual runtime (T-0110) TD-177; calculated fields and range rules TD-178; localisation of template content TD-183 (decision).
- Interpretation: an empty field is absent from `fields`, so rules referencing it error (`NO_SUCH_KEY`) and fail closed; templates guard with `has(fields.x)`. Empty optional fields skip their own validation.
- Review round 1: own-property reads in the form engine/renderer (prototype-named keys); rule evaluation catches a malformed values/context as `INVALID_ARGUMENT` (fail closed); `SavedViewStore.key` + remount on store identity change; tests for the CSV tab/CR guard and the visibility non-convergence path; unparsable audit timestamps shown as-is; gate reasons keyed by index.
