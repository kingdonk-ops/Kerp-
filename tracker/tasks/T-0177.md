## Goal
The server half of the user's offline action time design (diff §6.4.1), split out of T-0148 (PR #51 review round 3).

## Acceptance criteria
- [ ] For every pushed mutation: same `clock_session_id` as the push → `occurred_at = server_sync_time − (device_sync_monotonic_ms − monotonic_ms)`, `MONOTONIC_RECONSTRUCTED`; same session as a carried anchor whose token verifies (T-0147: HMAC over server time, `clock_session_id` and the client `monotonic_ms`) → `anchor.server_time + (monotonic_ms − anchor.monotonic_ms)`, `MONOTONIC_RECONSTRUCTED`; otherwise `clock_skew_ms = server_sync_time − device_sync_wall_time`, `occurred_at = device_wall_time + clock_skew_ms`, `SKEW_ADJUSTED`, or `UNVERIFIED_REBOOT` when |skew| > 2 min (planner default threshold); online API actions → `VERIFIED_ONLINE` (user, 2026-11-13)
- [ ] A `sync` service function returns the five values (`occurred_at`, `recorded_device_at`, `synced_at`, `clock_skew_ms`, `time_confidence`) and hands them to the owning module's service with each applied mutation; other modules (inspections, signing) store them through their own services
- [ ] Answer and answer-comment rows store the five values (additive migration through the `inspections` service; raw evidence never overwritten; column placement planner default)
- [ ] Audit entries for offline actions carry the five values in their hashed payload; the T-0006 ledger table is not altered (planner default; no core-table ADR)
- [ ] The offline-window check uses `occurred_at`
- [ ] Offline-grace soft check (planner rule from PR #73 review, diff §4.2): when a pushed mutation's `occurred_at` is later than its device session's `session_expires_at + offline_grace_hours` (T-0038, T-0044), it is still applied but flagged `grace_exceeded: true` in the push result and the audit payload, for review of possibly tampered or rooted devices; boundary test
- [ ] Tests with fake monotonic and wall clocks: a tablet wall clock set to 2022 reconstructs the exact time via monotonic; an anchor token for another `clock_session_id` or `monotonic_ms` is ignored; a reboot gives `SKEW_ADJUSTED`, or `UNVERIFIED_REBOOT` above 2 min; boundary at exactly 2 min
- [ ] `sync` `README.md` and docs updated
- [ ] All quality gates green (see CLAUDE.md §Quality gates)
