## Goal
SAQ over Redis (replaces ARQ); separate interactive (OCR/barcode) and batch (MDR/P6) queues (diff §3).

## Acceptance criteria
- [x] Both queues process; priority honoured
- [x] Worker container runs
- [x] `oe_jobs_job` uses `BaseRecordMixin` and has an RLS policy, with no RLS exemption; the worker binds tenant and project from the SAQ job kwargs before reading the row; polling another tenant's or project's job returns 404 (ADR 0007 rule 1)
- [x] The job row is committed before the SAQ job is enqueued; a rolled-back request leaves no queued SAQ job (test); a sweep re-enqueues rows stuck in `queued` with no SAQ job (test) (rule 2)
- [x] Each job kind declares its queue (`interactive` or `batch`); enqueue routes to it (rule 3)
- [x] Handlers are `async`, registered per module and picked up by the loader; heavy libraries are imported inside the handler (T-0022 lint passes) (rule 4)
- [x] A failing handler stores only a sanitised, length-bounded error (no traceback) and logs the full traceback with the request id (test) (rule 5)
- [x] `POST` enqueue and `GET /jobs/{id}` poll return kind, queue, status, progress, message, result, error; handlers report through `update(progress, message)`
- [x] All quality gates green (see CLAUDE.md §Quality gates)

- 2026-11-13 (implementer): Built on SAQ 0.26 (`saq[redis]`), which caps redis-py below 8, so
  the lock moves redis 8.1.0 -> 7.4.1; one mypy-only line in `core/auth/revocation.py`
  (`int(str(ttl))`, same idiom as its `count_failure`) keeps `mypy --strict` green on it.
  - Queues: `<prefix>:interactive` and `<prefix>:batch`, one SAQ worker each in one process
    (`python -m app.modules.jobs.worker`), own concurrency (settings, default 4 / 1). "Priority"
    = isolation: a busy batch queue never delays an interactive job (real-Redis test).
  - Rule 1: `run_job` binds tenant/project from the SAQ kwargs (and `use_tenancy` for the
    handler) before reading the row; no RLS exemption. Rule 2: `create_job` stages a ref on
    the session; an `after_commit` hook hands it to a `LoopDispatcher` (API lifespan / worker),
    `after_rollback` drops it. Rule 3: `JobKind.queue`. Rule 4: `register_job` in
    `<module>/jobs.py`, imported by the module loader (`import_job_handlers`, T-0011 loader).
    Rule 5: `JobError` message or `Internal error (<Class>)`, <= 500 chars; traceback logged
    with the enqueuing request id.
  - `POST /api/v1/jobs` only accepts kinds registered with `api=True` (422 otherwise).
  - Sweep: `service.sweep(db, broker, scopes)` exists and is tested, but nothing schedules it:
    under RLS the worker cannot list scopes yet -> TD-155. Capability checks on the API ->
    TD-156. Worker liveness probe + re-queue on shutdown -> TD-157.
  - Worker container: compose service `worker` (profile `worker`, `make worker`) runs the
    backend image with the worker command; CI's image smoke test imports the worker module.
    Docker was not available locally, so the container itself was not started here; the
    worker process was run locally against PostgreSQL 16 + Redis 7 and stops cleanly on
    SIGTERM (also covered by `tests/test_jobs_saq.py`).
  - Real-Redis tests (`tests/test_jobs_saq.py`) skip without `KERP_REDIS_URL` (SQLite step) and
    run in CI's PostgreSQL step, which has Redis.
  - Migration `0007_jobs` (down_revision `0006`, T-0010's membership scope); it was `0006` until T-0010 merged
    first.

- 2026-11-13 (implementer, review round 1): pending job refs are staged with their
