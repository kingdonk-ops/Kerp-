## Goal
SAQ over Redis (replaces ARQ); separate interactive (OCR/barcode) and batch (MDR/P6) queues (diff §3).

## Acceptance criteria
- [ ] Both queues process; priority honoured
- [ ] Worker container runs
- [ ] `oe_jobs_job` uses `BaseRecordMixin` and has an RLS policy, with no RLS exemption; the worker binds tenant and project from the SAQ job kwargs before reading the row; polling another tenant's or project's job returns 404 (ADR 0007 rule 1)
- [ ] The job row is committed before the SAQ job is enqueued; a rolled-back request leaves no queued SAQ job (test); a sweep re-enqueues rows stuck in `queued` with no SAQ job (test) (rule 2)
- [ ] Each job kind declares its queue (`interactive` or `batch`); enqueue routes to it (rule 3)
- [ ] Handlers are `async`, registered per module and picked up by the loader; heavy libraries are imported inside the handler (T-0022 lint passes) (rule 4)
- [ ] A failing handler stores only a sanitised, length-bounded error (no traceback) and logs the full traceback with the request id (test) (rule 5)
- [ ] `POST` enqueue and `GET /jobs/{id}` poll return kind, queue, status, progress, message, result, error; handlers report through `update(progress, message)`
- [ ] All quality gates green (see CLAUDE.md §Quality gates)
