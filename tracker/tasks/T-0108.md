## Goal
Default configuration packs become **client packs** (ADR 0003 §4): applying one via `POST /assets/config-packs/{key}/apply` seeds a project's breakdown template, terminology, item types, form/ITP templates, numbering patterns, register types, import mapping profiles and rule sets. The pack's rule sets are the source of the project rule copy (ADR 0004 §2).

## Acceptance criteria
- [ ] Starting packs `remediation-rsw` (Site/Asset/RSW/Item), `remediation-fep` (adds Activity with budget qty) and `cui-line` (Scope/Job Package/Line) ship as data; each provisions a project whose level defs carry the right roles (asset-and-tagging.md §Client packs)
- [ ] Applying a pack seeds all eight parts (level defs, terminology pack, item types, templates, numbering patterns, register types, mapping profiles, rule sets) idempotently; re-applying a pack key does not duplicate anything
- [ ] Pack rule sets are copied into the project rule layer through the T-0034 copy mechanism (ADR 0004 §2.3); mandatory gates arrive `locked`
- [ ] Two packs can be applied to one project side by side (e.g. remediation + CUI) without key clashes (ADR 0003 Amendment 1)
- [ ] Copied templates and types are copies with a `derived_from` link, not inheritance (TD-107); upgrade offers are T-0137
- [ ] `asset_management` `README.md` and docs updated
- [ ] All quality gates green (see CLAUDE.md §Quality gates)
