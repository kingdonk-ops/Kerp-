## Goal
Make the per-project module toggle usable. Today `GET/PUT /api/v1/modules` read the project from the session's tenancy binding, which no request binds (TD-122), so both always answer 404 and the Phase 0 exit journey (T-0027) cannot toggle a module. Serve the toggle API from the **`projects` module** (`backend/app/modules/projects/router.py`) on the project path: the route binds the project with `projects.service.bind_project` (T-0217) and calls `app.core.module_loader.service` (`project_states`, `set_enabled`) for the state; module → core imports are allowed, core never imports `app.modules` (`backend/app/core/auth/README.md`, `post_auth.py`). Writes are guarded by the admin capability (TD-129).

## Acceptance criteria
- [ ] The routes live in `backend/app/modules/projects/router.py` (with schemas in the projects module or reused from `app.core.module_loader.schemas`); `app/core/module_loader/router.py` loses the project-less routes and gains no import from `app.modules`
- [ ] `app/core` still imports nothing from `app.modules` (test: a static import scan of `backend/app/core/**` fails on any `app.modules` import)
- [ ] `GET /api/v1/projects/{project_id}/modules` lists every loaded module in dependency order with `name`, `version`, `depends_on`, `toggleable`, `enabled` for that project; a member of the project with `V` gets 200; a non-member gets 404; another tenant's project id gets 404 (tests)
- [ ] `PUT /api/v1/projects/{project_id}/modules/{name}` with `{"enabled": bool}` requires the `admin` capability on that project (PER-09, or `system_admin` per ADR 0016 through `bind_project` once T-0275 gives it every project's `admin` capability; test both): a member without it gets 403, a non-member 404 (tests)
- [ ] Unchanged semantics from T-0011, now reachable: unknown module 404; `toggleable=false` module 409 with a detail naming the module; a change that breaks a dependency 409 naming the module to change first; each change appended to the project's `project_modules` audit chain with the caller's user id; enable listeners run (validation copies module default rule sets) (tests with a test-only toggleable module in the test package, never in `app/modules/`)
- [ ] The module gate (`module_gate`) still answers 404 for a disabled module on a project-bound request (existing test kept green)
- [ ] The project-less `/api/v1/modules` routes are removed (they could never succeed); `backend/tests/test_module_toggle.py`, `test_openapi_export.py` and `test_module_loader.py` (line ~254 asserts the `/api/v1/modules` path) updated to the new path without weakening any assertion; `npm run gen:api` re-run and committed
- [ ] TD-129 resolved (guard in place); TD-122 noted as resolved for the module toggle API (the gate's project-less skip stays documented); TD-127 (toggle UI) points at the new path
- [ ] `backend/app/core/module_loader/README.md` (Toggle API, Until TD-122) and `backend/app/modules/projects/README.md` updated
- [ ] All quality gates green (see CLAUDE.md §Quality gates)
