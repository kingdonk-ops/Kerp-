## Goal
TD-170 and TD-185: one settings record per deployment, edited by System admins, read by sync, field clients and project creation.

## Acceptance criteria
- [ ] Tenant-level settings record (`BaseRecordMixin`, RLS) with `offline_window_days` (1–14, default 7) and defaults for new projects: status `ACTIVE`, site timezone `Australia/Perth`, currency `AUD`, locale `en-AU` (diff §4.4)
- [ ] `GET /api/v1/settings/deployment` readable by any signed-in user (field clients need the offline window); `PATCH` only by a `system_admin` (else 403); values validated (IANA zone, ISO 4217, BCP 47, 1–14)
- [ ] Project creation (T-0012 service) takes its defaults from these settings instead of literals; project status stays `ACTIVE|ON_HOLD|CLOSED` (master §4.1 amendment)
- [ ] Changes are written to the audit ledger
- [ ] Region is not a tenant setting: it stays deployment configuration (diff §4.4); documented in the README
- [ ] Module `README.md` and docs updated
- [ ] All quality gates green (see CLAUDE.md §Quality gates)
