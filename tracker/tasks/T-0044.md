## Goal
TD-170 and TD-185: one settings record per deployment, edited by System admins, read by sync, field clients and project creation.

## Acceptance criteria
- [x] Tenant-level settings record (`BaseRecordMixin`, RLS) with `offline_window_days` (1–14, default 7) and defaults for new projects: status `ACTIVE`, site timezone `Australia/Perth`, currency `AUD`, locale `en-AU` (diff §4.4)
- [x] `GET /api/v1/settings/deployment` readable by any signed-in user (field clients need the offline window); `PATCH` only by a `system_admin` (else 403); values validated (IANA zone, ISO 4217, BCP 47, 1–14)
- [x] Project creation (T-0012 service) takes its defaults from these settings instead of literals; project status stays `ACTIVE|ON_HOLD|CLOSED` (master §4.1 amendment)
- [x] The service always passes the four values explicitly; the DB-side defaults for `site_timezone` and `status` added by T-0063 stay as fallback literals equal to the shipped defaults (no DB default for currency/locale)
- [x] Changes are written to the audit ledger
- [x] Region is not a tenant setting: it stays deployment configuration (diff §4.4); documented in the README
- [x] Module `README.md` and docs updated
- [x] Setting `max_checkout_clock_skew_s` (integer seconds, default 5; user, 2026-11-13; bounds 1–300, planner default) readable by field clients and the sync service (diff §4.4, §6.4.1)
- [x] Setting `offline_grace_hours` (integer, default 24; product owner, 2026-11-14; bounds 1 to 24 × `offline_window_days`, planner default) readable by field clients: how long after the server session ended an offline device may keep unlocking with the PIN and queueing changes (diff §4.2 Offline grace, §4.4)
- [x] All quality gates green (see CLAUDE.md §Quality gates)

  `admin` would be a dependency cycle. `projects` now `depends_on=("settings",)`. Spec gap
  raised: TD-295. The IANA / ISO 4217 / BCP 47 validators moved unchanged from
  `projects/schemas.py` to `app/core/locale.py` (shared by both modules).
- Table `oe_settings_deployment` (migration `0017`), standard RLS, at most one live row per
  tenant; no row until the first change (GET answers the shipped defaults, reading never
  writes). Field names: `offline_window_days`, `offline_grace_hours`,
  `max_checkout_clock_skew_s`, `default_status`, `default_site_timezone`,
  `default_currency_code`, `default_locale`. Integers strict; the grace bound (<= 24 x window)
  is checked on the merged result (422, never clamped) and by a DB CHECK.

  added its DB-side defaults yet; when it does they must use those constants.
