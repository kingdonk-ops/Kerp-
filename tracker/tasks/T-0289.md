## Goal
Formal sign-offs (ITP hold/witness, inspection approval, substitution, shelf-life extension, TQ) become attributable electronic signatures: the signer re-authenticates, accepts an explicit intent statement, and the ledger entry records who, what, when, where from and how (quality-and-inspection.md §Signing attestation). Backend half, online path; offline sync acceptance T-0310, ceremony UI T-0290, consumers T-0291.

## Acceptance criteria
- [ ] Code-declared registry of formal sign-off kinds (`itp_hold_release`, `itp_witness`, `inspection_approve`, `substitution_approve`, `shelf_life_extension_approve`, `tq_approve`), each with an intent-statement i18n key and an integer `intent_version`; every version of a kind is kept with its `effective_from` (UTC) and i18n key so the version current at a given time can be resolved (used by T-0310); consumers register their kind from their own `service.py`
- [ ] `POST /api/v1/signing/reauth` `{method: signing_pin | password, secret, kind, record_type, record_id, record_version}` → single-use signing grant bound to user, session id, kind and record id + version, TTL from the registry entry `signing_reauth_ttl_minutes` (default 5, 1–15, declared here on T-0230); wrong secret → 401 with the T-0162 per-signer lockout (signing PIN) or the T-0068 lockout (password); every failure audited without the secret
- [ ] The T-0162 signing PIN is open to every user (not only PER-15): set or reset online only within 15 minutes of a fresh sign-in (password, SSO or magic link), Argon2id hash in `oe_identity_signing_pin`, never in any response, pull scope or export (existing T-0162 tests extended)
- [ ] `attest(context, kind, record, grant, intent)` in `signing/service.py` (online path; `reauth_method` `signing_pin | password`): refuses a missing, expired, used or mismatched grant (401 `REAUTH_REQUIRED`), an intent version other than the current one (409 `INTENT_STATEMENT_OUTDATED`) or `intent_accepted` not true (422); it never grants authority: the caller's persona, site scope, credentials and `run_checks` are checked by the consumer as before. The offline path (`device_pin_offline`, no grant, flags instead of 409) is T-0310
- [ ] Ledger payload `attestation` (inside the T-0119 entry, so the ledger hash format and `v` are unchanged): `{v: 1, kind, intent_key, intent_version, locale, intent_text, intent_sha256, reauth_method (signing_pin | password | device_pin_offline), reauth_at, signed_at (server UTC), occurred_at and time evidence (diff §6.4.1) for offline, device_id, ip, ip_source (request | sync), user_agent_family, on_behalf_of_user_id, delegation_id, flags (`grace_exceeded | intent_outdated | signer_inactive`, empty online)}`; the intent text is rendered on the server in the signer's locale
- [ ] IP from the request as resolved by uvicorn behind `FORWARDED_ALLOW_IPS` only (never a client-supplied header otherwise); test that a spoofed `X-Forwarded-For` from an untrusted peer is ignored
- [ ] Impossible under impersonation (ADR 0015): `/signing/reauth` and every attested sign-off refuse a request context with an impersonator (403 `IMPERSONATION_ACTION_FORBIDDEN`, unit test with such a context until T-0277 exists); the routes are classified `S` for T-0278's route contract; a `system_admin` without the qualified persona is still refused by the consumer (ADR 0016)
- [ ] Tests: replayed grant, grant for another record version, another user's grant, expired grant, wrong-locale render, intent-version history resolved at a past instant, attestation present in the ledger and verified by `verify_chain`
- [ ] Module `README.md` and docs updated
- [ ] All quality gates green (see CLAUDE.md §Quality gates)
