## Goal
Review finding 7 (lean): uploads, notifications, saved_views and validation routers each carry a copy of `_bind_project`, while the documented guards (`require_capability`, `require_hold_release`, `get_project_access`, `CurrentAccess`) are used by no endpoint and cannot work until the request session binds a project (TD-122). Owner decision 2026-11-15: one helper in `access.py`, delete the unused guards.

## Acceptance criteria
- [x] `access.bind_project(principal, grants, session, project_id) -> ProjectAccess` keeps today's order: non-member 404, rebind the session, deleted project 404
- [x] The four routers use it and check their own capability; their existing tests pass unchanged
- [x] `require_capability`, `require_hold_release`, `get_project_access`, `CurrentAccess` and their tests are removed; the auth README describes the helper instead
- [ ] All quality gates green

## Notes
- 2026-11-16: The helper lives in `app/modules/projects/service.py` as `bind_project(session, principal, grants, project_id, *, require=None)`, not in `access.py`: it needs the deleted-project check (`get_project`), and core never imports a module. `require` keeps the old order (404 non-member, 403 missing capability, then rebind, then 404 deleted). saved_views and validation keep one-line wrappers (they map the access to a `Viewer` / the personas). The guard tests in `test_access.py`/`test_admin.py` now assert the same matrix and SoD decisions on `ProjectAccess` (`has`, `can_release_hold`); new helper tests in `test_projects.py`.
