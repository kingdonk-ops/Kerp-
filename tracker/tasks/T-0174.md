## Goal
Co-sign mode (iii) (user, 2026-11-13): a drawn signature on the inspector's tablet counts only after the client confirms it.

## Acceptance criteria
- [ ] A wet co-sign (drawn image + typed name + PER-15 account picked by the inspector) is stored as a ledger entry with `verification_mode = provisional_wet`; the image is stored via T-0016 and never deleted
- [ ] The named PER-15 is notified in-app (T-0019; push later); `POST .../cosignatures/{id}/confirm` by that PER-15 in their own session writes a `client_confirmed` entry linked to the provisional one; `.../reject` needs a non-blank reason and returns the inspection (`RETURNED`) with it; anyone else → 403
- [ ] Approve of an inspection whose template has `requires_client_signature` fails with `CLIENT_SIGNATURE_PROVISIONAL` while its co-sign is provisional (test)
- [ ] Reminder to the client after 24 h and to the project's PER-06 after 72 h; a provisional signature never expires on its own (planner defaults; fake-clock tests)
- [ ] The review data and the PDF expose the provisional state for the badge (T-0153, T-0158)
- [ ] `signing` `README.md` and docs updated
