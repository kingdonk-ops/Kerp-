- 2026-11-10: Manifest contract: `MANIFEST = ModuleManifest(name, version, depends_on, toggleable, default_enabled)` plus the six required files. Start-up fails with every problem listed (missing file/MANIFEST, name != directory, bad version, unknown or cyclic deps, non-toggleable module depending on a toggleable one, missing `router`). Module routers mount at `/api/v1/<name>` (`_` -> `-`) in dependency order; `modules` is reserved for the toggle API.
- 2026-11-10: Per-project toggle: new table `project_module_setting` (BaseRecordMixin, `project_id NOT NULL`, unique per tenant/project/module, project RLS; additive migration `0004`, after T-0008's `0003`). Enabled = own setting (row, else `default_enabled`) AND all dependencies enabled; `set_enabled` refuses (409) changes that would break a dependency and audits each change on the project's `project_modules` chain. Every route of a toggleable module gets a gate dependency that answers FastAPI's own `404 {"detail": "Not Found"}` while the module is off for the request's project; requests without a project are not gated. Project context comes from the `DbSession` tenancy binding (T-0007 seam).
- 2026-11-10: Toggle API `GET /api/v1/modules`, `PUT /api/v1/modules/{name}` (401 without an authenticated active user via `CurrentPrincipal`; 404 without project context). Admin-tier guard deferred to RBAC: TD-129. UI: TD-127. First-insert race on the unique constraint: TD-128.
- 2026-11-10: Shared-file edits kept minimal: `app/main.py` (`create_app(..., modules_package=...)` + one `install_modules` call), `app/core/db.py` (one model import line), `tests/test_migrations.py` (head is now `0004`; renumbered from `0003` on rebase onto T-0008).
- 2026-11-10: TD-036 resolved: `tests/test_lint_get_db.py` (AST walk; only `app/core/db.py` may name `get_db`). TD-018 resolved: `npm run gen:api` (= `python -m app.openapi` + openapi-typescript 7) with `frontend/src/api/openapi.json` and `schema.ts` committed; CI drift check is TD-126.
- 2026-11-10: Fix round 1 (PR #32): both toggle endpoints now take `CurrentPrincipal` (app.core.auth.deps) and `set_module` records `actor_id=principal.user_id`. Verified with real login tokens: no token -> 401 `WWW-Authenticate: Bearer`; invalid token -> 401 `Bearer error="invalid_token"`; deactivated user with an unexpired token -> 401; valid tenant-level token -> 404. **Depends on TD-122:** T-0008 fills `get_tenancy_context` with the tenant and user but no project, so today every authenticated request is tenant-level: the toggle API answers 404 and the route gate never fires (no project, so not gated). Both become live only when TD-122 binds the authorised project. The project-bound paths are tested through the `get_tenancy_context` + `get_current_user` overrides. TD-129 now covers only the admin capability tier. Default `CurrentPrincipal` on module routers: TD-130.
