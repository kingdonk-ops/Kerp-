ADR 0003 Amendment 1 (and the CLAUDE.md section 6 wording it prescribes) says every root-to-leaf path has exactly one work-anchor node, never nested. Amendment 5 lets condition surveys and CUI scans sit on an inspection_anchor node with no work under it yet, and paths are built incrementally (P6 placeholders, imports), so a path can legitimately have zero work anchors for a while.

Planner default applied in docs/spec/modules/asset-and-tagging.md and T-0101 (not blocking): enforce **at most one** work-anchor node per path and never nested as a hard invariant on create/move/split/merge; a path with **no** work anchor is allowed; booking work (progress, time against a work anchor, completion gates) requires the work-anchor node on the path. Confirm, or say whether 'exactly one' must be enforced (e.g. at a project setting or on a leaf-level check).

- 2026-11-10: Decision (user, 2026-11-10): accept 'at most one per path, never nested'. Applied to ADR 0003 Amendment 1 and Consequences, asset-and-tagging.md, T-0101 and CLAUDE.md section 6 (TD-119).
