Raised from the PR #142 (T-0083) review. `backend/tests/pg_databases.py:_check_empty` refuses a source database (`kerp_test`) that still holds a schema, but it only inspects `pg_tables` in `public`. Leftover enum types, sequences, views or functions from an aborted shared-database run would pass and be inherited by every per-test copy. Widen the check to `pg_class` / `pg_type` / `pg_proc` objects in `public` (and to extra schemas in `pg_namespace` besides `public` and the system/extension ones), excluding objects owned by extensions (PostGIS, ltree) via `pg_depend` (deptype 'e'), and extend `tests/test_pg_databases.py` with a leftover type and a leftover view. Low risk today: the CI source is always freshly created from `infra/postgres/initdb`.
