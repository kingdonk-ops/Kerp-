Seen while running the full PostgreSQL suite for T-0012 review round 1 (local PostgreSQL 16 + PostGIS, kerp_app role): the test failed once in the full run and once in three isolated runs (`-k cancelled_or_timed_out`), with `(job.status, job.error) == ('running', None)`. T-0012 changes nothing in app/modules/jobs. The test cancels the task as soon as the row reads 'running'; the failure-marking write on CancelledError apparently does not always commit (e.g. the cancel lands while the start transaction or a session operation is in flight). Needs a look at run_job's cancellation path, not a looser test.
