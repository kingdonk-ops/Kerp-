Diff 4.1 says external invitees create their own password and company members use Entra ID SSO. T-0059's criterion is 'an active account without credentials whose e-mail is the invited one'. Implemented reading: 'credentials' = a local password or a linked Entra ID identity (auth.service.has_credentials); the is_internal flag is not checked, so a company-domain invitee who has never signed in can set a first password from the e-mailed link (the T-0077 reset already allows the same for any active account). Decide whether accept-with-password (and setup-preview) must answer INVITE_SIGN_IN_REQUIRED for is_internal accounts so staff always use SSO.
