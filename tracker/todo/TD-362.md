Planner defaults taken in T-0077 that the diff §4.2 does not state: (1) a third rejection code `PASSWORD_TOO_LONG` for passwords over 256 characters (the spec names only too short / too common); (2) a listed or context word with up to 6 leading/trailing digits or symbols is refused (`Password1!`, `kerp2026`), plus repetition and keyboard/counting runs; 'deployment name' is `KERP_APP_NAME` (core cannot read the settings module's tenant display name); (3) reset requests for an unknown address are audited as `password_reset_refused / unknown_account` without the address (magic links leave no record there), and a throttled call (429) is logged but not audited (it is refused before any database work); (4) rate-limit numbers per client (20 requests, 11 confirmations back to back) and per token (5 back to back, the 10th refused attempt kills the link). Confirm or adjust.
