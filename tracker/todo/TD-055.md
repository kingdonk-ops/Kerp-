Migrations run as the schema owner, and FORCE ROW LEVEL SECURITY makes the owner subject to the project policy, so an unbound data migration (UPDATE/backfill) silently touches zero rows. tests/test_rls_bypass.py pins this fail-closed behaviour. The first module that ships a data migration needs either a helper that iterates tenants/projects and binds app.current_tenant_id/app.current_project_id per batch, or a separate migration role with BYPASSRLS (decided in an ADR, since it widens privileges).

- 2026-11-10: Decision (user, 2026-11-10): Per-tenant/project backfill helper that binds scope per batch; no BYPASSRLS migration role. Build with the first module that ships a data migration.
