From the PR #154 (T-0331) review (non-blocking, low impact because the warning names the current project): the invite form fields stay editable while `send.isPending`. If the user edits during an in-flight request that comes back as a SoD 409, `onSuccess` sets `sod=true` after the edit has already withdrawn it, so the next send carries `confirm_sod: true` for a form the user never confirmed. Fix: disable the fieldset while pending, or compare the 409 against the submitted variables before arming the confirmation. Test: edit during a pending send that answers 409 SoD; the next POST carries `confirm_sod: false`.
