T-0342 refuses SUPERUSER/BYPASSRLS, unforced RLS tables and ledger UPDATE/DELETE/TRUNCATE. A runtime role that owns tables passes as long as FORCE and the ledger REVOKE/triggers are in place, but could undo them (TD-056). Local dev and CI's PostgreSQL shards still migrate as kerp_app (owner), so an ownership refusal would need those to switch to the T-0343 split first (ADR 0019).

- 2026-11-21: (implementer, T-0343) With migration 0039 and ADR 0019 the split works in production, and local dev / CI run with KERP_ENVIRONMENT development/test, where the startup check only warns; so the ownership check could ship now (warning in dev and the backend-pg shards, refusal in production). Verified by hand: a production API connected as kerp_owner (the table owner) starts today. Left out of T-0342 because its criteria name exactly the three checks.
