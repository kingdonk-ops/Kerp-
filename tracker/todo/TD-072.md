ADR 0004 (proposed) puts every rule set (check gates, handover activity digest, auto-link patterns) in one store with three layers: system defaults shipped in code, a tenant default set, and a per-project copy made at project creation. Projects can edit, disable, delete (tombstoned), add and reset rules; default upgrades are offered, never auto-applied; spec-mandated gates (calibration hard gate, open Cat A punch / NCR blocks completion) are locked. Decide before T-0018 starts. On acceptance: add the layering acceptance criteria to T-0018 (or a new S task after it), make T-0108 client-pack rule sets the default source, seed T-0124 gates as locked defaults, and include the rule store shape in the T-0131 freeze.

Open question inside this decision: unlocking a locked `check` rule is PER-13 Quality Director only (ADR 0004 sections 5 and 7); confirm whether it also needs a second approver via approval_routes, and confirm PER-01 owns the tenant defaults for non-check kinds.

- 2026-11-10: Decision (user, 2026-11-10): ADR 0004 accepted, amended: per-record override of a blocked check (requester + QA/QC Lead; if requester is QA/QC then Project Manager; if requester is PM then QA/QC; never self-approve; mandatory typed reason; saved to activity + audit ledger; approval bound to the exact values). Changing a locked rule needs the Quality Director plus a second approver. Validity checks evaluate on the inspection date, rerun live on edit and at submit; reports use completion snapshots. Backdating beyond N days (per project, default 7) needs a reason and is flagged on the report.
