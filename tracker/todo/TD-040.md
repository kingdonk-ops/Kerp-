To get identical client/server results, KERP's CEL wrappers decode every plain JSON number in an evaluation context as a CEL double (Python would otherwise make 20 an int and 20.5 a double; JS has only doubles). int64 must be sent as {"$int": "<decimal>"}, timestamps as {"$timestamp": "<RFC3339>"} (millisecond precision, JS Date). Results use the same encoding plus $uint, $duration and $double for NaN/Infinity. Sync payloads (T-0126) and form templates must follow this; confirm before the Designer (form templates) and sync ingest freeze it.
