T-0101: (1) after a move, and after a display_code_template change, display_code is recomputed in the request by loading the affected subtree (the whole project for a template change) into the session; O(nodes) memory and one UPDATE per changed row. Fine for thousands of nodes; a 100k-node project should do it in the SAQ batch queue. Projects without any display_code_template skip it. (2) Every tree mutation of a project is serialised by one advisory lock held to the end of the transaction, so a long import transaction blocks the project's other tree writers (not readers). If that hurts, lock per root subtree or chunk the import's transactions.
