Enterprise roadmap 2026-11-21, item 4 (after Pilot-0; spec diff §4.9 *SCIM provisioning*; ADR 0017). Planner defaults applied, not blocking:

1. **Users only.** `/Groups` is not supported (ServiceProviderConfig says so); Entra groups never map to personas or grants (diff §4.5).
2. **Create** is allowed: SCIM creates an account with no credentials, no memberships and no grants; `is_internal` is derived as usual (§4.1). Access still comes from invites, PER-09 assignments and team links.
3. **Deprovision:** `active = false` (PATCH/PUT) or `DELETE` deactivates (`is_active = false`, never a hard delete) and revokes every live session at once (T-0244's revoke). Devices are not revoked or wiped, so an offline outbox survives; it is not relied on that the outbox drains only after a fresh sign-in, because a later reactivation makes that possible. Instead the sync rules close the gap: offline formal sign-offs whose signer-standing window (TD-433 #4) contains the deactivation or the session revocation are kept as evidence but not effective, flagged `signer_inactive` and routed to QA review (T-0310); SCIM records these instants in T-0310's durable standing record, not only in the expiring Redis session index; other offline mutations follow the normal sync rules. A System admin may still revoke devices.
4. **Last active System admin:** deactivation is refused (409 SCIM error), audited, and every System admin gets an in-app notice.
5. **Matching:** `externalId` = Entra object id, linked like an SSO link (an account linked to a different oid → 409); `userName` = e-mail, case-insensitive; reactivation (`active = true`) restores sign-in but not sessions. SCIM never matches, updates or deactivates an `account_type = service` row (ADR 0017 §4), and only acts on `is_internal = true` accounts: a `userName` or `externalId` that matches an external (`is_internal = false`) account or a service account → 409 SCIM error, audited, account untouched, so an Entra user whose e-mail equals an external client's account cannot take it over or deprovision it.
6. **Tokens:** shown once, 256-bit random, stored as a hash, default lifetime 365 days (max 730), rotation keeps the old token valid for 24 h.
