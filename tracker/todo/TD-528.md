backend/app/modules/teams/service.py add_member checks live membership in Python before the insert, so a sequential duplicate returns False, but two concurrent adds of the same user (a double click or client retry) both pass the check and the second insert's unique violation reaches the client as 500 (same pattern as TD-128). Fix: lock the team row before the check or catch the unique violation and answer as for an existing member; PostgreSQL concurrency test.
