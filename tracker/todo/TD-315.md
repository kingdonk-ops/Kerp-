request_override accepts a blocking finding only from the record's latest run of the set that logged findings. run_checks logs failures only, so a later run in which every rule passed is invisible and an older finding can still be answered. The hash/rule-version binding makes this harmless (a stale override voids or never applies), but a per-run log (run_id, subject, set, passed) would let the request check be exact.
