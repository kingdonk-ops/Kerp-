Implementer defaults awaiting confirmation (ADR 0004 Amendment A.4, A.6; quality-and-inspection.md Per-record override):
1. Checked values: a check rule names its bound context paths in params.override_binding (e.g. fields.equipment_id, fields.spec_revision, fields.inspection_date); without it the whole record and fields are bound (any change voids). The hash is stored on every finding (oe_validation_finding.checked_values_hash, migration 0022) and copied to the override.
2. approver_user_id: set when the request names an approver or exactly one other holder of the routed persona exists; otherwise NULL and every other holder is notified and may decide.
3. A requester holding both PER-06 and PER-02 is routed to PER-02 (the QA/QC rule is applied first).
4. Requesting needs the C capability (view-only personas PER-15/PER-16 cannot request); any member reads.
5. Void also applies to a pending request and to a changed rule version (the override is bound to the rule as evaluated), not only to a changed hash; void is final.
6. The requester cannot reject (withdraw) their own request; there is no cancelled state in the frozen shape.
7. Binding roots are record, fields and project only (actor dropped in review round 1). Only a failing rule (outcome fail) can be overridden; a rule that could not be evaluated (error) cannot be requested and is never passed by an override.
8. Suggested, not built: warn at compile time when override_binding does not cover every context path the CEL expression reads (needs an AST walk of referenced paths).
