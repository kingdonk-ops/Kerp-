Planner default written into KERP-CONSOLIDATION-AND-DIFF.md §4.2 (Offline window) while applying TD-170 decision 14a (user, 2026-11-13), which set the window (tenant setting, default 7 days, maximum 14) but not what happens when it runs out. Default: the app keeps every queued change and stays readable, but refuses new edits until the user signs in online; it never deletes data. Alternatives: keep allowing edits and only warn, or lock the app completely. Used by T-0143. The other session/PIN/device details raised in PR #48 review were answered by the user on 2026-11-13 and are written into the spec as decisions.

- 2026-11-13: Decision (user, 2026-11-13): accept the default (queued data kept, new edits blocked after the offline window until an online sign-in) for the Capacitor/PWA field client until the full native Android app launches; that app will have a normal login system and its offline-expiry behaviour is decided then.
