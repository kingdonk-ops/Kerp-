backend/tests/pg_databases.py names its templates kerp_tmpl_empty_<worker> / kerp_tmpl_head_<worker> and its per-test copies kerp_t_<worker>_<n>. The names are global in the PostgreSQL cluster, so two sessions running 'pytest -n auto' against the same local server (two agent worktrees, each with its own KERP_DATABASE_URL database) drop and recreate each other's templates (DROP DATABASE ... WITH (FORCE)): a T-0230 run got 1141 errors 'template database kerp_tmpl_head_gw0 does not exist' while the same tests pass when run alone. CI is not affected (one run per server). Fix: put the source database name or a per-run token in the template and copy names.
