ADR 0002 lists AIP `unit-vectors/units-v1.json` + `terms/units.py` (store in SI, convert for display, one vector file for Python and TS) as a T-0110 port. Not done: the AIP clone was not available to the implementer and the slice had to fit size M. Today a `measurement` field declares its own `units` list and an answer is `{value, unit}` with `unit` in that list; nothing converts between units, and `range` compares `value` as entered, so a template that offers both `mm` and `in` with one range is wrong for one of them. Build `core/fields` units (catalogue beyond mm/in, bar/psi, degC/degF; conversion; `tests/contract` vectors on both runtimes) and make lint reject unknown unit codes and a range on a multi-unit field without a base unit.
