T-0059 added POST /api/v1/admin/invites/setup-preview and /accept-with-password for callers who are not signed in. The tokens are 256-bit, so guessing is not feasible, but (a) any client can make the server write one audit entry per refused call (the unmatched-token chain project-invites grows without bound), and (b) a holder of a valid link can try passwords against the policy without a cap (the reset link allows 5 refused passwords, PASSWORD_RESET_TOKEN_POLICY). Add a per-client lockout (ProgressiveLockout, like pwreset-confirm-client) and a per-link cap, with the per-client-IP limits of TD-138. Related: TD-372 (per-user throttle on signed-in invite refusals).
