T-0341 added a step budget (max_eval_steps, tests/contract/conformance_fixtures.json limits block) to the server evaluator (backend/app/core/cel/strict.py). @marcbachmann/cel-js 8.0 has parser limits (maxDepth, maxAstNodes, ...) but no evaluation step counter or abort hook, so the client applies only the static caps (macro nesting, nesting depth, expression length). A rule within the caps over very large context lists can still run long in the browser form (it fails closed on the server with EVAL_ERROR, which the client cannot predict). Options: a cel-js upstream hook, wrapping macro evaluation through a custom registered macro, or running client evaluation in a worker with a timeout. Until then, a budget-exceeded rule can pass on the client and be EVAL_ERROR on the server.
