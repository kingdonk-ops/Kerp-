Planner readings in T-0043 (diff 4.2, TD-203): (1) the startup check 'native list must not contain the deployment's web origin or any origin the SPA is served from' cannot know the SPA origin when KERP_WEB_ORIGIN is unset (then it is the API's own origin, known only per request), so settings refuse KERP_NATIVE_APP_ORIGINS without KERP_WEB_ORIGIN, and at request time the API's own origin never gets the body transport. (2) The task names login and refresh; the Android app's field workers sign in by magic link and rotate by PIN unlock, so redeem and /pin/unlock follow the same Origin rule (body out and in). On the web origin /pin/unlock still refuses a body token with 422 and /refresh ignores it. Confirm both readings.
