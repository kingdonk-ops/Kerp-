T-0016 has no delete endpoint. Content objects are keyed {tenant}/{project}/{module}/{sha256} and can be shared by several file rows (same bytes uploaded twice), so deleting an object needs a reference check across rows (and a soft-deleted-row retention policy). Separately, if uploads.verify fails with an internal error (storage outage) the job is 'failed' but the file stays 'verifying' forever and the sweep keeps its staging object: re-queue or reject such files (e.g. in sweep_orphans when the file's job is failed or older than N hours).
