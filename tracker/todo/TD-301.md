T-0038 planner-style defaults for what diff §4.2 leaves open: (1) the PIN is set by POST /devices/enrol {pin} once; re-sending it for a device that has one is 409 code PIN_ALREADY_SET; magic-link redeem no longer takes a PIN (422). (2) 'Changed after an online sign-in' = PUT /api/v1/devices/{device_id}/pin from a session bound to the device (every session starts with an online sign-in), no old PIN needed (forgotten PIN = sign in and set a new one), clears the failure counter, audited pin_changed; no recent-sign-in window. (3) /auth/pin/unlock answers 401 code PIN_INVALID (wrong PIN, retry) and PIN_EXHAUSTED (10th wrong PIN and after: sign in on the device), /auth/refresh 401 code PIN_REQUIRED. (4) Offline failures are reported only on /auth/pin/unlock (failed_offline, 0..1000, clamped to 10), applied only when the attempt runs (not on 429); a full sign-in on the device (new session bound to it) clears the counter, so unreported failures are dropped then. Confirm or adjust; T-0143 builds the client against this.
