title: "Password-reset and magic-link requests defer the account-dependent work to after the response: on a kept-alive connection the time until the next request is served may still differ by path (measure; move the deferred half to the SAQ worker if it does)"
kind: risk
status: open
tasks: [T-0077]

Both `POST /auth/password-reset/request` (T-0077) and `POST /auth/magic-link` (T-0057) answer a neutral `202` after doing identical work, and run the account lookup, token, store writes, mail row and audit entry in a Starlette background task after the response. The response itself is identical on every path. The background task still runs inside the same ASGI call, so an HTTP/1.1 client that sends a second request on the same kept-alive connection is served only after it finishes: the delay before that second response may differ between an active account (token, two store writes, mail row) and an unknown or deactivated one (lookup and audit entry only).

Not measured. If the difference is observable, hand the deferred half to the SAQ interactive queue (one identical job per request) instead of a background task, for both endpoints. The per-client and per-mailbox rate limits bound how many samples an attacker gets.
