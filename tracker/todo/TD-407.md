The addendum asks POST /api/v1/admin/users/{id}/resend-invite to send 'a fresh onboarding / magic-link email via notifications (T-0019)'. In the spec: invites are per project with their own re-send, token rotation and rate limits (diff §4.1 Re-send, T-0052/T-0059); sign-in magic links go only to PER-14 Field Workers (diff §4.2, T-0057); e-mail goes through core mail (§4.6), T-0019 is in-app notifications only.

Planner default (not blocking, T-0244): 409 unless the user is invited (first_login_at IS NULL, active). If the user has pending or expired never-accepted project invites, each is re-sent through the existing invite re-send (same rotation, audit and 1/60 s + 5/24 h limits; a System admin may re-send any). Otherwise, for an account without a password, the self-service password-reset e-mail (T-0077, neutral, single-use) is sent as the set-password mail. No magic link is ever sent by this action. Internal accounts expected to use SSO get no mail (409 SSO_ACCOUNT, planner default).

Confirm with the user.
