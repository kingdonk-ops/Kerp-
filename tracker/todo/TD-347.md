The T-0014 member API addresses a user, not a row: PUT sets the user's complete persona set, DELETE removes the user. T-0073 also requires that assigning an individual persona the user already holds through a team creates the individual row, so PUT cannot refuse a user who has team rows. Reading taken (most consistent with ADR 0008: PER-09 keeps full control of individual rows, derived rows are read-only): PUT and DELETE act on individual (direct) rows only and never touch team rows; DELETE of a user whose access on the project is only team-derived answers 409 code managed_through_team with the link ids (previously 404); DELETE of a user with both removes the individual rows (204) and the team rows stay. No PUT request can address a team row, so PUT never answers 409 for it. Confirm, or specify a per-row API if PUT must also 409.
