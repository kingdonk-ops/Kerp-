Product intake 2026-11-21, item 10. Some sign-offs need several people: multi-party hold points (client and principal on one ITP line), client acceptance of an MDR review revision (documents-and-mdr.md §Dossier builder), plan review approvals (E-07-04). Today each signer is a separate ledger entry and the consumer decides when the point counts as signed; there is no shared model.

Planner default (to spec when E-06-07 approval_routes is broken down; user to confirm):
- A **completion policy** per sign-off request: `all` (every named signer) or `any` (the first one), optionally `quorum N` (E-06-07 already names quorum).
- **Per-signer state**: `sent | viewed | signed | declined | expired | delivery_failed`, each change an event with time and actor; `delivery_failed` comes from the notification delivery result (see the notifications TODO raised with this intake), never counted as declined.
- The **aggregate state is derived** from the signer states and the policy, never stored and edited by hand. A `declined` under `all` ends the request as declined.
- Gating stays configuration: the consumer's `run_checks` rule set reads the derived aggregate as a fact.
- Each signature is still a T-0119 ledger entry with its T-0289 attestation (formal kinds) or co-sign mode (client).

Open: whether one shared `signing` request model serves hold points, MDR acceptance and plan review, or each consumer keeps its own.
