The spec has no detail on observability or HTTP security headers. T-0021 shipped these defaults (see backend/README.md): (1) X-Request-ID honoured if 1-128 chars of [A-Za-z0-9._-], else uuid4; echoed on every response. (2) JSON log lines: timestamp (UTC ISO 8601 ms, Z), level, logger, message, request_id + extra fields; access log 'kerp.access' with method, path (no query string), status, duration_ms; uvicorn access log disabled. (3) Headers: CSP "default-src 'none'; frame-ancestors 'none'" (KERP_CONTENT_SECURITY_POLICY), X-Content-Type-Options nosniff, X-Frame-Options DENY, Referrer-Policy no-referrer, HSTS 'max-age=31536000; includeSubDomains' only in production unless KERP_HSTS_ENABLED overrides (no preload). (4) /docs, /redoc, OAuth2 redirect get a relaxed docs CSP allowing FastAPI's default CDNs (cdn.jsdelivr.net, fonts.googleapis.com, cdn.redoc.ly). Open questions: confirm values; HSTS preload?; should /docs and /openapi.json be exposed in production at all?; trust an upstream proxy/LB request id header instead of X-Request-ID?; log shipping target/retention.
