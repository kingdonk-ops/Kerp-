Edge spec §6 amendments define the projects/memberships policy as 'project in app.allowed_project_ids or app.is_system_admin'. app.allowed_project_ids (T-0010) holds only the projects of portfolio personas and also widens project-scoped reads, and requests bind no project yet (TD-122). Taken literally, a PER-02/PER-09/PER-15 member could not read their own project's row (GET /projects, /me/projects, membership admin all 404 on PostgreSQL). T-0014 reading: a row is visible when its described project is app.current_project_id, in app.allowed_project_ids, in the new setting app.member_project_ids (every project of the caller's memberships, any persona, bound server-side in the same unit of work), or app.is_system_admin; memberships also to their own user (TD-152). app.member_project_ids widens only the membership-based tables, never project-scoped records, so a client-portal user of A still cannot list or fetch B. Confirm or amend the spec text.
