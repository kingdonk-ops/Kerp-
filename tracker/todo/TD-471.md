T-0110 probed about 590 edge expressions (null/absent, numeric types and overflow, strings and
unicode, timestamps and time zones, list/map membership, short-circuiting and errors) on both
runtimes. About 440 agreed; 176 of those are now parity fixtures (`edge.*`). The rest diverge. Following
the TD-041 decision (pin every divergence, restrict the Designer to a safe subset), 66 are pinned
in `tests/contract/conformance_fixtures.json` as `known_gap` fixtures citing this TODO; the
others are listed at the end. Same harness rule as TD-041: the deviating runtime is asserted
against its pinned `actual`, so a library change is noticed.

**Fixed in T-0110** (now parity fixtures, not gaps): a JSON integer beyond the double range in a
context crashed the server (`OverflowError`; now Infinity as on the client); the server wrote
timestamps before year 1000 without zero padding; the client accepted impossible `$timestamp`
context values (30 February, hour 24, year 0, an offset that leaves years 1-9999) that the
server rejects; the client could not evaluate anything over a map that has a `constructor` key
(JSON objects are now decoded to `Map`).

## Pinned gaps that matter most

A rule can pass on one runtime and fail on the other. "Server lenient" means the hard gate
accepts what CEL (and the client) reject.

- **Number field vs int literal** (server fails closed; the most likely to be written):
  `fields.count == 2`, `fields.count in [1, 2]`, `2 < fields.x`, `size(l) > 2.5`,
  `fields.l == [1, 2, 3]`, `fields.flag == 1.0`, `2 in ['a', 1]` are evaluated on the client and
  NO_MATCHING_OVERLOAD on the server. In a `visible_if` the server hides the field and drops
  its answer. Write double literals (`== 2.0`) until the lint catches it (TD-473).
- **Server lenient**: `has(a.b.c)` with `b` absent is `false` (client: NO_SUCH_KEY);
  `size(null)` is 0; `1 < 2 < 3` is `true`; `'a' in 'abc'` is a substring test; `int(' 12')`,
  `int('1_000')`, `int('0x1F')`, `int(true)`, `double(true)` convert; `timestamp('2024-01-01')`
  and a timestamp without offset are accepted (UTC assumed); `duration('1d')` and
  `duration(3600)` are accepted; an unknown string escape is kept; `l.all(x.y, true)` is
  accepted; `1.` is a literal.
- **Client lenient**: `int('')` is 0; `double('0x10')` is 16; `timestamp('2024-02-30T…')` and
  hour 24 roll over to the next day; a repeated map key takes the last value; durations and
  timestamps beyond the CEL range are accepted (a five-digit year in the result);
  `string(b'\xff')` gives U+FFFD; the string extensions `lowerAscii`, `trim`, `split`,
  `substring`, `indexOf`, `join` exist on the client only.
- **Regular expressions** (`matches`): the server uses RE2 (the CEL definition), the client JS
  `RegExp` without the unicode flag: `.` matches one UTF-16 unit, `\s` also matches NBSP,
  lookahead and backreferences are accepted, `(?i)`, `\p{L}`, `[[:alpha:]]`, `\A`/`\z` are not.
- **Strings**: ordering is by UTF-16 unit on the client (astral characters sort before
  U+E000-U+FFFF), by code point on the server.
- **Values**: `string(1.0)` is `"1.0"` on the server (`"1"` on the client), `string(NaN)` is
  `"nan"`; `duration('1ns')` is truncated to microseconds on the server.
- **Grammar**: the server rejects a ternary nested in the true branch without parentheses,
  a trailing comma in a list, 3-argument `map()` and a 900-term sum (recursion limit); the
  client rejects `.5`, `.fields.a`; `fields.in` is a lookup on the server.
- **Conversions missing on one side**: `timestamp(int)` (server), `int(timestamp)`,
  `timestamp(timestamp)`, `int(uint)` range error (client).
- **Error code only** (both fail closed): absent field as a ternary condition, an error inside
  a map literal, `double('abc')`, unknown time zone.

## Not pinned (both runtimes differ from CEL, or the expected result is unclear)

The fixture schema has one deviating runtime per fixture, so these are recorded here only:
`double(' 1.5')` / `double('1_0')` (server converts, client EVAL_ERROR); `string(1e-7)`
(`1e-07` vs `1e-7`); `string(Infinity)` (`inf` vs `+Inf`); two different errors on the two
sides of `&&` / `||` (each runtime reports a different one); `fields.l[1.0]` (client indexes
with a double) and `fields.l['a']` (NO_SUCH_KEY vs NO_MATCHING_OVERLOAD); `[1, 2] + ['a']` and
`true ? 1 : 'a'` (client type error, server value); `{1.5: 'a'}`, `{null: 'a'}`, `{[1]: 'a'}`
(client builds the map); `fields.s.all(c, true)` (server iterates the string); `0X1f`, `1e400`
literals; `timestamp('…t…z')` lower case; time-zone arguments `'08:00'`, `''`, `'Z'`;
`int('9223372036854775808')`, `int(NaN)`, `uint('-5')` (different codes); 300 nested
parentheses (different codes); `type(t) == google.protobuf.Timestamp` vs `timestamp`.

## Options

Same as TD-041: extend the strict evaluator / client wrapper per item, fix upstream, or reject
the construct at authoring time (TD-473). The server-lenient items should be closed in
`app/core/cel/strict.py` before sync ingest (T-0126) and public submit (T-0253) rely on the
server as the hard gate. T-0131 needs exact parity on 120 expressions: 434 parity fixtures now.
