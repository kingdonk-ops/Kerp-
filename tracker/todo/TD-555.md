Product intake 2026-11-21, item 38. Projects copy default ITP templates and rule sets and then edit them. When the publisher (tenant library or system defaults) issues a new version, the project needs a **three-way upgrade**: base (the version the project copied) vs theirs (new default) vs ours (project copy).

Planner default screen (user to confirm): counts first ("publisher changed 12 entries, you edited 5, 3 overlap"); a list of the overlapping pairs side by side; one question per upgrade, keep ours / take theirs, with per-pair override; entries the project never edited update automatically; entries the publisher dropped are marked "removed by publisher" and kept until the project removes them; nothing on signed or pinned revisions changes (T-0119 immutability, T-0281 never touches signed lines). Backend: the rule drift report and upgrade offers (T-0036, validation/upgrades.py; batching in flight under T-0348) and client-pack upgrade offers (T-0137); ITP master-revision propagation (T-0281). Frontend part of the rules screen is TD-280.
