The pasted spec asks System admins to edit subject + HTML/plain-text body of every automated e-mail. Diff §4.6: templates go through the i18n layer, plain text plus simple HTML, no remote images or tracking pixels, secrets only inside link fragments, every value HTML-escaped.

Planner default applied (not blocking): per template and locale, admins override the subject and the text blocks (intro, outro, action label) as plain text with only the placeholders the template declares; the renderer still builds the HTML, escapes every value and places the action link (an admin can never move or reveal the secret). Revisions kept; reset restores the shipped i18n text.

Question for the user: is raw HTML editing needed (it would need an HTML sanitiser allow-list and a review of the §4.6 rules)?
