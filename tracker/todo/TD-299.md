After T-0080, login and magic-link redeem check the device only after the credentials, as diff 4.3 requires. The check (service.refuse_revoked_device) still looks at any device of the tenant named in X-KERP-Device-Id, not only the signing-in user's own devices, so an authenticated user can learn whether another account's device id is revoked. Low risk (device ids are random client UUIDs seen by the device, its user and admins; one account per device id, TD-283). Mitigation if wanted: refuse only when the revoked device belongs to the signing-in user (and decide what a foreign revoked id gets: plain sign-in without binding, or a uniform refusal).

- 2026-11-16: Decision (product owner, 2026-11-16, TODO triage): fix: refuse only when the revoked device belongs to the signing-in user; a foreign revoked id gets a plain sign-in without binding.
