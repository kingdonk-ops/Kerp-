Repo review 2026-11-13 / PR #53 round 2. T-0068 re-keys only password login. The magic-link request lockout (service.request_magic_link) stays keyed by tenant + e-mail on purpose: it is also the cap on how many e-mails one mailbox can be sent, which a per-client key would lose. Options: per-client lock + a per-mailbox send cap that never blocks sign-in (e.g. silently drop extra e-mails but keep the last link valid), or accept the DoS until field workers move to the native app's device sessions.
