T-0014 lists 'tenant_id FK added (TD-032)'. There is no tenants table yet; adding the FK means a new core table (spec §1.1 tenants directory), first-run provisioning of the deployment's tenant row (KERP_DEFAULT_TENANT_ID), an FK on every existing table (14 migrations' worth of tables) and test seeding of tenant rows for every synthetic tenant id, which is a destructive-risk core-table change needing an ADR (CLAUDE.md §6). It does not fit next to the admin module within size M, so T-0014 leaves the criterion unticked. Proposed: a separate S/M task 'tenants directory table + tenant_id FK on every table (ADR)', depending on T-0014.
