User-supplied spec (2026-11-21, pasted task 'T-0073', now T-0221/T-0222) asks for a tenant-wide upload quarantine table and a global audit explorer for system_admin. Diff §4.1: System admins 'read no project-scoped records without a membership like any other user'.

Planner default applied (not blocking; revised in PR #137 review round 1): (a) quarantine monitor: full upload rows only for projects where the admin holds a membership, read under the normal RLS of `oe_uploads_file`; for every other project **counts only** per project, status and reason code, from a count-only `SECURITY DEFINER` function of the T-0219 pattern (pinned `search_path`, `EXECUTE` revoked from `PUBLIC`, numbers only, ADR). This is count-only, not row-level metadata: the uploads RLS policy is not widened and no bypass role is used. (b) Audit explorer reads under normal RLS: tenant-level chains in full, project chains only of projects where the admin holds a membership. A wider read needs a policy on a core table (audit_ledger) and therefore an ADR. (c) Project archive (E-01-02; documents-and-mdr §Access): export (T-0233), download (T-0237) and restore of a deleted project (T-0239) need `system_admin` and a membership of the requesting admin on the project (for a deleted project: a membership held when it was deleted, since deletion revokes all memberships); a non-member System admin gets 404. A System admin may grant themselves PER-09 on a live project through the existing membership API (T-0014), audited in `project-members:<project>`; the archive endpoints never grant it implicitly. Restore as new (T-0240) makes the restoring admin PER-09 of the new project, audited. The registry list, storage-tier changes and deep-archive restores expose no content and need `system_admin` only. In every case the user may relax the default.

Question for the user: keep the defaults (membership required for rows, audit chains and archive contents; self-grant of PER-09 is the audited way in), or allow System admins a full cross-project read for these surfaces (with an ADR, a policy change and an audit entry per read)? Also: should a System admin who was not a member be able to restore a deleted project in place (today only restore as new is open to them)?
