The paste (T-0181) makes new equipment start out_of_service until a verified cert exists, credentials pending_verification until QA verifies, and heat/MTR records pending_verification until the MTR is verified. Records created before these tasks (pilot data included) have no verification item. Planner default (not blocking): the additive migration marks existing certs/credentials/MTRs that already have a document as verified with verified_by NULL and verification_source = 'pre_gate' (shown as such in the two-lane history and the ledger), and those without a document as pending (missing-document alert sent once per project in a digest, not per record); bulk imports (T-0107 equipment rows) follow the same rule as single creates (unverified until QA). Question: accept, or require QA to re-verify every existing record?
