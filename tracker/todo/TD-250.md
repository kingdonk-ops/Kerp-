Catch `starlette.requests.ClientDisconnect` in `RequestContextMiddleware` and log it as 499 with `disconnected=true` (no 500 response, no error log), so client aborts mid-upload do not page as server errors. The T-0060 `BodyLimitMiddleware` (innermost, wraps `receive`) passes `http.disconnect` through unchanged and its own 413 is rendered inside the app, so it neither causes nor masks this case; a test should cover a disconnect during a body read through both middlewares.
