title: Internal contexts that bind is_system_admin=True for a narrow read (jobs scheduler deployment_scopes, teams reconcile, onboarding, the invite token lookup) now also see every project-scoped record of the tenant under ADR 0016
kind: risk
status: open
tasks: [T-0274]
source: implementer
raised: 2026-11-21
---

Before ADR 0016 the flag widened only the membership-described tables (project rows, memberships, admin grants, access requests, invites, teams), so several server-internal paths bind TenancyContext(tenant, is_system_admin=True) to read project rows or a single invite: app/modules/jobs/scheduler.py deployment_scopes, app/modules/teams/reconcile.py, app/modules/onboarding/service.py, app/modules/admin/invites.py (_elevated lookup by token hash). T-0274 widens project_isolation_policy for that flag, so these sessions can now also read and write every project's records of the tenant. Each reads only its own tables today, so nothing leaks, but the blast radius of a future bug in those paths grew. Planner default: keep as is (they are server-side, never client-bound); consider a narrower setting (e.g. app.describe_all_projects) for the project-row-only readers if a reviewer prefers least privilege.
