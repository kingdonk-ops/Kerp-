Product owner, 2026-11-15 (TD-223). pull_request and pull_request_review workflows run the PR's copy of the workflow files, so a PR can change .github/workflows/review-gate.yml or add a workflow with a review-gate job and satisfy the required check (pinned only to the GitHub Actions app). Mitigation in place: the repo is user-owned with the owner as sole collaborator (agents act as the owner login), and Settings > Actions > General > 'Approval for running fork pull request workflows from contributors' is set to 'Require approval for all external contributors' (applied by the owner 2026-11-15, owner-reported; not verifiable from the agent proxy), so a fork PR's workflows never run unapproved; unexpected fork PRs are closed without running workflows. No human-approval requirement now (no second human; GitHub forbids self-approval); org-only 'required workflows' rulesets are not available to a user-owned repo. Revisit trigger: a second collaborator (human or bot account) gets write access -> add CODEOWNERS on .github/ and scripts/ with required code-owner review on dev.
