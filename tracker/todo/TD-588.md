Product intake 2026-11-22 (3), item 4 (planner default; user to confirm). Spec written: documents-and-mdr.md §Numbering schemes. One shared numbering service (pattern with whitelisted tokens and zero-padding, allowed code lists per token, row-locked counter, numbers never reused even when a draft is voided, revision and status never part of the number) for documents, ITPs, transmittals and dossiers, generalising the RFI pattern-plus-counter (quality-and-inspection.md §inspection_requests §8) and the per-template patterns of ADR 0003 §4 item 5.

Open points for the breakdown:
1. **Which task builds the service.** T-0108 seeds "numbering patterns" from client packs and other tasks already say "through the T-0108 numbering mechanism" (T-0185 substitutions, T-0312 issues), but no task builds the mechanism itself. Planner default: a core service (`app/core/numbering/`) built as its own S/M task before T-0108, T-0312 and T-0185 need it, or as the first task of E-05-01 if that epic is broken down first.
2. **RFI numbering stays module-owned** (quality §8, "T-0108's numbering does not allocate RFI numbers"). Planner default: unchanged for now; the RFI counter may move onto the shared service later only if its behaviour (counter scope, `seq_start`, validity rule) is kept.
3. **Asset node codes** (TD-480): whether level-def code generation uses this service is TD-480's question; this TODO does not decide it.
