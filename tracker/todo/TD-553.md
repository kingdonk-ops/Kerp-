Product intake 2026-11-21, items 33, 34 and 36. Admin-safety behaviours not yet in the spec (planner defaults; user to confirm):

- **Verbs by recoverability** (item 33): permissions on configuration split so that irreversible or wide-impact actions are separate verbs, off by default: for example template and rule-set **delete** (distinct from edit and retire) is granted to nobody by default and is refused with 409 while the template or rule set is in use (pinned by a record, referenced by a rule or project copy); retire is the normal path. Applies to the template designer (E-01-03), rule sets (T-0036) and settings (T-0232).
- **Scope of a policy change** (item 34): every setting and policy edit screen states whether the change applies to existing records or only to records created afterwards (for example notice hours apply to new issues and reschedules only; offline window applies to existing leases at next sync). The registry entry declares `applies_to: existing | new_only` and the Settings screen (T-0232) shows it beside the field.
- **Impossible values** (item 36): values that cannot be true (a "last active" time in the future, a negative duration, an end before a start, a sync from before enrolment) are shown flagged ("clock problem") in admin screens such as the user directory (T-0246) and device lists, never shown as normal values; the API returns them unchanged with a flag rather than clamping.
