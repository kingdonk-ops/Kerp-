T-0013's RLS criterion says a non-admin session reads a team when it is linked to a project in its scope (bound project or app.allowed_project_ids) or the caller is a member. ADR 0008 says the link row describes a project like a membership, and the task says to follow T-0014's tenant-level pattern, whose membership policy also counts app.member_project_ids. Without it a PER-09 (single scope) could not see the team name of team-derived rows in the T-0014 member list (a tenant-level session), which the same task requires. Implemented: bound + allowed + member projects (described_project_ids), so anyone with access to a project can read the teams linked to it, which equals what GET /teams/projects/{p}/teams shows them anyway. Confirm or narrow (then the admin member list must bind the project to fill in team names).
