Product intake 2026-11-21, items 21–24. The offline client tasks (T-0127 indicator, T-0149 download, T-0165 capture, T-0157 photos) leave several user-visible behaviours unspecified. Planner defaults to add to diff §6.4 and those tasks (user to confirm):

- **Connection pill** (item 21): always visible on field screens: "Online", "Offline – N queued", "Syncing", "Not syncing" (the device cannot back up its local copy: storage full, auth expired, server refusing) with the reason on tap. Photo tiles show `empty | loading | queued | failed (reason)`; a failed upload offers retry.
- **Availability** (item 22): an inspection is available offline only once it was downloaded while online (download = checkout, diff §6.4); the list marks what is on the device. Signing out offers to clear local copies, but only after the outbox is drained (purge never deletes unsynced work, diff §6.4); with pending work it warns and keeps them. **Not adopted:** "video online only" from the source: KERP captures video offline (T-0167, T-0170).
- **Restore while offline** (item 23): if the server copy of a record was restored or replaced while a device held it (project restore, archive restore as new, admin correction), the device's copy is set aside into one backup slot, shown to the user, never silently merged; the server version becomes the working copy. A reconnect must never visibly roll back local edits: local values stay shown until the server acknowledges or explicitly reports a conflict (the conflict flag of diff §6.4). Test: a rating changed offline survives reconnect.
- **Responsive editor** (item 24): one pane on phones, two on portrait tablets, three or four on landscape; rotation keeps scroll position, the open item and unsaved input; burst photo capture from an item (several shots in one go, each queued).
