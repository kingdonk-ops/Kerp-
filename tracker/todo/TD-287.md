From the PR #88 round-1 review (T-0036). _diff treats any rule under a new default's key with origin_rule_key NULL as key_in_use, including an own rule the set already soft-deleted. The offer then says to delete it first although it is already deleted, and the default can never be taken (accept is refused, the deleted key still occupies the slot). Fix: when the own rule is deleted, offer the default as new (accept reuses or replaces the deleted row) or give the entry a distinct, actionable state.
