T-0080 audits every refused POST /api/v1/devices/{device_id}/wipe-confirmed on device:<device_id> (acceptance criterion), including unknown ids, so an unauthenticated caller can grow the audit ledger (one new chain per invented id) without limit. The answer itself leaks nothing (uniform 404, comparable work). Mitigation: a per-client ProgressiveLockout (or the reverse proxy's rate limit) on this endpoint, applied before the lookup so it does not depend on the device; or audit refusals of unknown ids on one capped tenant chain. Decide before pilot go-live together with the edge rate limits.
- 2026-11-15: (coordinator, PR #94 review) also cap `WipeConfirmRequest.wipe_secret` with `max_length` (e.g. 128) so an unauthenticated caller cannot make the server hash an arbitrarily large string; the 422 is device-independent.
