The user's 2026-11-21 paste (T-0179) asks for /api/v1/public/inspections/{token}: no JWT, IP rate-limited, tenant and project resolved from a URL token, anonymous submitters (typed name, optional contact), project lookups of equipment and worker display names. This conflicts with CLAUDE.md §6 (tenant from the JWT only), diff §4.2 (magic links for Field Workers, PER-14, only; TD-136) and the rule that project-scoped notifications and records need a member principal. ADR 0013 (docs/decisions/0013-public-inspection-capture-links.md, status Proposed) drafts the safest form: tenant from KERP_DEFAULT_TENANT_ID like the SNS endpoint (diff §4.6); project id carried inside the opaque token and bound as the session scope, then the hash looked up under the normal project RLS (no row-returning RLS bypass, no SECURITY DEFINER lookup); 404 for every failure; source public_link (new RECORD_SOURCES value); security controls as acceptance criteria. Options: (a) accept ADR 0013 as drafted; (b) accept with changes (e.g. no worker-name lookup, no submitter contact, permanent links not allowed); (c) reject: keep capture authenticated (PER-14 magic link + PIN; workers need accounts), drop T-0186-T-0189. No safe default: T-0186, T-0187, T-0188 and T-0189 are blocked until decided. Also asked: retention of submitter IP, user-agent and contact (privacy; planner default 90 days for IP/user-agent, contact kept with the record).
