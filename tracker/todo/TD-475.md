EDGE-SCREENS section 2.2 shows one field (`field_key`, `label`, `data_type`, `validation`, `visible_if`); the rest of the template schema is not specified. T-0110 chose the following; spec owner to confirm or correct (each is covered by `tests/contract/form_fixtures.json`, so a change is a fixture change on both runtimes):

1. **Range**: `range: {min?, max?}`, inclusive, each bound a JSON number or a CEL string that must give a finite double; allowed on `numeric`, `measurement` (compares `value`) and `calculated`. An out-of-range answer is **flagged** (`failed`), it does not make the form invalid, following section 2.1 ('flags out-of-tolerance reading; prompts NCR'). A bound that cannot be evaluated blocks (fail closed). TD-065 (block vs warn severity, limits as parameters) is still open and may change this.
2. **Calculated**: `expression` (CEL); evaluated in template order in one pass, so it may read calculated fields declared before it only; a client-sent value is ignored and recomputed; a `null`/empty result is 'unanswered'.
3. **Sections**: `sections: [{section_key, title, fields: [field_key]}]` reference the flat `fields` list (keys stay unique template-wide, CEL always reads `fields.<key>`). No section-level `visible_if` and no LIST/FORM check layouts (TD-062).
4. **Type names**: the property stays `data_type` (section 2.2). Palette keys are `numeric`, `text`, `measurement`, `photo`, `signature`, `instrument_ref`, `calculated` (diff 2.1) plus `boolean`, `select`, `date`, which the T-0025 renderer already had; `number` (the section 2.2 example) is an alias of `numeric`. TD-104 (choice with stable keys, integer, multiline, heading) is still open.
5. **Answer shapes** not given by the spec: `signature` = `{attachment_id, ...}`, `instrument_ref` = `{instrument_id, ...}`, `measurement` = exactly `{value, unit}`, `date` = `YYYY-MM-DD` checked for shape only (no calendar check), `photo` = list of objects with `attachment_id` (the full photo schema is T-0156).
6. **Keys**: `field_key` is lower snake case (`[a-z][a-z0-9_]{0,62}`) and not a CEL reserved word; unknown properties are lint errors.
7. **Order of checks** per field: calculated error, required, answer shape (`type_mismatch`), validation, range; one error per field.
