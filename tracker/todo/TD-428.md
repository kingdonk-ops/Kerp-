The user's 2026-11-21 pastes (T-0187, T-0188) assume a table oe_qms_itp_template with status draft/approved, stages, per-party intervention points and bound ITR form ids, and an ITP 'instance' per anchor with is_customized. The spec has only: ITP = master template authored in qms on the one-engine (T-0110 template revisions, publish freezes a revision), instantiated per anchor as kind = itp records that pin template_revision_id (quality-and-inspection.md §ITP/RFI/ITR, §Unified inspection record); T-0113's acceptance criteria are two lines. Planner defaults (applied, not blocking; written into quality-and-inspection.md §ITP authoring, assignment and propagation): (1) no separate oe_qms_itp_template table: an ITP template is a one-engine template of kind itp whose revision body holds ordered stages → line items (activity, acceptance criteria, spec/code references, ITR form template id + revision, intervention point per party Contractor / Principal / Client (PER-15) from H, W, R, S, M); (2) 'approved' = a published (frozen) revision; publishing an ITP revision needs PER-06 on a project-layer template or PER-13 on a tenant master (the ADR 0004 §7 editor split for quality rules; PER-13 approval generally: see TD-422); system_admin and PER-09 never publish (no A, ADR 0016); a revision drafted by AI carries source = ai and cannot be published by the job, only by that human action; (3) a new qms table oe_qms_itp_instance (BaseRecordMixin + project RLS: anchor node/item, template id, pinned revision, is_customized, status pending_qa_review | active | superseded) groups the kind = itp line records of one template on one anchor through an additive nullable itp_instance_id on oe_inspections_inspection. Question for the user: confirm or adjust (1)-(3) before T-0113 starts; the M1 freeze (T-0131) should include them.
