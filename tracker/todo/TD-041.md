`tests/contract/conformance_fixtures.json` pins every known divergence as a fixture with a
`known_gap` block (runtime + actual result). The harness asserts the pinned result on the
deviating runtime, so a library change is noticed. 14 gaps remain (7 server, 7 client). **None
of the server gaps fails open**: each one is an error where CEL gives a value, or a different
error code.

**Fail-closed contract (every caller, incl. `run_checks` / T-0018):** a CEL gate passes only on
`CelOk(value=True)` (Python: `isinstance(r, CelOk) and r.value is True`; TS:
`r.ok && r.value === true`). Every error and every non-bool result blocks.

Closed in T-0017 (`backend/app/core/cel/strict.py` + compile-time checks in `runtime.py`, now
parity fixtures under `strict.*`):
- function-table overrides: mixed int/uint/double arithmetic, `int / double`, IEEE
  NaN/-Infinity for `x / 0.0`, `&&`/`||` with non-bool operands (absorption kept), string
  indexing, negative list indexing;
- a strict `Evaluator` subclass (via `Environment(runner_class=...)`): bool-only predicates for
  `filter`/`exists_one` (error) and `all`/`exists` (error value, still absorbed by
  `false`/`true`), also in nested macros; macro errors returned as values so `false && <macro>`
  absorbs them; `string()` only for string/bool/int/uint/double/bytes/timestamp/duration
  (`string(null)`, lists, maps are NO_MATCHING_OVERLOAD; `string(true)` is `"true"`);
- compile time: `has(x)` without a field selection, literal non-bool `&&`/`||` operands and
  macro predicates, and celpy's non-standard `min()`/`reduce()` macros are rejected.

Remaining server (celpy) gaps — all fail closed:
`gap.heterogeneous_ordering_literal` (`1 < 2.0` errors; int on the left of a mixed ordering),
`gap.eq_null_on_value` (`x == null` errors instead of false),
`gap.all_every_element_errors` / `gap.exists_every_element_errors` /
`gap.ternary_condition_error` (no-overload instead of the element error),
`gap.macro_wrong_arity` (`all(x)` is INVALID_ARGUMENT, not NO_MATCHING_OVERLOAD),
`gap.map_uint_key_lookup` (`{1: 2.0}[1u]` errors instead of finding key 1).

Remaining client (cel-js) gaps: `uint(-1)` is INVALID_ARGUMENT not INT_OVERFLOW; intermediate
int64 overflow is not detected (the wrapper only range-checks the final result); `has()` on a
map literal is rejected; an int-keyed map result looks string-keyed; `string(1e20)` is
`"100000000000000000000"` (CEL/server: `"1e+20"`); `string(timestamp)` and `string(duration)`
are not supported (NO_MATCHING_OVERLOAD).

Options: extend the strict evaluator, upstream fixes, or restrict the Designer's CEL subset with
authoring-time type checks. T-0131 needs exact parity on 120 expressions (currently 258 parity
fixtures).
