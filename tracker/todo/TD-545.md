Product intake 2026-11-21, item 27. The user decided (2026-11-21) that client and site data may be sent to an external AI provider (recorded in diff §4.11). Still open for confirmation are the planner defaults on how:

- **Provider:** one per deployment (one tenant per deployment, diff §4.1): OpenAI, Anthropic Claude or a self-hosted model.
- **Residency:** hosted in the deployment region (Australian region, as TD-078 already chose for ingestion).
- **Credentials:** the company's own key (tenant-owned) held in the deployment secret store, never a runtime-registry entry (diff §4.7, TD-398). A platform-held key is not offered by default.
- **Fail closed:** no provider or no valid key → every AI feature unavailable (503 `AI_UNAVAILABLE`, entry points hidden); no fallback to another provider or region.

Question for the user: confirm these four defaults, or name the provider, region or key model you want. Not blocking: E-05-08, T-0187 and T-0189 build against the defaults; the assurance record (diff §4.11) records the credentials owner either way.
