T-0009 marks a session as PIN-gated only by the presence of kerp:auth:pin:<sid> in Redis. If Redis evicts that key under memory pressure (allkeys-* policies), /auth/refresh accepts the session's refresh token without the PIN. Remedies: carry amr=["pin"] (or a session-kind claim) in the refresh token so /refresh refuses it regardless of Redis state and unlock fails closed when the hash is missing; and/or require maxmemory-policy noeviction for the auth Redis (deployment check, cf. TD-124). Reviewer suggestion on PR #35.

- 2026-11-13: (planner) T-0038 moves the PIN hash from Redis pin:<sid> to the device record, which should remove this fail-open path.
