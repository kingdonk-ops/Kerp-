T-0008 reading: POST /api/v1/auth/login takes an optional tenant_id; when omitted, KERP_DEFAULT_TENANT_ID (single-company deployment) is used; no tenant -> 401. Users are tenant-level rows of auth_user (one row per tenant), looked up in a session bound to that tenant so RLS holds at login. The spec does not say how a person with accounts in several tenants (MOD-01: a client inspector across EPC contractors) chooses a tenant, nor whether there is a tenant slug/domain lookup. Decide: explicit tenant picker, slug/subdomain, or a global identity table mapping email -> tenants (would need an RLS exemption or SECURITY DEFINER lookup).

- 2026-11-13: Direction (user, 2026-11-13), spec change requested, model to be confirmed: one company uses KERP; several administrators each run one or more projects and assign users to one or many of their projects; administrators get no hold/sign-off authority without the required qualifications; a project picker in the top bar; either per-site subdomains (e.g. coastal.<domain>) or a lobby where a user with no project can see projects and request access. User asks whether tenants should be dropped altogether. Coordinator recommendation sent to the user; awaiting confirmation before the planner changes the spec.
