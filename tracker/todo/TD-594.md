Product intake 2026-11-22 (3), item 12 (planner default; user to confirm). Later, with the Daily Workface Log (E-04-04). The edge spec §1.3 already says the log "queries local weather telemetry"; this TODO pins the rules before that is built:
- Weather is a **fetched, timestamped reference**: provider/source, station or grid point, fetch time and the values are stored with the diary entry, shown as "Weather reference (<source>, <time>)".
- It **never replaces measured readings**: ambient temperature, humidity and dew point for coatings and tests come only from calibrated instruments (quality §Coatings, calibration gate diff §5).
- It is a **new outbound data flow** (site location sent to a third-party weather service). Needs a user decision before it is built: which provider, what location precision is sent, and whether it is on by default per project. Until decided, manual weather entry only.

**User decision (2026-11-22):** any provider is acceptable if it uses **local Australian data and is free of charge**. Planner notes for when this is built (E-04-04):
- First candidate: the Bureau of Meteorology's public observation products. Confirm the licence allows reuse inside a commercial product and automated retrieval before building; a provider whose free tier is non-commercial only does not qualify.
- Prefer bulk products (state or region observation files) and pick the nearest station on the server, so **no site location leaves KERP**; if a provider needs a location, send it rounded to a nearby grid point (about 10 km).
- Still a planner default: off by default per project, switched on by PER-09.
