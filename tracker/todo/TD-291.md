From the PR #89 round-1 review (T-0043). service.refuse_revoked_device checks the revoked status of whatever device id X-KERP-Device-Id names, for any user of the tenant, before credentials are checked on login: an unauthenticated 'is this device id revoked' oracle. wipe-confirmed similarly answers 404 for an unknown id and 409 for an active one. Low risk: device ids are client-generated random UUIDs seen only by the device, its user and admins. Related: TD-286 (unauthenticated wipe-confirmed). Mitigations if needed: check credentials first and answer uniformly, or a per-device secret.
