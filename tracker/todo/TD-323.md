title: Rate-limit GET /auth/sso/entra/start per client (each call stores a 10-minute state entry in Redis)
kind: later
status: open
tasks: [T-0054]

Every /start writes one ~0.5 kB state entry (10-min TTL) for an unauthenticated caller, so a flood can grow Redis memory (with noeviction it could eventually refuse writes). Add a per-client ProgressiveLockout (like WIPE_CONFIRM_POLICY, T-0212) or a fixed per-IP budget before the state is stored; answer 429 + Retry-After.
