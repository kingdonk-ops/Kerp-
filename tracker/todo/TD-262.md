Invites are in the Pilot-0 gate (product owner, 2026-11-14), but an invite creates the account with no credentials (diff §4.1) and the first-time password set through an e-mailed invite is T-0056, outside the gate and blocked by TD-084 (no outbound e-mail). Magic links also need a mail transport (production refuses to send without one) and are PER-14 only. So before T-0056 a brand-new invitee who is not a member of the company Entra tenant cannot sign in at all; only company members (SSO) and existing accounts with a password can complete an invite. Options: (a) accept the limit for the pilot: pilot invitees are company members or existing accounts (planner default applied; the T-0146 runbook uses such an account; the Pilot-0 invite decision stands, scoped to those users); (b) a System admin sets an initial password for a new account (would extend T-0014, one-time, must-change at first sign-in); (c) a copyable one-time 'set first password' link returned with the invite, like the invite link itself (no e-mail needed; would extend T-0052/T-0056); (d) pull T-0056 + TD-084 (e-mail delivery) into the gate. Affects T-0052, T-0053, T-0146.

- 2026-11-14: (planner) Resolved the same day by the product owner (option (d) plus self-set first password at acceptance and self-service reset). Planner security rule added: the first-password set needs the `setup_token` that only the invite e-mail carries, so the inviter's copied link cannot set the password. The Pilot-0 invite decision stands, now covering brand-new external invitees.
