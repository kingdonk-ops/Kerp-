T-0005 increments revision on every update but nothing compares it, so concurrent writers silently overwrite each other. Decide between SQLAlchemy version_id_col (stale UPDATE → StaleDataError) and an explicit base_revision check in services/offline sync (Phase 1 sync core). Raised from PR #13 review round 1.

- 2026-11-09: Decision (user, 2026-11-09): SQLAlchemy version_id_col for server writes + explicit base_revision check on offline sync ingest; settle before T-0126.

- 2026-11-10: Refined by ADR 0005 / TD-075: base_revision stays on the sync envelope, but tablet ingest accepts/rejects per field via base hashes.
