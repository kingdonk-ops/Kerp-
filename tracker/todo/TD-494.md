Diff §4.7 says every System console action is written to the audit ledger and that the audit explorer is read-only; the T-0222 acceptance criteria say 'audited' only for verify-all. Implementer default (T-0222): reads (GET /admin/system/audit) are not ledgered (as the queue monitor's reads, ADR 0016 item 5); POST /audit/verify appends 'audit_chain_verified' (chain key, project id, ok, length, first_broken_seq) and verify-all appends 'audit_verify_all_requested' (job id) with the job row and 'audit_verify_all_finished' (counts, first broken chain/seq) from the job, all on admin-system:<tenant>. No ledger row is updated or deleted. Open: should a single-chain verification be ledgered at all (an admin clicking through chains grows the console chain), and is the outcome entry wanted next to the request entry?
