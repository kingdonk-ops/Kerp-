PR #67 added a total-position cap to PolygonGeoJSON, which ProjectRead.spatial_bounds reuses (backend/app/modules/projects/schemas.py). Rows stored before the cap (up to 100 rings x 10,000 positions were allowed) would fail validation on read and turn the list endpoint into a 500. Phase 0 data probably has none. Fix: apply the cap to input models only, or check/migrate existing rows; add a test that reads an over-cap stored row.
