Product owner, 2026-11-14: deferred to later. PR #80 added permission deny rules so agents cannot change .claude/settings.json or scripts/gemini_review.sh, but those rules cover only the Edit/Write tools. An agent can still change both files through the Bash tool (for example sed -i, a heredoc redirect, cp/mv, git checkout of another revision, or a script). Options to close the gap: (a) CODEOWNERS entries for both files with required human-owner review on dev; (b) a CI check that fails a PR touching either file unless it carries a human-applied label or approval; (c) a PreToolUse hook that refuses Bash commands writing to these paths (best effort only, since shell commands can be obfuscated, so combine with (a) or (b)). Changes to these files remain human-only until this is done.
