T-0039 makes memberships of a deleted project confer nothing by soft-deleting them in projects.service.delete_project (memberships.revoke_project; audited as revoked_memberships on project:<id>). load_grants itself does not join the project table (core never reads a module table). Follow-ups: (1) any project restore/undelete feature must decide whether to revive the revoked memberships (the audit entry lists them); (2) databases with projects soft-deleted before this change keep live memberships on them; no deployment exists yet, so no data migration was written. If one is needed, revoke memberships whose member_project_id is a deleted project in a provisioning script.
