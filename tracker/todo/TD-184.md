T-0012 has no tenant administrator to gate project creation on (T-0014 adds it). Interim rule: `POST /api/v1/projects` needs the `admin` capability (Project Administrator, PER-09) on at least one project of the tenant; the very first project of a tenant is created through `app.modules.projects.service.create_project` (seed/script). Creating a project grants no membership, so the creator cannot read or edit the new project until a membership is assigned (T-0014 admin API). Decide in T-0014: tenant-admin-only creation, and whether the creator is granted PER-09 on the new project automatically.

Caveat: `load_grants` does not exclude memberships on soft-deleted projects, so a PER-09 whose only project was deleted can still create projects. T-0014 should drop or ignore memberships of deleted projects when it settles the creation rule.

- 2026-11-13: Decision (user, 2026-11-13): 1a. Projects are created by an administrator (not by any PER-09). The creator is granted PER-09 (Project Administrator) on the new project automatically. Memberships on soft-deleted projects are ignored by load_grants. Who the 'administrator' is (tenant admin vs project-portfolio admin) follows the tenancy/lobby direction recorded on TD-120; settle both in T-0014.
