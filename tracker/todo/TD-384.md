T-0075 AC (SoD on fix): the sync gets 'the expected set minus the pending users, plus their existing rows'. A pending user has, by definition, no live row of the link matching its (project, persona, site); sync_team_link_grants keeps only matching rows, and passing the user would make the sync re-add the hold persona (SodConfirmationRequired). So the only rows a pending user can still have on that link are stale ones (wrong persona/site/project), which are excess access. Implemented reading: the sync gets the expected users minus the pending ones, and a pending user's stale rows of that link are removed as excess (the dangerous direction is always repaired). Keeping a stale persona row until --confirm-sod would need a new core API. Confirm or decide otherwise.
