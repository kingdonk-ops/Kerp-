`app.core.fields.lint_template` compiles every CEL string but does not resolve what it reads. Add, on the celpy parse tree (`app.core.cel` already extracts free identifiers): (1) `fields.<key>` must name a field of the template (TD-104: a legacy validator never fired because of a field-name mismatch); (2) a calculated field may only read calculated fields declared before it (evaluation is one pass in template order; a forward reference is NO_SUCH_KEY at run time); (3) warn when a rule reads a field that can be hidden without a `has()` guard; (4) the safe-subset checks decided in TD-041: reject constructs with a pinned parity gap (TD-041, TD-471), first of all an int literal compared with a number field (`fields.count == 2`: true on the client, NO_MATCHING_OVERLOAD on the server), client-only string extensions (`lowerAscii`, `trim`, `split`, ...), regex features RE2 lacks, and non-RFC 3339 `timestamp()` literals. Until then the rule-writing guidance is in `backend/app/core/fields/README.md`.
