T-0007 policy: a row is visible when tenant_id = app.current_tenant_id AND (project_id IS NULL OR project_id = app.current_project_id). With no project bound only tenant-level rows (project_id NULL) are visible, so there is no tenant-wide cross-project read yet. Open points: (1) how portfolio/admin views read across projects (an explicit multi-project scope, a separate reporting role, or per-project fan-out); (2) tenant-level rows, including the project row itself, are visible to every session of the tenant, so a client-portal user bound to project A could list project B's row. T-0010/T-0014 must decide whether projects (and other tenant-level tables) get a stricter per-table policy.

- 2026-11-10: Decision (user, 2026-11-10): Explicit multi-project scope (session binds a list of allowed project ids) plus a stricter membership-based policy on the projects table and other tenant-level tables.  Implement in T-0010/T-0014.
