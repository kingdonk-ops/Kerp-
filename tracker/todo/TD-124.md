title: Fail fast at startup when production auth config (JWT key, KERP_REDIS_URL) is missing
kind: later
status: open
tasks: [T-0008]
source: implementer
raised: 2026-11-10
---

The auth runtime is built lazily on the first authenticated request (so /health and existing production-mode tests need no key or Redis). A production deployment without KERP_JWT_PRIVATE_KEY(_FILE) or KERP_REDIS_URL therefore starts, and the first login/bearer request answers 500 (AuthConfigError, logged). Add a startup check (lifespan or a readiness probe) once deployment config exists, e.g. with the T-0003/T-0004 infra work.
