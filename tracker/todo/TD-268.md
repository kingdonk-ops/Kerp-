Readings taken in T-0034 (ADR 0004 §5, §7, Amendment B) to confirm: (1) Tenant-layer permissions (PER-13 check, PER-01 other kinds; unlock request PER-13, approval PER-13/PER-01) use personas the caller holds on any project of the tenant, the same interim as project creation (TD-184), until T-0014 adds tenant-level roles. (2) Reset (one rule or the whole set) is allowed on locked rules because it can only make the rule equal to the current default of the parent layer; it is also how a project picks up a default unlocked at the tenant layer (project copies stay locked until reset). (3) A project cannot set locked on its own rules (409). (4) On the tenant layer a locked rule cannot be edited, disabled or deleted until a two-person unlock; re-locking needs one PER-13. (5) An approved unlock records the ADR reference on the rule (unlock_adr_reference); a rule changed after the request cannot be unlocked by it. (6) A reset-all soft-deletes rules the layer added itself.
