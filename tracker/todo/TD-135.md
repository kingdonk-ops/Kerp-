Diff §4 says only 'magic-link + 6-digit PIN as a local session unlock only, with progressive lockout throttling'. T-0009 implemented: a magic link (15 min, single use, sha256 digest in Redis) starts a new session on the device and sets its PIN (scrypt hash in Redis keyed by sid); /auth/refresh refuses PIN-gated sessions, only /auth/pin/unlock (refresh token + PIN) rotates them, so the worker re-enters the PIN whenever the 15-minute access token lapses. PIN alone can never start or refresh a session. Lockout: PIN 3 free, 30 s doubling to 15 min, 10th wrong PIN revokes the session; password login 5 free then same escalation, never permanent; magic-link requests 3 free per hour then 1 min doubling. Weak PINs (one digit repeated, straight runs) are refused. Confirm or change: (a) PIN on every token renewal vs only after idle/app-lock, (b) the numbers, (c) whether the PIN should instead be purely client-side (no server hash) with a server-side attempt counter only.
