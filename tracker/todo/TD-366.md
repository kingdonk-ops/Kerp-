T-0077 provides the policy and the one set-password API (`app.core.auth.service.set_user_password`, `set_password`, `create_user(password=...)`), used by the self-service reset. No endpoint exists yet for a signed-in user to change their password (current password + new one), and the admin API creates accounts without a password. When those are built they must call `set_user_password` (policy, NFKC, session revocation) and decide whether the caller's own session survives the change.

Added in PR #125 review round 1: `set_user_password` / `set_password` have only a DB session, no auth store, so they do not delete the account's reset pointer (`pwreset:user:<tid>:<uid>`). A reset link issued before a later change or admin set therefore stays usable until it expires (up to `KERP_PASSWORD_RESET_TTL_MINUTES`). Whoever builds the change-password endpoint and admin-set passwords must also kill the outstanding reset link (pass the store, or make the reset compare the link's issue time with `password_changed_at`, as magic links do).
