E-04-15 (Phase 4, user addendum 2026-11-21) asks for a revocable token-authenticated iCal feed of personal tasks and inspections. Calendar clients cannot send a JWT, so the feed authenticates by a URL token, which conflicts with CLAUDE.md §6 (tenant from the JWT only) like the public inspection links (TD-410). ADR 0013 (Proposed) names the feed as a second instance of the same pattern: tenant from KERP_DEFAULT_TENANT_ID, the token bound to one user (and its memberships at read time, so a removed member gets an empty feed or 404), stored hashed, revocable and rotated, rate-limited, no row-returning RLS bypass (the token resolves the user, then the normal membership-based session is built), event titles limited (planner default: code + type + date, no answers, no names of other people). Not blocking now: Phase 4 epic, still needs-breakdown; the planner applies the decision when breaking E-04-15 down. Options: (a) feed as described; (b) no feed (in-app calendar only); (c) feed without project data (times and opaque titles only).

- 2026-11-22: (planner, product intake 2026-11-21, item 14) Product intake asks for the same per-user ICS feed: revocable token, events limited to what the holder may see, and a plain warning in the UI that anyone holding the link can read it. Add the warning to option (a) if chosen. Not a duplicate TODO.
