Enterprise roadmap 2026-11-21, item 5 (metering step 1; spec diff §4.10). Planner defaults applied, not blocking:

1. **Shared bytes (TD-408 content addressing).** Objects are keyed `{tenant}/{project}/{module}/{sha256}` (TD-213), so one physical object belongs to one project; several file rows of that project can reference it. Rule: **physical bytes are counted once tenant-wide and once per project; logical bytes (sum over referencing file rows) are reported next to them.** If a physical object is ever referenced from several projects, project statements attribute it in full to every referencing project and mark it `shared`; the tenant total still counts it once. Derivatives (T-0247) are attributed with their original; archive packages (E-01-02) to the archived project, in their storage class (`DEEP_ARCHIVE` for cold archives, never Glacier IR); restore-as-new copies (T-0240) are new physical objects of the new project.
2. **Seats.** Tenant: users whose `last_active_at` (T-0243) falls in the day / trailing 30 days; per project: live members of the project who were active (approximation, no per-project activity tracking). Never from audit-log scans.
3. **Public capture submissions** are counted only if TD-410 accepts ADR 0013; until then the metric does not exist.
4. **Snapshot time:** after midnight in the deployment's default site timezone (diff §4.4, `Australia/Perth`); a re-run for a date overwrites that date idempotently.
5. **Cost centre:** a reference on a metering-owned table (`external_source` + `external_id` + `synced_at` when it comes from the ERP; free code otherwise), never a column on `oe_projects_project`; no currency amounts anywhere.
6. Soft limits only advise (in-app + e-mail with link and project code/name); they never block an action.
