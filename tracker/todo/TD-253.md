When KERP_WEB_ORIGIN is unset, /auth/refresh and /auth/pin/unlock compare Origin with the API's own scheme+host (backend/app/core/auth/router.py). Behind a TLS-terminating proxy that uvicorn does not trust (or that rewrites Host) the derived origin is wrong, every refresh returns 403, and sessions silently end when the access token expires. Options (PR #69 review): make check_startup_config fail fast in production when web_origin is unset, and normalise/validate web_origin to scheme://host[:port]. Also frontend/src/lib/api/client.ts treats a 403 from /auth/refresh as transient; it should clear the session as it does for 400/401/422. Fits T-0043 (Origin allow-list) or a follow-up task.
