Diff §4.5 says GET /api/v1/auth/sso/entra/start keeps the optional invite_token with the state (T-0054 took it as a query parameter), while diff §4.1 and T-0052 forbid the token in any server-visible URL path or query. T-0052 resolves it for the stricter rule: GET /start no longer takes invite_token (a query value is ignored); POST /start (top-level HTML form post, application/x-www-form-urlencoded: invite_token, device_id, app_challenge) carries it in the body, sets the same pre-auth cookie and answers 303 to Entra. Only the invite's reference (SHA-256) is kept with the state. Follow-ups: update the spec §4.5 wording; T-0053/T-0055 must start SSO with a form post when an invite is pending (not a link with a query); the web landing /login/sso-return now also receives joined_project_id or invite_error.
