The startup census function kerp_live_team_link_grant_count() (migration 0025) must count live team_link rows across all tenants while its definer (kerp_app in CI/dev, TD-056) is subject to FORCE RLS. It raises app.team_link_census transaction-locally for its own count and restores the caller's value; the read policy membership_team_link_census_policy honours that setting. Any SQL run as the runtime role that sets app.team_link_census itself could read live team_link rows of every tenant (same class as the lobby functions' is_system_admin elevation, migration 0021). The app never sets it. With split roles (TD-275) a BYPASSRLS/owner definer would make the policy unnecessary; revisit then (drop the policy and the setting).
