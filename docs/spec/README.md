## What the merge changed (summary — full detail in the consolidation diff)
- **Culled:** GL/accounting, HR/payroll, e-commerce/POS/CRM, `enterprise_workflows`, `module_builder`, 3D CAD/BIM viewers & `.dwg` parsers. Money is a read-only external mirror.
- **One-engine (TD-002):** one field-type registry (`core/fields`), one inspection record (`oe_inspections_inspection`, kind inspection/itp — TD-045), stateless `eligibility`, new `inspection_requests`. ITP = plan, Request for Inspection = trigger, ITR = evidence: see [modules/quality-and-inspection.md](modules/quality-and-inspection.md).
- **2026-11-21 issues decisions (user):** NCR and punch become two types of one template-driven **issues** engine ([modules/issues.md](modules/issues.md)): workflow fixed by type (punch raise → rectify → verify → close with Cat A/B/C; NCR containment → disposition → root cause → corrective/preventive actions → attested effectiveness verification `ncr_close_verify`), fields from layered, revisioned issue templates with pack/project-editable categories and a default template per category × type; `visibility` (`internal | client`) and `mdr_effect` (`blocks | register_only | excluded`) flags with audited QA/PER-09 overrides; clients never see internal issues; punch → NCR upgrade and "raise external NCR" create new linked records (no downgrade, void with reason); `create_issue` post-submit action raises issues from failed inspections and audits; the MDR gate and an NCR/concession register use `mdr_effect` ([modules/documents-and-mdr.md](modules/documents-and-mdr.md)). Flag overrides have guardrails (client/external-audit origins locked, never internal once client-seen, loosening notifies QA and counts in KPIs). One shared template designer for inspection and issue templates comes after Pilot-0 (epic E-01-03); the pilot uses starting issue templates we seed. The client-asset findings register stays separate.
- **2026-11-21 template menus, settings, anchors and links (user):** two menu items, one shared designer: **Templates** lists every inspection template (filters area, issue category, formal, audit, status, kind) and **Issues** holds the issue templates (Punch / NCR) ([modules/quality-and-inspection.md](modules/quality-and-inspection.md) §Template settings, diff §6.1). "New template" starts from a preset. Template settings: area (= category, plain labels, `health_safety` added), formal tick (informal = record-only, no review, outside MDR/progress/KPIs), audit tick with internal/external scope, linked issue types (0..many; one used, several picked, none → the template's `issue_category` × type default); changing area/formal/audit needs QA authority or PER-09 and makes a new revision. `qa_itp` inspections still anchor to an asset (ADR 0003); every other area is **project-level** with optional informational location and links (asset, material, equipment) that never roll up or block ([ADR 0003 amendment 2026-11-21](../decisions/0003-configurable-breakdown-and-terminology.md)); equipment is a link (ADR 0014 superseded, TD-411 resolved). Audit/H&S issues may be project-level; with `mdr_effect = blocks` they block every MDR of the project, or only the MDRs covering their location ([modules/issues.md](modules/issues.md) §3.1, §6; TD-443 resolved).
- **Product intake 2026-11-22 (3) (planner defaults unless marked; user to confirm):** AI change cards (field-level diff, rationale, confidence as a label only; Apply through the same service path, RBAC and `run_checks` as a manual save by the person applying; edit before apply; optimistic Undo; requester and approver audited) and a per-project Changes list with expiry (diff §4.11); one numbering service with token patterns, code lists and row-locked, never-reused counters, revision and status never part of the number ([modules/documents-and-mdr.md](modules/documents-and-mdr.md) §Numbering schemes, TD-588); competency at signing and paper-signed pages, since decided by the user (TD-592, mode iv) ([modules/quality-and-inspection.md](modules/quality-and-inspection.md) §Signing attestation, TD-591, TD-592); client-supplied material late for its work pack as a warning readiness conflict (quality §Schedule readiness conflicts, [modules/materials-and-traceability.md](modules/materials-and-traceability.md), TD-593); punch verifier ≠ rectifier also for a separate close ([modules/issues.md](modules/issues.md) §4.1). Raised: title-block number check later (TD-589), bolted joint breakout reset (TD-590), weather on the daily diary later with a decision (TD-594), notification rule model and delivery log carried over (TD-587); task T-0351 (CI SBOM, security self-assessment and retention table). **User decisions 2026-11-22:** TD-538 confirmed as is (per-client limits: 20 magic-link requests and 60 Entra SSO starts per hour; diff §4.2); TD-549 call-out and inspection-request notices are transactional and ignore opt-out, which applies to optional notifications only (quality §inspection_requests §9, diff §4.7); TD-592 a scanned paper signature may count as the client co-sign through §Client co-sign mode iv, confirmed by the client in their own account; TD-590 a joint breakout is recorded per joint; TD-594 a weather provider must use local Australian data and be free of charge; the 14-day change-card expiry is confirmed (diff §4.11). **Not adopted** (recorded so they are not re-proposed): benchmark cost indexation and regional normalisation (money is a read-only mirror; tender estimating is outside KERP's scope); gate-slot delivery booking (site logistics booking is not in scope); a generic "readiness provider hook" registry (gates already run on service facts through `run_checks`); a multi-provider LLM router or automatic local-model fallback (excluded by the TD-545 decision, diff §4.11).
- **2026-11-23 P6 XER format (planner defaults; user to confirm):** a real schedule re-profiled column by column → [modules/p6-xer-format-and-mapping.md](modules/p6-xer-format-and-mapping.md): file layout and encoding, stdlib streaming parser contract and limits, table catalogue (interpreted / ignored, never money), column mapping to the `oe_p6_*` mirror incl. float, driving path and late dates (TD-570), wall-clock dates in `site_timezone` and hours as stored truth, critical definition `from_schedule`, resources without cost (TD-611), measured name-grammar corpus with code lists and qualifiers (TD-612), calendar interpretation later (TD-613), synthetic fixture generator.
- **2026-11-22 product intake follow-up (planner defaults unless marked; user to confirm):** AI only through named server-side operations, no silent provider fallback, logical model tiers, company controls (module allow-list, conversation retention, daily budget cap), cited answers, per-answer feedback, in-record drawer (diff §4.11); earned value counts only verified completion ([modules/commercial-and-claims.md](modules/commercial-and-claims.md), TD-563); P6 schedule facts (float, critical path) for rule sets ([modules/p6-import-and-rsw-matching.md](modules/p6-import-and-rsw-matching.md) §5.6, TD-567); inline XER preview later (TD-566); label printing decision (TD-564); risk register later (TD-565). A daily site diary is already covered by the Daily Workface Log (edge §1.3, E-04-04), not by handover (handover.md §1). **User decisions 2026-11-22:** TD-545 defaults accepted (one AI provider per deployment, Australian region, company-owned key, fail closed); TD-561 defaults accepted (no second approver when PER-09 assigns a hold-authority persona it does not hold; external subcontractor crews may hold PER-14) (diff §4.1, §4.9, §4.11). **Not adopted** (recorded so they are not re-proposed): LLM "watcher" agents for gates (gates stay deterministic `run_checks` and scheduled jobs); a SQLite store in the browser (the web client uses IndexedDB through Dexie; the Android build's SQLCipher store, diff §6.2, is unchanged); per-project storage region (region is per deployment, diff §4.4); a free-form wiki (specs and procedures live in document control); geotags in photo EXIF (EXIF is stripped by design; a location, if needed, is an explicit field); building dictation now (OS keyboard dictation already works; server transcription would be a later option under the AI rules of diff §4.11); browser-side XER parsing as the import path (the server parses the stored original, p6 §1 principle 7, §3); baseline replace or cascade delete on import (never delete; change-impact preview, p6 §1 principles 4–5); ad-hoc unticking of WBS branches (scope lives in the mapping profile and eligibility rules, p6 §5); P6 WBS as ltree paths of the asset hierarchy (the ltree is the asset hierarchy, ADR 0003; WBS stays a schedule mirror).
- **2026-11-21 product intake (planner defaults unless marked; user to confirm):** MDR builder screen, Draft compile vs Issue, Rev A review → client acceptance → Rev 0, stamp → sign → hash the final bytes, deduplicated certificate appendices ([modules/documents-and-mdr.md](modules/documents-and-mdr.md) §Dossier builder); signer and credential snapshot, key fingerprints, signature retention vs erasure (§Signing attestation); RFI call-out delivery failure per party and per-party lines on detail and calendar (§inspection_requests §9, §11); template editor details (diff §4.7); AI data use and assurance record, project assistant (diff §4.11). **User decisions 2026-11-21:** no public/unauthenticated dossier verification page; client and site data may be sent to an AI provider (`source="ai"` + human confirmation still apply); no Teams/WhatsApp messaging bridge (diff §4.6).
- **2026-11-21 enterprise governance roadmap (user):** attested formal sign-offs and narrow delegation ([modules/quality-and-inspection.md](modules/quality-and-inspection.md) §Signing attestation, §Delegation of authority); SCIM provisioning, external parties, API keys and service accounts, network restrictions (diff §4.9, ADR 0017); usage metering (diff §4.10); feature flags (diff §4.7).
- **2026-11-14 decisions (login and lobby, product owner):** stateful lobby with an access-request lifecycle (`pending | approved | rejected | withdrawn`, rejection reason, "Request again" after a 24 h configurable cooldown, outcome shown in the lobby; e-mail once TD-084 exists); "Browse / join another project" in the picker; token-based invites (one-click join for existing users, membership right after first sign-in for new users, single-use, expiring, bound to the e-mail); internal staff flag (company Entra sign-in or configured e-mail domains) with the lobby list shown to internal users only; offline grace of 24 h (configurable) after the 12 h session ends on an offline device (diff §4.1, §4.2, §4.4); **Entra ID SSO, identity only** (OIDC + PKCE, no group-to-role mapping, same KERP session; diff §4.5). Later the same day: offline grace confirmed to bind edits with the 7-day offline window only as an upper bound (TD-257); invites in the Pilot-0 gate; internal staff should use SSO (promoted/default on the sign-in screen) but password sign-in stays allowed, no SSO-only enforcement (diff §4.5); sign-in magic links limited to Field Workers, PER-14 (diff §4.2; TD-136); external users never use SSO: invited by e-mail, they create their own password at invite acceptance and reset it by e-mail (local-password policy and reset, diff §4.1, §4.2; TD-262); outbound e-mail (SES) specified and a Pilot-0 dependency (diff §4.6; TD-084). Roles: PER-01–PER-16.
- **2026-11-13 decisions (teams):** tenant-level teams managed by System admins, team-project links with a role per project, effective access = individual memberships ∪ team-derived grants (diff §4.1 Teams, ADR 0008); saved views shared with several linked teams (register-views §3); manual notifications by PER-09 only (diff §4.1); grants stored by source (`direct` | `team_link`), effective = union (ADR 0008 accepted); team links carry PER-01–PER-14 except PER-09, plus new **PER-16 Project Viewer** (edge §5.2).
- **2026-11-13 decisions:** access model (one hidden tenant per deployment, System admins appoint Project Admins, lobby + access requests, project picker), 12-hour sessions, hybrid device PIN, devices, deployment settings and region (diff §4.1–§4.4); nav mapping, Android SQLCipher client storage contract, NFR budgets (diff §6.1–§6.3); Pilot-0 milestone (diff §7); localised template strings (edge §2.2); ADR 0004 Addendum F. Pilot-0 slice spec with planner defaults (Q5a): sync scope and download for offline (diff §6.4), review/return, answer comments, planning fields, photo annotation, video/audio/barcode fields and reference images, client co-sign on the inspector's device, inspection PDF and dashboard tiles (`modules/quality-and-inspection.md`; user decisions R1a–R5a recorded there), Item scan identifiers (`modules/asset-and-tagging.md`).
